## 1. 目标与边界

用户给短剧角色确定一个声音后，在不同镜头、不同画布以及同一短剧的后续创作中持续使用这个声音；每次生成都能核对实际使用的音色身份、音频样本、口音、声音指令及版本。修改角色声音时，历史结果保留，可选择哪些后续内容采用新版本。

本功能提供“可复用的声音身份 + 真实生成时的绑定 + 试听与逐条检查”。它不能仅靠保存资料保证模型输出永不漂移，也不把音色一致等同于口型同步。

用户已确定：
- 个人使用，本机 Electron，模型服务可配置。
- 模型连接和凭据属于应用配置；短剧素材和创作数据属于各自项目。
- 借鉴已查证的 LibTV 音色库/克隆入口，以及 BeefTV 角色绑定声音、样本、指令、角色版本的方式。
- 最初要求先出 spec；2026-10-30 已批准按本规格开发，工程实现已完成。

本文提出的默认设计：
- 复用 P4 数据和执行系统，增加明确的声音来源、角色默认绑定、路由能力和审核状态。
- 先做项目内角色复用；不新增独立的跨项目公共音色商城。
- MiniMax 是首个声音列表与克隆适配对象；已有 OpenAI 兼容 TTS 保留。具体账号是否开放这些接口，不能由模型名称、Token Plan 或文本接口成功推定。
- 原生参考视频与固定音色 TTS 并存；每个任务明确选路线，不自动回退。
- 供应商声纹相似度不是本期自动验收标准；真实听感由人工判断。

### 1.1 本期范围

1. 项目声音列表和角色声音编辑入口。
2. 从支持的服务获取音色列表；列表不可用时手动绑定 voice ID。
3. 导入、试听、裁切、派生声音样本；区分视频参考片段与克隆样本。
4. MiniMax 克隆完整流程：准备、上传、克隆、短句验证、保存音色绑定、恢复未决任务。
5. 角色声音版本与默认绑定，镜头逐句固定引用。
6. 统一解析声音输入，接通原生参考视频、独立 TTS、画布和 Agent 提案入口。
7. 三种情绪试听、人工音色/口音/台词检查、批次一致性检查。
8. 保留音频来源与版本；按句本地合成整段配音，接入已有配音确认、时间线和导出链路。
9. P4 旧数据迁移、离线查看、项目备份与迁移兼容。

### 1.2 本期不做

- 新增对口型模型或重写已有 Sync/手工修正流程；仅传递其需要的确认音频。
- 声音转换、歌声转换、音乐生成、人声分离、自动说话人分离、声纹训练。
- 语音克隆任意服务通用化；没有对应适配器的服务不宣称支持克隆。
- 自动保证任意方言、每句发音及跨模型声线完全一致。
- 多集项目管理、无限画布结构改造、跨项目自动共享声音、Linux 和远程引擎。
- 在本次写 spec 时使用真实凭据、上传音频、调用计费 API。

## 4. 方案选择

| 方案 | 优点 | 代价/不足 | 结论 |
| --- | --- | --- | --- |
| 仅保存音频样本，每次给视频模型参考 | 改动较少，复用 H3 路线 | 不支持纯服务音色，难确认 TTS 用了什么，质量全依赖视频模型 | 不满足完整需求 |
| 角色声音档案统一管理两类身份：参考音频与供应商 voice ID | 复用 P4，同时支持原生视频、TTS、克隆、历史追溯 | 需要统一解析和迁移，按服务做能力适配 | 本文采用的建议方案 |
| 全量强制先配音再对口型 | 可以先确认最终声音和台词 | 增加生成步骤、成本、口型服务依赖，环境镜头也被迫走此流程 | 保留为已有可选路线，不作为全局强制 |

用户已选择参照两款产品建立自己的功能；上表中的细化是设计建议，不冒充用户逐项确认。

## 5. 用户操作与界面行为

### 5.1 角色 → 声音档案

沿用“角色场景 → 编辑角色 → 声音档案”。展示：
- 当前默认声音、版本、来源；允许切换已保存声音或新建。
- 本地样本、原生视频参考、TTS 可用、人工试听的独立状态。
- 角色声音用途提示：音色身份、口音、表演说明与单句情绪各自独立。
- 已关联镜头/对白数量，查看使用情况与历史版本。

新建提供两个入口：
1. **选择已有音色**：选已配置的语音服务和模型，拉取音色列表或填写 voice ID；生成短句后试听，确认绑定。
2. **上传声音样本**：从本机导入或选项目音频；本地试听、保存；可准备视频参考，或选支持的服务执行克隆。

已有音色不要求用户先上传音频。上传样本可以先保存为“仅参考音频”，不因没配置 TTS 而不能建档。要将已有服务音色用于原生参考视频，应明确将试听输出保存为新版本的参考样本，不能隐式互转。

基础字段：名称、语言、地域/方言描述、声线说明、角色常态表演说明。单句情绪、台词、时长放在对白，不覆盖角色常态设定。

### 5.2 声音列表

项目资产页增加“声音”筛选/子页，复用资产布局：
- 项目内声音可按名称、角色、来源、可用状态筛选。
- 每项可试听基准音频，打开角色绑定、版本历史和使用位置。
- 远端音色列表是当前连接的候选目录，用户绑定后才生成项目声音记录。
- 远端目录刷新失败保留缓存，标明更新时间；列表出现一个 ID 不代表已验证可合成。
- 不在列表刷新时自动克隆、调用 TTS 或修改项目绑定。
- 本地归档声音后不出现在新建默认列表；已有引用和媒体仍能查看。

### 5.3 克隆流程

1. 选择原始样本与服务。界面显示该服务的样本要求及实际检测结果。
2. 准备上传计划：明确样本/范围、目标连接、生成的候选 voice ID、验证文本与模型、会发生的远端步骤及费用信息。
3. 用户发起后上传并克隆，进度和中间结果持久化。
4. 用同一候选 ID 生成一段验证语音。按第 10 节记录步骤，不能仅凭 HTTP 200 或目录中出现 ID 标成可用。
5. 用户试听，确认音色、口音和台词。可保存为未通过草稿，也可在通过后设为角色默认声音。
6. 三情绪资格试听与这次单句验证是不同证据。单句验证不代表后续批量制作已通过。

克隆不必重新生成角色图片。点击保存草稿、绑定本地样本、切换页面均不调用模型。

### 5.4 镜头对白

选择角色后默认填入其当前默认声音的明确版本，用户可以改选该角色的其他声音版本。

- 草稿显示“将使用：角色 / 声音 vN / 路线 / 服务与模型”。
- 保存对白时固定 voiceRef；以后默认声音改变，不自动改写已保存对白。
- 同镜头多角色逐句绑定；禁止只用音频排序猜测说话人。
- 批量更换声音先列出受影响对白，用户选范围后创建新修订。
- 修改台词/声音/路线后，旧产物保留但不作为这份新对白的当前结果。
- 路线为固定配音时，先产出与确认音频；是否接后期口型由已有对白路线决定。

### 5.5 画布

本期不新增另一套角色档案，也不把每个业务对象都改造成专用节点。

- 继续使用通用 media 卡表示声音素材，附带显式 voiceRef 和 characterId 时显示为“角色声音引用”。
- 视频生成卡支持选择角色声音；绑定到分镜的生成卡从保存的对白获取声音，不能与对白各用一套身份。
- 增加语义明确的 voice_reference 输入。边保存角色映射，文字标签仅用于展示，不作为提示词。
- 未绑定角色的普通音频不能冒充角色声音，界面提示先选择角色/档案。
- 同一生成任务，同一角色最多选择一个声音版本；多个角色按稳定顺序编译为模型实际音频索引。
- 已绑定对白的生成卡若连入冲突声音，阻止准备并提供“去对白修改”；不得静默覆盖。
- 自由生成卡：显式连接优先于尚未保存的默认建议，但提交前必须显示最终选择；不隐式加入未展示的声音。
- 本期只接受已保存档案的声音参考；不扩展成任意音频生成节点互相驱动的完整工作流。
- 音频只保存在档案而未接到任务，必须显示“未用于本次生成”。

### 5.6 Agent

Agent 可以查询、提出绑定/试听/生成计划，复用同一套命令与解析器。
- 不能凭角色描述发明 voice ID。
- 不能将保存档案写成“已克隆”或将请求成功写成“声音一致性通过”。
- 提案展示实际角色、声音版本、样本、模型和缺失项。
- 执行服从现有生成确认流程，不另起后台请求。
- 任何入口都不能绕过版本、能力和结果审核。

## 6. 领域模型与持久化

以下为逻辑字段；实际命名可按现有 contracts 风格调整。复用现有 id/revision，不另造第二套同义声音档案。

### 6.1 CharacterVoiceRevision 增量

| 字段 | 含义与规则 |
| --- | --- |
| id / revision / projectId / libraryId | 沿用现有身份与版本 |
| entityRef | 创建时关联角色快照；稳定关联由 entityRef.id 识别，角色外观当前快照在生成时另行固定 |
| name / language / dialect / timbreDescription / performanceNotes | 名称与声音描述；不充当实际声音身份 |
| sourceKind | sample / provider-voice / cloned-voice；描述主要来源 |
| sourceSample | 可空，导入原件的固定 MediaReference、hash、probe、选区；不被标准化文件覆盖 |
| videoReference | 可空，为某适配器准备的派生音频，含 hash、probe、选区、处理版本与原件来源 |
| ttsBinding | 可空，固定 providerVoiceId、connectionRef、modelRef、profileRef、voiceOrigin、克隆回执引用；现有 ttsProfileRef 迁入 |
| baselineAudio | 可空，用户确认用于对比的基准音频；记录来自原件或哪次 TTS take |
| archived | 不再作为新任务默认候选；历史只读仍可访问 |

约束：
- sourceSample、videoReference 或 ttsBinding 至少存在一种可解释来源；仅一段描述不足以构成可生成的声音身份。
- 同一个声音档案可同时有参考音频和 TTS 绑定，但是否“听起来是同一人”必须经过跨路线试听；不能从档案 ID 相同推定。
- providerVoiceId 与本地声音 id 分开；前者仅在对应服务/账户作用域有效。
- 相同字符串 ID 在两个连接下不是同一声音。
- 预设提供模型和参数；角色 ttsBinding 决定实际音色。准备时复制预设到请求快照并显式应用绑定的音色，不修改公共预设。
- 旧预设 voice 与迁移后的绑定相同；新绑定若与公共预设 voice 不同，显示最终生效值。禁止保留两套互相冲突的权威。
- 生成参数中原有 voice 校验应按适配器调整；不能截断、去空格或规范化供应商 ID。

### 6.2 默认角色绑定

增加版本化的 CharacterVoiceBinding：
- projectId、characterId、voiceRef、revision、updatedAt。
- 一个角色同一时刻最多一个默认声音；可有多个历史/候选声音。
- 绑定只用于新草稿默认值，不改变既有对白。
- 仅改角色名称、简介或图片时保留默认声音；生成依旧固定当时的角色外观快照。
- 保存绑定采用 expectedRevision，冲突不覆盖他人/其他窗口的新选择。
- 声音换版不自动推进默认绑定；用户通过“保存并设为默认”明确操作。

### 6.3 能力、资格与任务状态

不要用现有 production.ready 一个布尔值承担全部含义：

| 维度 | 示例状态 | 解释 |
| --- | --- | --- |
| materialState | missing / needs-preparation / ready / unavailable | 文件和派生音频是否可读、格式是否合格 |
| providerState | unverified / verified / unsupported / unavailable / unknown | 当前连接与身份能否实际使用 |
| reviewState | unreviewed / passed / needs-fix / stale | 对某个明确配置指纹的人工试听结果 |
| cloneState | prepared / uploading / uploaded / cloning / unknown / cloned-unverified / verifying / ready / failed | 克隆任务进度，不等于人工质量结果 |

providerState、reviewState 是针对“档案版本 + 路线 + 模型/连接/参数”的派生视图或独立记录，不能把远端状态变化直接写进不可变档案快照。

增加或扩展记录：
- VoiceProviderCatalogCache：按连接修订隔离，记录获取时间和来源；不是音色权威。
- VoiceCloneJob：固定输入、逐步状态、供应商文件 ID、请求的 voice ID、请求摘要、验证 take、错误与恢复信息。
- VoiceQualification：档案/路线/语音配置语义指纹、试听用例、输出引用及 hash、人工结论。
- ResolvedVoiceInputs：冻结后进入 PreparedGeneration 的声音快照。
- 保留 P4 AudioTake、DialogueTake、ConfirmedDialogueAudio、DialogueSelection，不用伪造视频 take 代表纯音频。

### 6.4 存储与项目目录

模型连接与凭据继续使用应用配置和已有凭据管理。项目中的声音仅保存连接引用及非敏感配置快照，不另放一份 API Key。

逻辑组织：
```text
<短剧项目>/
  assets/characters/          现有角色资料
  audio/voice/                用户可查看/导出的声音资料
    <character-id>/
      <voice-id>/
        v0001/
          voice.json         导出的档案与使用说明
          source.*           需要导出时的原始样本
          reference.wav      需要导出时的视频参考
          audition-*.*       需要导出时的试听结果
  .movieagent/library/       现有数据库与对象存储，运行时权威
```

上述 voice 子目录是可读导出结构，不引入文件和数据库双向同步。正常运行继续以现有库/对象存储为权威；导出文件不作为任务自动输入。实际新增导出文件只在用户执行声音导出时创建。

项目备份/转移必须遍历新增声音引用、原始样本、派生文件、试听结果；外部文件需纳入对象存储。恢复后本地素材与历史可用，远端声音标为需核验，不自动上传/重克隆。只保留应用连接引用，不复制凭据。

## 7. 统一声音解析与生成契约

新增共享解析服务，供对白、画布、TTS、试听和 Agent 使用；各入口不得复制一份各自的默认规则。

### 7.1 解析步骤

1. 从已保存的对白或显式画布绑定确定角色和声音版本；默认角色声音只用于未保存草稿。
2. 校验项目归属、角色关联、声音存在性、媒体 hash、引用可用性。
3. 根据任务路线选择 ttsBinding 或 videoReference。
4. 校验连接、模型和已验证能力；不支持则返回具体缺项。
5. 编译声音指令与身份映射；计算配置指纹与最终请求摘要。
6. 显示预览，按现有准备/确认/提交机制冻结请求。
7. 提交时重查当前任务输入和服务能力；字节变化、撤销或配置失效时阻止新提交。
8. 把实际音色 ID、样本 hash、模型修订、角色映射和最终参数写入任务及产物来源。

### 7.2 三种路线

| 路线 | 实际身份输入 | 本期交付粒度 | 后续关系 |
| --- | --- | --- | --- |
| native-reference | 每角色明确的参考音频 + 角色/音频映射 + 声音说明 | 一个生成视频及其音频来源记录 | 人工审听、采用，或转独立配音修正 |
| fixed-voice TTS | 同一服务/账户的固定 voice ID + 固定模型/参数 + 台词 | 每句/每段独立 AudioTake | 用于画外音或确认配音，再接既有口型流程 |
| imported performance | 用户已录好/制作好的音频 + 角色与对白映射 | 固定音频版本与人工审核记录 | 接既有确认配音/时间线，不伪称由 TTS 生成 |

fixed-voice TTS 是声音生产方式，不另增取代现有 DialogueRoute 的枚举。它可服务 voiceover 或 dubbed-lipsync；两者在后续是否处理嘴形上不同。

### 7.3 提示词与字段映射

原生视频编译至少包括：
- 角色稳定标识/名称；对应图片序号和音频序号。
- 语言、地域口音、声线、常态表演指令。
- 当前对白原文、说话角色、单句情绪及时间范围。
- 样本用于声音身份参考；本段说的是当前台词，不能把样本中的台词当作要求复述的内容。

字段映射按适配器实现。某个 TTS 接口没有指令/方言/情绪参数时：
- 保留档案字段，界面明确“该字段当前仅用于人工参考/此模型不接收”。
- 不把说明拼入需要朗读的正文。
- 不静默声称口音指令已生效；方言验收仍需要实际试听。
- 本期 MiniMax/OpenAI 现有基础 TTS 请求先复用已支持字段；新参数只有完成对应协议适配与验证才开放。
- 合成文本必须保持用户台词；不得为适配器省事而修改专名或删减字句。

### 7.4 冻结内容与优先级

冻结：projectId、characterId、voiceRef、对白/镜头修订、路线、providerVoiceId、连接/模型/预设修订、实际参数、样本原件与派生 hash、角色参考、编译模板版本、compiledInstructions、未映射字段列表、请求 hash。

优先级：
1. 已保存对白的 voiceRef 是该对白任务的权威。
2. 自由画布的显式绑定是该任务的权威。
3. 角色默认声音仅生成建议值，保存前必须可见。
4. 公共预设的 voice 不能覆盖角色声音绑定。
5. 外观、文字描述、边标签不能自动更换声音。

## 8. 版本、失效与历史结果

“产生新版本”和“撤销旧版本”必须分开。

| 变化 | 新生成/未提交计划 | 已完成结果 |
| --- | --- | --- |
| 修改声音样本、voice ID、口音、表演指令或音色参数 | 新声音/配置指纹，需对应重新试听；受影响未提交计划重新准备 | 保存旧版本与审核，标注使用旧版本 |
| 更换角色默认声音 | 新草稿使用新默认；已有对白不自动改 | 不变 |
| 只改角色名称/简介 | 保留默认声音；生成使用新角色快照 | 不撤销纯音频试听 |
| 换角色图片 | 原生视频试镜重新验证外观与声音映射；纯 TTS 音色资格可复用 | 历史媒体保留 |
| 更改台词或情绪 | 重新生成/审核该句；身份资格可复用，除非越出已验证能力 | 旧句留历史 |
| 删除/失效的远端音色、损坏样本 | 阻止依赖它的新请求；不能自动切回默认音色 | 本地已完成音频仍可播放/导出 |
| 用户明确标记声音不可再用 | 阻止新任务使用该版本；说明原因 | 保留历史记录，不自动擦除已完成作品 |

相对 P4 当前“必须是最新声音/角色版本”的检查，此处有明确调整：
- 已固定的旧声音版本仍可供新任务显式选择，只要没有归档限制/撤销、媒体完整、当前连接能力有效；不自动读最新版本替换。
- 新请求使用旧绑定的旧连接修订而连接已更新时，要求重新核验/保存新的可用绑定，不将旧密钥快照用于请求。
- 旧 take、已采用的时间线片段和已通过的审核按其当时快照保留。新声音出现本身不禁止历史剪辑继续播放和导出。
- 将旧产物采用为一份已经改过台词/声音的新对白结果，需要重新核对，不能沿用旧“当前结果”标记。
- 文件完整性失败仍是硬错误，不因“历史结果”而忽略。

资格指纹分层：声音资格不包含无关角色图片；原生视频的角色映射资格包含图片、全部声音版本、模型和映射。多角色组合不能只凭第一个角色的声音通过来放行。

## 9. 模型能力与首批适配

能力由具体连接 + 适配器 + 模型声明并核验，至少区分：
- fixedVoiceTTS
- voiceCatalog
- voiceClone
- referenceVoiceVideo
- performanceInstructions（允许的字段/方式）
- providerVoiceLookup / replayOrReconcile（如服务有明确契约）

| 首批类型 | 本期要求 | 不允许的假设 |
| --- | --- | --- |
| MiniMax Speech | 固定 ID TTS、获取声音目录、样本上传和克隆、验证结果入库 | 文本兼容接口通了就一定支持语音/克隆 |
| OpenAI 兼容 Speech | 沿用已接通的固定 voice TTS；可填写实际 ID；有依据的内置列表注明来源 | /models 就是声音目录；OpenAI 兼容意味着可克隆 |
| 现有 minimax-h3-v2 | 复用已实现参考音频请求，加完整角色映射和指令 | MovieAgent 当前限制等于所有 H3 服务限制 |
| 其他自定义网关 | 选择已适配协议，用其 Base URL/凭据；不具备接口时清楚显示不可用 | 自动转发至另一家官方服务或换用别的 Key |

用户继续在模型设置配置服务；声音页面不要求理解底层 API 协议，能力不足时提示缺少哪种服务功能。

### 9.1 MiniMax 克隆适配边界

以官方文档核对日期 2026-10-30 为初始契约：
- 上传使用 files/upload，purpose=voice_clone；克隆操作使用 voice_clone；语音目录使用 get_voice。请求目标由选定连接确定，不硬编码绕过用户 Base URL。
- 克隆源样本支持 MP3/M4A/WAV，10 秒至 5 分钟、不超过 20 MB；与现有 H3 视频参考的 2–15 秒派生分开。详见 [上传文档](https://platform.minimax.io/docs/api-reference/voice-cloning-uploadcloneaudio)。
- voice ID 按克隆接口的规则生成和验证，保存原请求 ID；不能假设响应一定另返一个新 ID。未在 7 天内使用的克隆声音可能被服务删除；记录时间与可用性，不启动自动收费保活。详见 [克隆文档](https://platform.minimax.io/docs/api-reference/voice-cloning-clone)。
- 新克隆声音可能在成功用于合成后才进入目录；列表没看到不等于克隆失败。验证使用原候选 ID，不能再创建一次。详见 [声音查询文档](https://platform.minimax.io/docs/api-reference/voice-management-get)。
- file_id 等远端 int64 必须无损处理，禁止经不安全的 JavaScript Number 四舍五入后提交。
- 首版不暴露可选 clone_prompt 高级增强；用户已有的短参考样本不自动冒充其专用提示音频。
- 文档契约不等于用户网关契约；不兼容时返回诊断，保留输入与任务，不暗中改 URL。

### 9.2 样本处理

保持导入原件；对不同用途单独产生派生文件：
- 视频声音参考：继承现有 H3 适配器的格式与时长约束。
- 克隆样本：按克隆服务要求检测/派生，不能将所有原件统一裁成 15 秒。
- 试听基准：可使用导入样本或确认后的合成输出。
- 不自动做强降噪、改变音高/语速等会改变声音身份的处理；新增处理需要可见参数和可追溯派生记录。
- 无音轨、解码失败、选区越界直接阻止；静音/多人物/背景音乐等无法可靠自动判断的问题展示提示，交由试听确认，不伪造机器判断。

## 10. 执行、恢复与费用

复用现有 prepare/approve/submit 与任务/回执设计。克隆是多步骤远端操作，需要独立持久化每一步，不伪装成普通 TTS 一步请求。

- 计划固定上传样本、连接、候选 ID、验证台词、模型和费用说明。一次用户操作可以覆盖明确展示的上传、克隆、一次短句验证。
- 同一计划重复点击不能重复提交；已完成步骤复用原回执。
- 明确拒绝与网络中断区分。上传或克隆请求发出后结果不明，进入 unknown。
- unknown 不自动重发，不自动换 voice ID。先查询原操作；服务没有可靠查询时保留“需核对”，用户在服务控制台确认后再选择恢复或新操作。
- “服务显示 ID 存在”只能帮助找回身份，不能确认其与本次样本相同；未知来源仍需验证和明确处理。
- 原操作在声音草稿变更后返回，结果只记入原版本/历史，不覆盖当前默认。
- 克隆成功但验证失败，保留 candidate ID 和状态，重试仅执行已明确失败且安全的步骤。
- 缓存目录和听本地音频无需模型费用。云端短句验证、三情绪试听、克隆和生成显示服务和预计用量；未知金额显示未知，不填 0。
- 停止本地等待不保证远端取消，重开后显示原任务。
- 不添加为了测试声音而自动执行的大批量视频请求。

## 11. 试听、采用与一致性验收

三个层级单独展示：
1. **技术连通**：服务返回可解码音频，绑定 ID/样本确实进入请求。
2. **声音资格**：用户听过该角色在选定路线/模型下的代表性输出。
3. **成片采用**：当前具体台词/音频/镜头通过审核并被采用。

资格试听：
- 平静、激动、低声三类短句，复用现有情绪分类。
- 使用同一声音身份、同一配置；与基准音频并排播放。
- 检查音色、口音、台词；纯音频口型项为不适用，不强迫制作视频。
- 不支持情绪指令时明确提示；允许用户评价实际表达，不把界面选择当作已实现情绪。
- 新角色组合的原生视频另做串声/说话人映射检查；各角色都需具备资格。
- 无基准样本的系统音色，用首次用户确认的输出作基准；以后对比仍可追溯。
- 用户可以生成单条待审样本而不具备批量资格；正式批量制作默认要求对应资格通过。
- 延续 P4 的有原因例外入口时，仅针对该批次记录风险，不把档案全局标成通过。
- 人工拒绝记录具体原因；重生成、换模型、修改指令都产生新结果，不覆盖旧文件。

固定音色只保证请求使用了同一身份；输出仍可能漂移。方言是否自然，由能判断该口音的人检查。ASR 不是本功能前置条件，识别到正确文字也不是音色或口音通过的证据。

## 12. 交付资产与时间线接口

最小可交付对象：
- 角色声音档案某一版本及角色绑定。
- 原始样本、按用途准备的参考、供应商音色身份（如适用）。
- 已试听的代表性结果与审核。
- 每句/段最终音频：文件、台词、说话人、voiceRef、源任务、实际配置、时长、hash、审核与确认状态。
- 原生视频结果：对应视频、实际声音参考映射和人工审核。

“上传了一份样本”不是完整资产交付；至少要明确它目前能走哪条路线、是否进入真实请求、是否经过试听。

对固定配音：
- 复用 ConfirmedDialogueAudio 固定最终音频。
- 配音 AudioTake 与原生视频中的音轨不能同时作为同一句台词播放。
- 使用后期口型时，口型任务引用这个已确认音频；换音频需重新处理相关嘴形。
- 时间线采用时保存声音版本和音频 hash；重开/导出与预览采用同一份声音。
- 声音档案更新不自动替换历史时间线的音频。
- 原生视频如保留环境音，仍按现有音轨策略处理；本期不自动分离其人声来实现无损替换。

### 12.1 逐句配音合成整段对白（本期包含）

这是独立设计审阅后补齐的默认方案：复用本机媒体作业，把已选定的逐句音频按 DialogueTurn 的时间位置合成一份完整对白音频；不要求用户另开剪辑软件手工拼接，不新增云端调用。

增加 DialogueAudioAssembly 的版本化清单：
- projectId、shotRef、dialogueRef、assemblyId/revision、目标时长与 48000 ticks/秒时间基准。
- 每个 turnId 对应 characterRef、voiceRef、AudioTake 或 imported-audio 来源、原件 hash/probe、人工审核引用、startTicks、分配时长和实际解码时长。
- 合成规则版本、冻结清单 hash、localMediaJobId、输出引用/hash/probe。
- 清单必须恰好覆盖当前对白的全部 turn；同一个 turn 只能有一个被选结果。禁止拿第一句音频当整段已完成。

合成规则：
1. 每句放到其 startTicks；不足该句分配时长的尾部补静音，句间和镜头剩余时间同样补静音。
2. 单句解码后超过分配时长就阻止合成，提示重新录制/生成或调整对白时间；不能自动截断、删字或变速。仅处理音频容器的正常解码/重采样，不把任意时长误差当作可忽略。
3. 首版自动合成只接受互不重叠的 turn 区间；有抢话/叠说则提示调整时间或导入已制作好的整段音频。这个限制只针对新增自动合成，旧项目和已导入音频仍可读、可播放。
4. 输出为完整镜头时长的 48kHz PCM WAV；通过探测确认每个输入/输出的可解码性与确切时长，使用现有对象存储和本地渲染任务。
5. 任一句缺失、未确认、声音映射不符或来源变化，不能把合成结果标为当前可采用。用户可试听未确认草稿，但它不能冒充确认音频。

衔接已有契约：
- ConfirmedDialogueAudio 增加 source.kind=audio-assembly，并记录 assemblyRef/manifestHash；继续提供下游需要的单个 ref/hash/probeId。
- 新的单句 audio-take 直接确认路径仅限当前对白确实只有一个 turn，且来源绑定和人工审核匹配。多句必须使用完整 assembly 或明确的整段 imported-audio。
- imported-audio 保留人工确认路径：要求用户确认其覆盖整段对白的所有角色/台词，保存该确认；没有逐句源文件时标为“整段导入，逐句生成来源不可追溯”，不伪造 AudioTake 清单。
- 当前对白、句子选择或任一源音频改变，都使未提交的 assembly 计划和“当前确认”失效；旧 assembly 与历史时间线按第 8 节保留。
- assembly 已包含对白起点与补静音。进入现有视频对齐时 startTicks=0，禁止再把各句起点重复加一次。配套视频时长不匹配时要求修订计划，不默默截断。
- 这是完整配音交付，不代表自动解决多人物同屏口型。既有口型服务若不能明确选择目标人物，应阻止该段自动修正并提示分镜拆分/手工修正；整段音频仍可用于画外音、时间线或外部修正。

## 13. 兼容与迁移

1. 迁移前记录库版本与可恢复备份；迁移事务失败不得留下半个绑定。
2. 保留现有 character_voice_revision 的 id/revision 和所有对白引用。
3. 旧 reference 迁为来源/派生关系可解释的样本；若缺少原始长音频，不伪造源样本，只保留现有固定媒体。
4. 旧 ttsProfileRef 能解析到完整固定配置时，将实际 voice 参数和连接/model/profile 记录为绑定；缺字段或失效则标“需配置”，不代填默认音色。
5. 迁移不自动发 TTS/克隆请求，不补造 provider verified 或人工 passed。
6. 旧 production.ready 映射为相应视频参考技术状态，不映射成声音质量通过。
7. 一个角色只有一个声音候选时可迁入默认绑定；多个候选显示待选择，不能按数组顺序任取。旧对白仍指向原版本。
8. 历史试听只有在输入指纹可完整对齐新规则时复用；否则保留历史证据并标需要新验证。
9. 更新所有读取点：对白、配音、批次、画布、Agent、快照导出、备份、项目转移、恢复、时间线采用与渲染。
10. 旧计划可回放/查询，但不拿旧格式重新提交未冻结的新身份；未提交计划要求重新准备。
11. 归档不物理删除有引用的样本或音色记录；远端删除音色暂不提供，避免本地归档影响其他作品。

### 15.2 真实服务质量验收（另行执行）

不能用本地 fixture 代替：
- 一位角色，同一服务/模型/声音身份，三条不同内容和情绪的短句；试听并确认声线可接受。
- 更换镜头或项目内画布位置后保持相同身份与来源；实际输出不能串声。
- 两位角色至少一段轮流对白，逐个核对声音和台词。
- 方言样本在至少两句不同台词中检查口音自然度；能识别该口音的人给结论。
- 如验收克隆：原样本与克隆结果做 A/B 试听；保存实际 voice ID 和任务记录。
- 如同时使用原生参考与 TTS：必须额外对比两条路线，不能共享一次试听就宣称跨路线一致。

先执行用户允许的最小测试数量，再按结果扩展；未执行项持续标“真实服务未验”。记录服务/模型/版本/输入输出 hash、实际请求次数、估价与实际费用（未知则明确未知）、审核人/时间/原因。

完成定义：工程 AC 满足、迁移和交付链验证通过，并且已完成的真实质量项目有证据。若仅工程完成，交付说明必须明确“工程完成，真实声音质量未验”。
