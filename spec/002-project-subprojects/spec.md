# SPEC-002：项目、子项目与连续创作

- 规格状态：Approved。用户于 2026-10-31 明确“那开始执行吧”，批准按最新设计实施。
- 实现状态：工程实现、本机回归和包体验证完成；真实视频、Kimi长请求、自动摘要与第二集Agent接续部分通过。旧未知任务并发堵点已修复并在并发1下真实验证，见 [恢复验收](unknown-slot-verification.md)；历史栏目等语义仍未验，详见 [真实补验](real-text-acceptance.md)。结果见 [实施与验收记录](implementation.md)。
- 创建/更新日期：2026-10-31。
- 适用范围：个人使用的 Windows Electron 桌面端与内置本机引擎。
- 用户原始需求：一个项目下管理多集、多期与多份制品；子项目代表一集或一期，共享项目资源、资产和记忆，使短剧和专题栏目连续创作。

## 1. 目标、边界与决定

### 1.1 目标

一个项目代表长期创作的整体，例如一部短剧《大明朱清》或一个栏目《明朝军事史》。子项目代表可独立制作和交付的一集、一期或一条视频。用户无需为每集重新建立完全独立的项目、复制角色或重新交代全部背景。

连续性包含共享可引用资产、共享有来源的设定与知识、保留前期已经采用的创作进展。共享文件夹本身不能证明 Agent 已理解并使用这些内容。

### 1.2 用户已明确的决定

- 引入“项目 → 子项目”：多集短剧或同主题多期节目归入同一个项目。
- 子项目有独立制作内容和制品，共享项目资源、资产和记忆。
- **每个子项目完成后自动写入共享记忆，不要求用户逐条确认后才生效。**
- 保持应用级模型配置、项目级工作目录、Windows 本机 Electron 的既定产品边界。

### 1.3 本稿的设计默认

- 第一版固定两层，不递归建立子项目的子项目；场景、制作分组和画布承担更细粒度组织。
- 一项目使用一个工作目录、一个资料库和一套本机引擎连接；子项目在其中登记。
- 子项目可有多个剧本、多张画布、多条时间线和多个制品；可指定一条主时间线。
- 同一父项目统一登记资产，所有子项目都可检索、预览并选用其中可用的固定版本。来源子项目是分类和追溯信息，不构成同项目内的读取门槛。
- 共享资产采用固定版本引用；新版本可供后续制作选择，不静默替换已经采用的版本。
- 子项目可显示“第 N 集”“第 N 期”或自定义标题，底层使用同一种业务实体。

### 1.4 非目标与容量边界

本需求不加入 Linux、远程引擎、多人协作、自动发布、无限嵌套或跨项目实时共享。不同项目的工作目录边界保持明确。

本需求不自动扩大现有的单时间线 64 个视频/图片片段、600 秒，以及单次制作批次 16 个镜头的限制。它们是单独的容量约束；不能把“支持多集”表述成“已支持任意密度的长片剪辑”。这些限制不再额外施加于整个项目的累计内容。

## 3. 方案与取舍

采用用户提出的项目内子项目模型：项目负责长期共享内容，子项目负责独立制作和交付。它能沿用现有多时间线、版本化资产和本机资料库。

| 方式 | 取舍 | 本稿处理 |
| --- | --- | --- |
| 每集建立独立项目，额外复制资产 | 旧边界容易保留，但共享记忆、角色更新与整体备份分散 | 与用户目标冲突，不采用 |
| 同项目只给剧本和时间线打分集标签 | 适合分类，难以约束画布、任务、会话、制品和恢复 | 标签辅助展示，不承担子项目身份 |
| 建立有身份与归属的子项目 | 涉及持久化、上下文、界面和迁移；可维持共享与独立交付 | 采用；固定两层为本稿默认 |

复制子项目只创建新的制作身份，复用明确的固定资产引用；不复制正在运行的供应商任务，也不把复制品标为已经交付。复制内容及复制 UI 的范围在实施计划中明确；第一版至少支持空白创建。

## 4. 用户流程与状态

### 4.1 进入与创建

1. 启动器继续打开项目目录，例如《明朝军事史》；项目首页展示各子项目、进度和制品。
2. 新建子项目时填写标题，可选集/期编号、目标说明。创建独立身份、目录和一张空画布。
3. 主时间线在有可绑定剧本后创建；没有剧本或素材时保持空态，不注入演示内容。
4. 子项目内的画布、剧本/分镜、Agent、任务、时间线和制品默认只显示本地内容；项目共享资源始终可达。
5. 当前项目、子项目、画布有明确标题；项目总览的聚合记录显示归属。

### 4.2 多画布、多时间线、多份制品

- 多张画布可服务同一子项目，每张画布可组织多段生成视频。
- 子项目可以有“主剪辑”“竖屏版”“预告版”等独立时间线，每条时间线保留自己的修订历史。
- 主时间线指针只负责默认打开哪条剪辑；不自动改变已交付制品。
- 制品登记固定时间线修订、渲染/导出回执、输出规格和媒体版本/hash。失败导出不显示为已交付。
- 一集可以有正式版、修改版及不同画幅的多份制品；项目首页可汇总查看和过滤。
- 对话、配音、字幕与角色声音继续使用原有版本、审核及固定引用规则。

### 4.3 统一资产库与跨子项目复用

- 父项目统一登记角色、声音、场景、道具、视觉风格、配乐、片头片尾、资料文献，以及各子项目已导入或生成收存的图片、视频和音频。
- 资产面板提供“当前子项目”“项目共享资产”“全部子项目成果”三个视图。当前子项目默认只看本集来源；切到全部成果后，可以直接选用兄弟子项目的可用资产，无须先执行“加入共享”。
- “加入项目共享资产”将常用内容加入项目公共分类，便于后续集找到；这是整理操作，不是解锁其他子项目访问的步骤，也不改变资产身份、来源或历史引用。
- 媒体原件在同项目对象存储中去重保存；子项目采用时登记固定资产版本及使用关系，不复制大文件，也不依赖兄弟目录的临时绝对路径。
- 编辑本集服装或提示词时，明确选择本集变体或项目共享定义的新版本；不能改掉其他集已经使用的固定版本。
- 第一集生成的视频可以直接从第二集的“全部子项目成果”中选入画布或时间线，用于回顾或混剪，保留来源子项目和固定版本。选用素材不自动修改第一集的剧本、节点、任务或剪辑。
- 素材需要处于可用状态；失败任务和未收存原件不能当作可用资产。手动放入目录的文件需要导入登记；位于同一父目录并不自动成为业务资产。
- 资产在同项目可检索不等于 Agent 自动读取全部内容。仍由本轮任务的选择与预算决定实际上下文，保存采用来源；未来集素材也不会因为可浏览就自动进入早期集的记忆。

### 4.4 切换、后台任务与生命周期

- 子项目默认状态为准备中、制作中、已完成、已归档；用户明确标记完成，生成一段视频不会自动把整集标为完成。
- 未保存剧本、配音或时间线草稿沿用保存/放弃/取消导航机制。
- 切换子项目不停止已经提交的任务；结果回到原来的子项目、画布、节点和修订。
- 查询缓存键、事件订阅、界面草稿与任务通知都包含作用域；迟到响应不覆盖当前子项目。
- 项目任务中心可看全部任务，本集入口默认只看本集，并支持跳回来源。
- 归档可恢复，不删除被引用资源或历史；有运行任务/未保存内容时处理对应状态后再归档。

## 5. 自动共享记忆与连续性

### 5.1 记忆分层与优先级

| 层级 | 内容 | 使用 |
| --- | --- | --- |
| 项目显式设定 | 用户维护的世界/人物设定、栏目定位、视觉规范和资料约定 | 项目内共享，优先于模型自动总结的推断 |
| 子项目工作记忆 | 本集目标、讨论、草稿、试验和局部决定 | 默认服务本子项目 |
| 自动完成摘要 | 本集采用的剧情/人物状态/伏笔，或本期讲过的主题、术语、资料与结论 | 完成后自动写入项目共享记忆，后续可检索和采用 |

自动总结保留来源与事实性质。模型归纳的历史说法不会因此变成“已核实事实”；未核实、来源缺失和冲突必须可见。

### 5.2 完成触发的自动更新

1. 用户将子项目标为完成时，固定一次 completionRevision 和 sourceSnapshotHash，记录该次采用的剧本/分镜、主剪辑/交付选择、笔记及资料引用。
2. 使用这份固定快照自动整理记忆并写入项目，不要求额外逐条审批。默认不采用失败生成、已弃用方案和普通闲聊。
3. 本集有多个剪辑或制品时，完成操作保存“本次完成采用”的明确版本；不能简单把最近生成的预告片当成完整剧情。
4. 自动整理使用项目记忆设置所选的应用文本模型配置引用，首次可预选当前文本配置；任务固定配置版本，不在项目保存密钥。界面提前说明标记完成将自动整理记忆，并展示更新任务和模型。浏览、切换等操作不触发模型调用。
5. 子项目完成状态与记忆同步状态分开。显示待更新、更新中、已更新、失败、结果未知；没有可用文本模型时保持待更新并提供配置入口，不声称已经记住。
6. 生成完成并校验后原子写入记忆修订和生效指针。只有与当前完成快照匹配的结果可激活；迟到的旧结果保留历史，不覆盖新版。
7. 同一次完成快照以幂等键登记更新任务，重复点击完成或重开不重复付费提交；结果未知时查原任务，不直接新建请求。未知请求无法核实时，可在任务详情明确确认风险后解除本机并发占用，以继续不同的新任务；保留原unknown、请求历史和费用预留，不自动重发旧任务。
8. 记忆任务失败不丢失已完成视频或撤销交付。配置修复后可继续原任务或明确重试；失败和待同步始终可见。
9. 用户可查看、编辑、撤回自动记忆；所有动作产生可追溯修订。撤回本地记忆不自动改掉已经生成的视频。
10. 重新打开已完成子项目进行修改时，旧完成摘要继续作为旧版本存在；再次完成创建新快照和新摘要。后续已经批准的计划保持原上下文，新计划可采用新摘要。

### 5.3 自动更新中的冲突

- 自动摘要不能静默覆盖用户显式项目设定；冲突项保留双方来源并提示。
- 剧情状态按发生位置和来源记录，不把某集的“角色受伤”无期限覆盖整个角色身份定义。
- 重复项可基于稳定键和来源合并，保留各次出处；相互矛盾的历史观点不能自动合成确定结论。
- 冲突不会阻止其他正常记忆条目自动写入；Agent 使用时显示冲突及采用依据，必要时请求用户选择。
- “自动共享”指完成摘要自动生效，并不等于重写所有项目规则、加载全部聊天记录或自动修改后续已完成内容。

### 5.4 前后关系与上下文来源

- 子项目显示顺序与连续性引用分开。创建下一集时可预选此前已完成摘要；允许参考的前期来源保存为明确关系，不能按当前列表顺序反复猜测。每轮新计划解析这些来源当前生效的摘要，保存实际采用的固定修订；用户显式锁定旧摘要时保留该选择。
- 重新排序或重命名不改写旧前情，也不让未来集摘要悄悄进入早期集。
- 短剧的“前集”以已保存的前期来源关系确定，创建时预选候选；显示排序和编号不作为运行时依据。检索只在这些前期来源及适用的项目共享设定中进行；明确指定的跨期资料可以引用同项目其他完成内容，并展示来源。
- 栏目记忆重点保留已讲主题、术语、资料出处和待展开内容；短剧重点保留事件、人物状态和伏笔。
- Agent 每轮固定项目设定、所选资产/声音版本、前期摘要、本集材料和近期对话，保存包含/遗漏清单与来源版本。
- 内容超出预算时缩减可选材料或要求选择，不静默丢弃用户指定的关键约束；不承诺“完整记住所有项目内容”。
- 项目记忆更新作用于后续新计划。已批准计划、生成视频、旧时间线与已导出制品保留当时快照。

## 6. 数据、目录、接口与一致性

### 6.1 目标业务数据

以下是目标模型，不是当前已有接口：

| 对象 | 核心关系 |
| --- | --- |
| Project | 保留 projectId、libraryId，增加项目类型/说明等概览元数据 |
| Subproject | id、projectId、title、可选编号、显示顺序、状态、revision、主画布/主时间线指针与时间戳 |
| ContentScope | libraryId + projectId，记录编辑归属与来源 subprojectId；资源身份独立；资产来源归属不限制同项目检索与引用 |
| 子项目内容 | 剧本、镜头、画布、制作批次、Agent 会话、时间线及制品有可验证归属 |
| 项目资产登记 | 父项目身份、可选来源子项目、固定资产/实体/声音/文档引用、公共分类标记与使用关系 |
| MemoryRevision | 作用域、类型、内容、来源修订、创建方式、状态与版本 |
| CompletionSnapshot | 子项目、完成修订、采用内容及交付引用、快照 hash、记忆更新任务/状态 |
| ContinuitySelection | 当前子项目允许参考的前期来源及可选锁定摘要；每轮记录实际摘要修订，不依赖显示顺序解析 |
| Deliverable | 子项目、timelineId + revision、渲染/导出回执、固定媒体/hash、输出规格及来源清单 |

角色身份与声音继续遵守 SPEC-001；子项目选择使用哪一版，不创建另一套独立音色系统。公共分类与生成来源分开，加入公共分类不能抹去源子项目。资产读取/引用按父项目校验，制作内容的编辑、审批与结果回挂按其实际子项目校验。

### 6.2 服务端不变式

- 校验 libraryId、projectId、subprojectId 的真实关系，不只依赖下拉框过滤。同父项目、不同来源子项目的资产允许读取和固定引用，不因 sourceSubprojectId 不同而拒绝；跨父项目仍须经过明确导入，不能凭路径或任意 ID 直接引用。
- 剧本与镜头归属一致；常规时间线绑定本子项目剧本，粗剪采用本地镜头。跨集回顾经显式固定媒体引用加入。
- 主画布/主时间线必须属于当前子项目；未创建时允许空指针。
- 每个准备计划和审批哈希固定作用域与输入修订；A 的计划不能作为 B 的操作批准。
- 复制、切换、迁移、恢复不会重复提交供应商任务；后台任务不读取“当前打开的是哪集”来决定回挂位置。
- 历史不可变 revision、plan、receipt 不批量改写 JSON 加字段。可用独立归属登记关联旧身份，新契约明确兼容旧格式。
- 解除 canvas.project_id UNIQUE 时保留所有 canvasId、依赖外键和历史引用，并核查 canvasId === projectId 的调用假设。
- 当前资产以资料库为边界；新增引擎校验保证父项目拥有关系、固定版本和媒体可用性。子项目资产视图负责分类，不能误实现为兄弟子项目之间的访问隔离。
- 资产保留/回收需检查整个父项目的引用；来源子项目归档或移出公共分类不能导致其他子项目采用的原件丢失。

- 未知请求的手动解除固定taskId与attemptId，仅无有效工作者租约时允许；跨子项目编辑守卫仍生效。schema27独立审计表保存本机决定，操作与回执/事件原子保存。仅unknown且已解除不占并发；迟到accepted重新占位、completed正常收存，预算预留不因解除减少。

### 6.3 项目目录

新建项目的目标结构示意：

~~~text
项目目录/
  movieagent.project.json
  shared/
    assets/
    documents/
    memory/
  subprojects/
    <稳定子项目ID>/
      scripts/
      storyboards/
      notes/
      exports/
  .movieagent/
    library/                 # 同项目共享数据库、原件、缓存与任务
~~~

- 子项目标题与目录 ID 分离；重命名不移动身份和整个目录。
- 数据库是身份、归属、版本、记忆状态和引用的事实源。可读记忆/分镜文件采用明确导出/导入，不形成两份自动互相覆盖的事实源。
- 原件沿用项目统一对象存储，不要求复制到每集；可见目录保存用户资料与明确交付。shared/assets 不是唯一可复用位置，资产是否可用由登记、拥有关系与收存状态决定。
- 模型配置留在应用，不在子项目复制 models.json 或 API Key。
- 旧项目的 scripts、shots、audio、exports 等目录保留，不擅自搬走用户文件。

## 7. 兼容、迁移、备份与恢复

1. 迁移前完成一致性备份与空间预检，保留项目和资料库身份；迁移版本由实际迁移链决定。
2. 旧项目建立“默认子项目”，关联原画布、剧本、镜头、会话、时间线和制品；已有多条时间线全部保留，不自动猜测分集。
3. 原有角色、声音和可复用实体保留为项目公共内容；普通素材登记到父项目并保留来源，所有子项目可检索选用，不破坏旧引用。
4. 旧 ID、修订、hash、已批准计划、供应商任务和费用记录保持；作用域用可校验的登记/映射衔接，不伪造生成或回执。
5. 无法判断来源的旧数据保留“历史未分类”，可查看并归属；执行/修改前核对，不静默归给其他项目。
6. 模板空文件、用户手放文件不会自动变成已导入资产、剧本或记忆。
7. 迁移失败不能发布半成版本；明确恢复点。旧应用不理解新格式时拒绝写入，不丢弃子项目和记忆字段。
8. 整项目备份/转移包含全部子项目、共享引用、记忆版本、完成快照、同步任务与制品；恢复后不重复触发旧完成事件。
9. 第一版不提供子项目跨项目移动或独立子项目工程包。单集制品导出与整项目备份分别处理。
10. 编写规格时不运行迁移；实施验收使用隔离夹具。用户现有项目只在实际打开时按迁移流程升级，验收不擅自打开或迁移用户工程。

## 8. 验收标准

以下为批准的验收标准；工程用例与实际结果见 [实施与验收记录](implementation.md)。真实模型语义验收独立列明，不把本地 fixture 视作真实服务质量通过。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 同项目建立两集/两期 | 独立 ID、标题、状态和内容列表，重开保持，不重配模型 |
| AC-02 | 共享角色与声音 | 两个子项目采用同一身份/固定声音版本，局部改动不覆盖其他集 |
| AC-03 | 多画布、多时间线 | 同一子项目至少两张画布、两条时间线，数据独立，主指针归属正确 |
| AC-04 | 多份制品 | 两份输出均追溯到固定时间线修订、规格和媒体 hash |
| AC-05 | 完成自动记忆 | 一次完成自动产生有效共享摘要，用户无需逐条确认；第二集 Agent 清单确有其固定引用 |
| AC-06 | 同步故障 | 未配文本模型、服务失败、结果未知分别可见；制品仍在；恢复不重复付费提交 |
| AC-07 | 幂等与迟到结果 | 重复完成/重开只生成一个对应任务，旧完成快照结果不能覆盖新版 |
| AC-08 | 记忆版本与冲突 | 修改/撤回有历史；显式项目设定不被自动覆写；冲突与来源可见 |
| AC-09 | 连续性顺序 | 排序/改名不改旧前情；未来集不被隐式纳入；历史栏目可查已讲主题与资料状态 |
| AC-10 | 切换与草稿 | 有导航保护；A 的迟到查询、结果和审批不写入 B |
| AC-11 | 后台恢复 | A 提交后切到 B，结果回 A；重开保持归属；未知任务不重复 POST |
| AC-12 | 跨子项目素材复用 | B 的本集视图不混入 A 的素材；全部成果视图可以直接找到并采用 A 的可用资产，无须先加入共享；原件不重复复制，来源版本固定，A 更新/归档不改变 B 已采用内容 |
| AC-13 | 旧项目迁移 | 旧内容完整关联默认子项目；ID、历史、hash、文件和运行状态保留；失败可恢复 |
| AC-14 | 备份/转移 | 全部子项目、记忆、快照与制品可重开，无遗漏表、断引用和旧事件重放 |
| AC-15 | 归档/改名 | 改名不移动身份，归档可恢复，被引用素材不丢失 |
| AC-16 | 引擎作用域 | 同父项目跨子项目资产读取/固定引用成功；跨父项目非法引用及错误子项目的编辑、粗剪、审批被拒绝 |

| AC-18 | 验证分层 | fixture 验证归属、连续性引用和恢复；真实模型语义质量另验，不把模拟当效果保证 |
| AC-19 | 未知请求并发恢复 | 明确风险确认后可解除旧unknown占位；原请求/费用保留、不自动重发、活跃/错attempt/错集拒绝、迟到accepted重新占位、重开及备份保持；并发1可继续不同新任务 |
