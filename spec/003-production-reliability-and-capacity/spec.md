## 1. 目标、边界与顺序

让用户能沿用应用内模型预算，在一个子项目中剪辑 2–5 分钟、100–200 个独立画面片段，并稳定导出成片和原件 ZIP。沿用 SPEC-002 的父项目 / 子项目 / 多条命名时间线组织方式；本需求不改变项目归属或资产共享规则。

实施顺序：A Agent 默认预算 → B ZIP 导出稳定性 → C 时间线容量。A、B 可先独立交付，C 必须完成保存、代理预览、正式渲染、导出和重开，才算交付。

不包含图像 / TTS / 对口型模型接入，不修改用户模型配置，不调用付费模型，不自动续费或重发生成任务；不包含 Linux、远程引擎、视频转场、多层画面轨、无限容量和自动拆集。本次“输出 token 预算”是单次文本输出上限，和费用预算、未知任务账单预留是不同概念。

## 4. A：Agent 默认预算

1. 新打开 Agent 时，输出 token 字段留空，文案“沿用模型预设”；准备命令不包含 outputTokens。
2. 所选预设含 max_completion_tokens / max_tokens 时展示对应有效值；预设未明确设置时显示“未显式设置，使用适配器 / 服务默认值”，不猜一个数字。
3. 用户手填才发送覆盖；沿用现有 1–8192 的契约，不在本需求中提高该上限。模型预设本身的继承路径不新增 8192 截断。
4. 手填覆盖只对当前模型预设和当前 Agent 会话有效。切换会话、模型预设或其修订时清空；同一范围内普通重绘保留。提供“恢复沿用预设”操作。
5. 输入越界、非整数或不是有限数时，本地阻止准备，不创建任务。准备后显示固定的预设 / 覆盖来源和数值；改值重新准备，不能改变已批准请求。
6. 应用原预设和历史派生预设不修改；已准备计划、历史会话、账单预留保持。连接测试、其他生成页的预算不随此 UI 改动。

## 5. B：原件 ZIP 超时与恢复

### 5.1 定位与观测

以 requestId / exportId 关联主进程导出和内部 RPC，记录：阶段、RPC kind、开始 / 结束单调时钟、耗时、累计字节、错误码及固定修订。覆盖 prepare、open/hash、read、写进度回执、verify、publish、最终回执、close。

只记必要元数据；不记录 API Key、模型配置正文、签名 URL、原件内容或完整外部路径。慢阶段与失败日志落到现有受控日志目录。先用归档复现材料与独立本地 fixture 区分：实际 RPC 超时、存储校验耗时、主进程排队、回执提交结果未确认。不能复现原偶发错误时，保留“原故障根因未证实”，仍须完成受控故障验证与稳定性验收。

### 5.2 建议等待策略

以下仅供主进程内部的时间线导出包装使用；不开放 renderer 任意 timeout / 文件权限，不全局修改通用命令或供应商等待时间。

| 阶段 | 建议单次 RPC 等待 |
| --- | --- |
| prepareExport | 60 秒 |
| 打开并校验原件 / 派生产物 | 120 秒 |
| 单个不超过 1 MiB 的 range read | 30 秒 |
| 写进度 / verified / completed 回执 | 30 秒 |
| cancelExport | 30 秒 |
| closeMediaRead | 10 秒 |

导出阶段采用独立控制器，整个调用硬上限 30 分钟；复制阶段超过 120 秒没有成功读写字节则停止并保留可恢复状态。正常读写更新空闲计时，单独的日志或“仍在等待”不算进度；复制计时不把 prepare 的等待算作读写进度。此上限不改变本机渲染的既有 30 分钟策略。最终数值可依据冷盘测量收紧或放宽，但须在同一规格修订中说明依据，不能以无上限等待结案。

取消须立即阻止新块、新发布和新重试；界面 1 秒内进入“取消中”，取消确认仅在实际停止后显示。超时并不证明内部写入失败：回执状态未确认时显示“结果待核对”，按原 requestId 读取原导出记录，不用新 ID 发起一份替代导出。

### 5.3 一致性与资源释放

- 保留原 requestId、固定 timeline revision、源 hash、渲染产物引用和目标文件身份；“仅重试复制”不渲染、不调用模型。
- confirmed completed 不得被迟到的 failed / cancelled 覆盖；一般超时 / 确认丢失不能直接把 verified 降为 failed。verified 后发布结果不明确时，先核对目标 hash 和原回执，不覆盖同名异 hash 文件。
- 原件读取租约当前为 120 秒。导出在剩余不足 45 秒时主动关闭并按同一固定引用 / hash 重新打开；字节长度与 hash 一致后从已复制 offset 继续。MEDIA_LEASE_EXPIRED 时允许一次受控重开，连续无进展失败即退出；周期续期受整体 / 空闲上限约束。
- 超时后迟到的 open 成功回包须关闭所创建租约；迟到回执只用于核对，不触发再次发布。close 错误单独记录，不掩盖原导出错误；引擎退出由现有生命周期清理兜底。
- 取消状态规则：prepared / copying，或已 verified 但尚未开始发布时，取消持久化为 cancelled，并禁止该 requestId 在重开或重试时自动继续。它是 verified 不降级规则的明确例外。用户要重新导出时，需明确点击新导出，以新 requestId 复用固定修订 / 渲染产物；仍不新增渲染或模型任务。
- 取消与已开始的原子发布竞争时，先等发布结果核对：本操作目标已发布且 hash 正确，则收敛为 completed 并显示“文件已发布，取消未生效”，不删除成品；目标确实未发布则收敛为 cancelled；无法判断则保留“结果待核对”，不自动再发布，也不谎报已取消。即使临时已写 cancelled，只有证实本操作取消前开始的发布已经成功，才能核对为 completed；迟到 copying / verified 不能复活取消操作。取消请求之后禁止开始新的 link / rename 发布。
- 同一 requestId 同时重试只允许一个复制过程；失败只清理本操作拥有的临时文件，保护其他导出和用户文件。
- 不降低原件 hash 校验、不扩大 renderer 文件访问、不更改 2 GiB 原件 ZIP 上限；超过上限应预检失败，不能生成残缺包冒充成功。

## 6. C：时间线容量与全链路

### 6.1 容量合同

| 项目 | 现状 | 建议目标 |
| --- | --- | --- |
| 画面轨（video + image 合计） | 64 段 | 256 段 |
| 粗剪输入 / 每剧本镜头总数 | 各 64 镜头 | 各 256 镜头；创作批次 64、生成批次 16 保留 |
| 配音轨 / 音乐轨 | 各 128 段 | 各 256 段；继续保持同轨不重叠 |
| 正式渲染独立媒体 manifest | 320 条 | 768 条，覆盖三轨各 256 个不同固定引用 |
| 单次编辑代理 | 64 个独立引用 | 保留 64，上层去重、分批，逐批确认和入队 |
| 字幕 / 时长 / 时间基 | 1000 条 / 600 秒 / 48000 ticks | 保留 |
| 时间线 JSON / 单次编辑操作 | 1 MiB / 100 个 op | 保留，分别预检并提示 |
| 镜头生成批次 | 16 镜头 | 保留，多批生成后可汇入同一时间线 |
| 输出大小 | MP4 1 GiB / WAV 128 MiB / 原件 ZIP 2 GiB | 保留，片段数扩容不等于解除文件大小上限 |

使用共享容量常量与结构化容量预检，区分画面数、音轨数、字节数、时长、manifest 数和磁盘空间；不得全库替换数字 64，hash 长度等无关规则保持。

达到容量时能继续删除、移动、裁切和替换。第 257 个画面、每音轨第 257 段或使拆分超限的操作，须在原子写入前拒绝；保留草稿、历史与当前修订，提示具体上限。粗剪必须按真实媒体时长与对白组关系检查，不能截掉第 257 段后假称成功。

1 MiB 是独立上限：极长 ID、引用和满额字幕可能先触及它，不承诺各计数最大值在任意文本长度下都能同时保存。测例必须包含正常密集整集和超字节输入。

### 6.2 编辑预览与界面

代理按固定引用和画幅 / fps / fit 分组，单批最多 64 个独立引用，串行准备和提交；汇总所有批次结果。部分批次失败时保留成功结果，只重试失败批次；切换子项目 / 时间线后忽略旧回包，不自动给新时间线排任务。

保留当前仅挂载播放头处画面和活动音频的机制；波形 / 缩略图只加载可视区附近，按固定来源与配方缓存，离开或删除后释放。增加片段计数、明确容量错误及分批代理进度。做性能实测，再决定轨道 DOM 是否需要虚拟化，不预先重写整个编辑器。

### 6.3 正式渲染

用户仍获得一个固定时间线作业和一个最终文件。大时间线不把几百路解码器和所有参数塞进单个 FFmpeg 进程。

建议增加确定性的内部切段：每段最长 30 秒、最多 32 个独立输入；边界落在时间线帧上，跨段媒体按精确 source offset 裁切。每段也处理原视频非静音声、配音、音乐、黑场与字幕。在同轨不重叠约束下，普通跨段背景音乐不会造成无界并发输入。

沿用固定 libx264、fps、色彩、字幕字体与声音策略：分段视频编码后串接时直接复制视频流，避免再编码一次；分段音频保留未限幅的浮点 PCM，串接后统一 limiter、采样对齐，再编码最终 AAC / PCM，避免在每个接缝重启 AAC 或 limiter。每段视频参数、帧数和关键帧必须可串接；字幕跨段按窗口裁切，空隙输出黑场 / 静音，尾帧与尾音不丢失。

小任务可继续使用原编译路径；选择条件固定为不超过 32 个独立输入且估算命令长度不超过 30000。大任务走分段；路径选择不改变已经冻结的媒体引用或 compositionHash。分段子进程串行，输入和中间文件留在本作业暂存目录；保留每进程命令长度、内存、时间、取消和文件边界。视频段使用统一 48000 timescale 的仅视频 MP4，音频用独立 48kHz 双声道 f32le 原始采样文件，以采样数而非容器毫秒时间戳串接。若单帧窗口内就超过 32 个不同输入，预检明确拒绝该输入密度，不能丢弃声音或无限增开解码器。

新冻结计划可携带 intermediateBudgetBytes，界面明确选择 2 / 4 / 8 GiB 并纳入 planHash；历史计划省略该字段时保留原 JSON / hash。中间文件默认预算 2 GiB，计入现有 diskBudgetBytes 总预算；允许用户明确提高总预算后提升中间额度，硬上限 8 GiB。预检要求预算及可用空间覆盖固定原件暂存 + 中间额度 + 最终输出预估 + 1 GiB 余量；运行中不得自动扩大。预算不足或超额应可读失败、保留原件与固定作业，不能无声截断产物。

分段是本批必须验证的实现策略；不能用“保存 256 段成功”代替渲染验收。未验证的分段文件不在崩溃后继续使用；原作业显式恢复时可重新本机渲染，不重新生成云端素材。

### 6.4 数据兼容与回退

A、B 不需要修改业务库 schema。C 建议从 schema 27 提升到 28（若实施时已有新迁移，占用下一版本并同步修订本文件），以版本门槛阻止旧包误写大时间线；迁移只更新版本 / 迁移记录，不重写历史时间线 JSON、planHash 或成片对象。

沿用现有“备份 → 候选库迁移 → 完整性 / 外键验证 → 替换”的路径，同时核对项目备份 / 恢复 / 迁移工具的版本判断。新包可打开旧库和旧 64 段修订；旧包遇到新库应明确拒绝。回退需使用兼容旧包的迁移前备份恢复到另一个目录，不能把库版本改回 27 或覆盖已经创作的新数据。保留新库与新媒体。
