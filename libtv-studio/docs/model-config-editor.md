# 软件模型配置

在工作台的「模型设置 → 软件全局模型配置」新增、编辑或删除条目。配置始终写入软件的 `config/models.json`，不在项目目录创建副本。「重新载入配置」会把文件默认值同步到当前项目。

新增或编辑会打开独立的本机窗口。先选择文本、图片或视频用途，填写 Base URL、API Key、模型 ID 即可保存；名称可选并默认使用模型 ID，条目 ID 内部生成且编辑时保持稳定。文本和图片默认使用受支持的 OpenAI 兼容接口子集，视频默认使用 MiniMax 原生接口。兼容协议、可选参数、价格和私有端点授权都在默认折叠的「高级设置」中；参考图生成也可在此选择。不会根据模型名猜协议，也不会付费试探接口。编辑已有条目时，即使高级设置保持折叠，也会保留其适配器、参数和价格。

当前支持以下实际适配：

| 协议 | 用途 | 默认参数 |
| --- | --- | --- |
| `openai-chat-v1` | 文本 Chat Completions | `max_tokens`，整数 1–8192，默认 1024；价格未知 |
| `openai-image-v1` | 单张文生图 | 可选 `size`、`quality` |
| `openai-image-edit-v1` | 参考图生成单张图片 | 可选 `size`、`quality` |
| `minimax-video-v2` | 文生视频、首帧/首尾帧/参考图视频 | `duration` 4–15 秒，`resolution` 768P，受支持的 `ratio` |

图片尺寸支持 `1024x1024`、`1024x1536`、`1536x1024`；质量支持 `auto`、`low`、`medium`、`high`。「服务默认（不发送）」保留参数缺省行为。视频首帧使用 `adaptive`，纯文本视频使用其他画幅。配置保存不代表供应商已验证这些能力，保存不会自动生成或付费探测。

Key 输入框始终为空且隐藏输入内容。留空保留原 Key；勾选「清除现有 Key」才会清除。清除后可保留地址、模型 ID 和参数，条目为未配置状态。工作台只收到 `hasKey`，不会读取原 Key。已有条目的 ID 固定；需要其他 ID 时新增条目。

文件保存与项目导入是两步。界面明确显示「文件已保存；当前项目已载入」或「文件已保存；当前项目尚未载入」。后者可重新载入；不会回滚文件，也不会重复创建相同的配置或凭据版本。

文件由其他窗口或外部编辑器修改时，保存会拒绝覆盖并保留草稿。使用「读取最新文件以核对」，查看最新公开字段，再明确选择「已核对，保留草稿并采用最新版本」后重试。对同一文件的应用写入使用 SQLite 操作系统锁，繁忙时保留草稿。写入通过同目录临时文件、文件同步和原子替换完成；应用不按锁文件年龄删除活锁。

文件管理的项目连接、模型和全局默认预设会引导到全局编辑器；可另建独立项目预设。删除或清除全局 Key 后，当前项目新增无凭据的连接及关联默认版本，保留所有历史版本和原凭据。已受理任务继续使用原快照和原供应商任务 ID 查询。历史配置会标注来源已移除，新的生成不能继续使用停用的连接。

其他已打开的工作台在下一次新的生成准备或批准操作前，读取固定配置文件并同步变更；同步失败会明确阻止新的生成。已有命令回执的恢复、已受理任务的查询不属于新生成，不受这一步阻断。界面可随时手动重新载入；没有后台监听或自动取消任务。

V1 文件仍可读取；主动保存写成 V2。两版最多 32 条、文件最多 64 KiB。V1 地址、Key、模型 ID 保持全填或全空规则；V2 允许已填写地址与模型 ID 的条目不含 Key。V2 新增 `adapterType`、`parameters`（参数值，非描述符）、`pricing`。公开字段不得含凭据，重复 ID、无效 URL、协议能力冲突和不支持的参数都会被拒绝。

开发接口：`DesktopBridge.readModelConfig`、`openModelConfigEditor({providerId?,expectedVersion})`、`removeModelConfigProvider({providerId,expectedVersion})` 均为类型化、脱敏接口。专用配置 preload 仅导出 `info` 和 `submit`；普通 preload 不接受原始 Key。主进程 `createModelConfigSynchronizer` 为每个引擎提供串行同步和版本缓存；后续工作流的新准备/批准命令应接入 `ipc-policy.ts` 的明确新生成命令集合。
