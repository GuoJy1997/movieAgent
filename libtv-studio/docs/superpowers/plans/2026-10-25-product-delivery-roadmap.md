## 核心实现方式

1. **桌面与引擎分开。** Electron main 管窗口、凭据和文件授权；React renderer 管界面；utility process 管数据库、领域命令与任务。用户安装时不需要自行安装 Node、数据库或开发工具。
2. **本机连接使用统一接口。** `WorkspaceConnection` 统一查询、命令、事件和媒体身份，本期使用受限 IPC。远端认证 HTTP/SSE、独立远端资料库及凭据归属保留为后续设计，不增加本期实现负担。
3. **模型配置分层。** 服务连接、模型能力、任务 Profile、运行快照独立版本化。更换默认模型不会修改已提交任务；文本、图像、视频协议分别适配。
4. **资产、任务、画布各有唯一所有者。** 任务服务推进生成状态；资产服务发布不可变媒体版本；画布服务应用编辑与选择结果。手工操作和 Agent 都调用这些服务。
5. **先保存事实，再显示成功。** SQLite 保存项目、任务、命令和事件；文件对象区保存原件。供应商完成、原件收存、加入资产和画布选中分别记录，下载失败只重试下载。
6. **Agent 先提案，再执行。** 它通过明确工具读取和修改项目，付费动作绑定模型、输入、数量和审批；工具断流、重放、冲突、停止与恢复都有确定语义。

## UI 怎么落地

- 将现有样板拆为真实 React 组件：应用壳、导航、工具栏、输入、模型选择器、弹层、任务卡、资产卡、节点和属性面板。页面读取统一服务，组件不自造业务状态。
- 正式 P1 已采用石墨绿工作台；原型中的材质候选继续留作研究。主题 token 与业务分离，后续选风格不重写任务和存储。
- 动效用于打开弹层、切换面板、拖动/连线、进度与选择反馈；首页可有低强度背景动画。用纯色素材、无图和长内容验收，视觉不能依赖固定封面图。
- 每个正式页面都检查空、加载、失败、离线、权限不足、长文本和键盘状态。模拟数据只在明确的样板/测试环境出现，正式界面不显示伪造成功。
- 未接入的 Agent、音频时间线、导出和远程能力标明阶段或暂不显示可执行按钮；已完成入口才承诺实际行为。

## 验证与推进规则

每批交付同时给出：实际可运行程序、已实现功能、执行过的测试、未验证的服务商/系统，以及可复现验收步骤。以下证据分别标注，不能互相替代：

| 证据 | 能说明什么 |
| --- | --- |
| 协议 fixture 与本地 HTTP 服务测试 | 参数解析、任务状态、失败恢复、请求次数符合本产品契约 |
| SQLite、真实文件与子进程集成测试 | 数据持久化、收存、命令去重、崩溃恢复等本地行为 |
| 用户指定真实 API 的有限验收 | 该连接、模型、参数和实测能力可用；不能推导全部兼容服务均可用 |
| 打包安装后的干净 Windows 验收 | 内置运行时、资源、原生组件、升级/路径处理可用 |
| UI 检验与性能测量 | 实际窗口/DPI、空态/换图后的视觉、交互和资源消耗；不能以静态截图替代 |

本轮 P2 开发未调用真实服务或新增生成费用；历史 MiniMax 有用户授权的有限真实验收，保留原证据。开发接口测试不需要用户 Key；真实接口验收在确定连接、模型及测试额度后进行。密钥通过产品的凭据入口输入，不放入计划、源码、截图或聊天记录。
