## 1. 方案结论与已经确定的方向

做一套以 Electron 为主界面的 AI 影像创作桌面工作台。你可以自行添加模型服务商、API 地址、密钥和模型，按任务选择文本、图像、视频、语音模型；也可以接入自己运行的 Ollama、ComfyUI 等服务。素材、项目、生成记录和配置由你保存。

核心体验是：**一句创作需求 → Agent 拆解剧本与分镜 → 画布组织输入和生成任务 → 资产库维持角色、场景与素材 → 时间线剪辑 → 导出作品。** 手工操作与 Agent 操作使用同一套数据和执行接口，随时可以接管。

“整个 LibTV”在本方案中指覆盖主要创作能力，而非把原站所有商业运营功能一起重建。完整蓝图包含资产、Agent、画布、模型配置、生成任务、剧本分镜、音视频编辑、导出、备份，以及后续的高级节点和团队能力；实施分期交付，每期都能完成实际工作。

| 决策 | 状态 | 对方案的影响 |
| --- | --- | --- |
| 自己使用，第一期以本机为范围 | 用户于2026-10-29明确收窄首期 | 单所有者优先；服务器自部署延期，不先做会员、积分售卖和商业运营 |
| 资产、Agent、画布都要覆盖 | 用户已明确 | 共用项目、素材引用与任务体系，不能只做聊天壳 |
| 自行配置模型 | 用户已明确 | 模型配置与供应商适配是底座，不能绑定某一家服务 |
| Electron 桌面界面 | 用户已明确 | 包含窗口、原生文件操作、托盘、后台任务和安装包 |
| 安装即用，内置本机引擎 | 用户已确认；远程连接首期延期 | 本机无外部数据库依赖，远程连接作为后续可选方向 |
| Windows 首发，macOS 后续 | 本方案建议 | 先把当前使用环境的安装、升级、恢复做完整 |
| TypeScript 模块化引擎，SQLite，独立 Worker | 本方案建议 | 本机和远程个人版共用数据语义；单引擎拥有数据库 |
| 本地文件存储默认，S3 兼容存储可选 | 本方案建议 | 首次部署不强制额外对象存储服务 |
| 第一版优先可靠工作流，再扩展高级节点和多人协作 | 本方案建议 | 控制复杂度，避免每个功能只有外观 |

这里的建议均可调整，不代表你已同意具体技术栈或时间预算。

## 3. 使用场景与成功标准

### 3.1 主要使用场景

1. **手工创作**：上传参考图，在画布连接提示词与图片，选择自己的模型生成图像或视频，比较多个版本，把满意结果加入资产库。
2. **Agent 创作**：输入“做一个 30 秒产品短片”，Agent 提出剧本和镜头计划，经你确认后组织节点、生成素材，再交给时间线。
3. **角色连续性**：建立角色、场景和风格卡，多个镜头引用同一组已固定版本的参考素材，记录每次生成参数和差异。
4. **模型试验**：同一输入分别调用两个服务商，比较质量、耗时、失败率和实际成本；保留独立结果，不覆盖旧作品。
5. **长期积累**：素材、项目模板、角色设定和 Skill 能复用；从本机迁移到服务器后仍可打开项目。

### 3.2 第一版完成的定义

用自己配置的至少一个文本模型、一个图像模型、一个异步视频模型，完成一段含 3–5 个镜头的短片：建立项目 → 导入素材 → 剧本/分镜 → 图像 → 视频 → 配音或导入音轨 → 简单剪辑/字幕 → MP4 导出。

关闭窗口、重启应用、请求超时、单个生成失败都不会让整个项目无法恢复。完全退出或关机后，本机计算暂停，已接单的云端任务可能继续，恢复时必须重新对账。能查出每个输出来自哪个输入版本、模型配置和任务尝试。供应商没有提供的费用或取消能力，要明确显示未知或不支持。

### 3.3 首版不包含的能力

公开社区、支付订阅、积分商城、模型训练平台、原生移动应用、完整专业非线性剪辑器、无限自动 Agent、所有供应商即插即用、多人实时共同编辑和复杂 3D 导演台不进入首版验收。它们有后续位置，不能用来拖延核心闭环。

## 4. 实现路线比较

| 路线 | 优点 | 代价 | 适用性 |
| --- | --- | --- | --- |
| Electron 仅作远程界面 | 客户端简单，长任务集中在服务器 | 本机使用仍需额外安装后端，无法真正安装即用 | 已讨论，用户选择更完整的本机模式 |
| Electron + 内置引擎 + 可选远程引擎 | 安装即用、原生文件体验、服务器任务可持续运行 | 需要桌面进程管理、两种传输及打包升级验证 | **采用，符合用户明确选择** |
| 纯 Web / 商业 SaaS | 浏览器访问和公开运营方便 | 不满足桌面主界面偏好，SaaS 还增加运营范围 | 不作为当前主交付 |

内置引擎与远程引擎共用领域服务、任务状态机、适配器和数据格式。本机通过窄 IPC 通道连接，远程通过认证 API 连接。首版两边都用 SQLite 与单引擎调度，避免为个人工具先维护两套数据库。多实例服务与 PostgreSQL 迁移留到确有团队规模需求时再做。

## 6. 产品结构与关键界面

主导航保持五个入口：**项目、创作 Agent、资产、任务、设置**。窗口顶部一直显示当前连接“本机资料库 / 服务器名称”，防止误认数据位置。工作台进入项目后，以画布为中心。优先覆盖 Windows 1440×900、1920×1080 与高 DPI 缩放；较窄窗口收起侧栏。手机和浏览器入口后置。

### 6.1 首次启动与模型设置

首次启动选择本机资料库位置或添加远程服务器。本机由当前操作系统账户使用，不强制注册外部账号；远程模式登录自部署实例的所有者账户。模型设置分为“连接”和“模型”两层：一个连接可以注册多个模型，一个模型也可对应不同连接。输入密钥后仅显示掩码，界面不再读回原文。

配置流程：选择适配器 → 填服务地址与认证 → 添加/发现模型 → 确认能力与参数 → 测试 → 保存。模型发现是辅助功能，不是必需条件；服务没有模型列表接口时允许手工输入 ID。鉴权测试、文本测试、图像/视频试生成分别标记，可能产生费用的测试必须显示内容和估价并由你点击启动。

### 6.2 项目页

显示项目封面、画布数量、最近修改、运行任务和存储占用。项目可包含多个画布、剧本、镜头表和时间线。项目复制复用不可变素材对象、创建新的项目和节点身份；不得复制正在运行的任务或供应商作业。

### 6.3 画布工作台

- 左侧：节点工具栏、资产抽屉、镜头列表。
- 中部：无限画布，缩放、框选、分组、对齐、复制、搜索、快捷键。
- 右侧：选中节点的内容、模型、参数、输入、输出版本和诊断。
- 可折叠 Agent 面板：对话、计划、工具进度、待批准操作、结果导航。
- 底部按需展开：任务列表或时间线；不让视频编辑一直占用画布空间。

节点明确展示：缺少输入、待运行、排队、生成中、需处理、失败、有新输出。没有供应商进度时显示阶段与已耗时，不伪造百分比。模型更换导致参数不兼容时列出受影响项，由你保留草稿或修改，不静默删掉设置。

### 6.4 Agent 首页与会话

保留类似 LibTV 的“直接描述任务 + 选择 Skill”入口；提交后在选定项目内创建会话和任务提案。支持全能创作、剧本创编、导演分镜三种模式，但它们共用一个运行引擎，差别由提示词、工具范围和输出契约定义。

### 6.5 资产与任务中心

资产页支持网格/列表、文件夹/标签、媒体类型与实体筛选；详情页展示版本、来源、参数、引用位置和相关产物。生成历史来自任务/产物记录，收藏进入资产库，无须复制媒体文件。

任务中心用于排队、失败恢复、停止、查看费用和供应商任务 ID。错误要给出可行动原因，例如“此模型不支持尾帧”“供应商是否接单未知”“输出下载失败，可以重试保存”，而不是统一显示“生成失败”。

## 7. 总体技术架构

```text
Electron Renderer：React 工作台（本地打包页面）
  ├─ 项目 / 资产 / 画布 / Agent / 模型设置
  ├─ IndexedDB 未确认操作与恢复草稿
  └─ 最小 preload bridge，不暴露 Node / 文件系统 / 原始 IPC
              │ 命名命令、事件、文件授权句柄
Electron Main：窗口 / 托盘 / 文件对话框 / 凭据保护 / 生命周期
  ├─ LocalConnection → IPC → 内置引擎 utility process
  └─ RemoteConnection → HTTPS REST + SSE → 自部署引擎
              │ 共用应用服务与契约
模块化引擎（本机或远程，各自独立资料库）
  ├─ 身份与项目模块         ├─ 资产与实体模块
  ├─ 画布命令与版本模块     ├─ 模型注册与凭据模块
  ├─ 任务/预算/产物模块     └─ Agent 会话与审批模块
              │ 短事务、持久调度、事件日志
SQLite（引擎独占写入口）       BlobStore
  ├─ 业务数据与版本            ├─ 本地持久卷（默认）
  ├─ 任务/尝试/预算            └─ S3 兼容对象存储（可选）
  └─ 调度记录 / 租约 / 恢复游标
              │ 持久任务、租约、恢复
Worker 进程
  ├─ Agent 编排 → 文本/多模态适配器
  ├─ 生成调度 → 图像/视频/音频/ComfyUI 适配器
  ├─ 产物收存 → 校验、探测、缩略图、代理媒体
  └─ 媒体渲染 → 固定版本 FFmpeg、隔离临时目录
              │
你配置的云端 API / 私有网关 / 本地推理服务
```

### 7.1 建议技术栈

| 层 | 建议 | 选择原因与边界 |
| --- | --- | --- |
| 桌面 | Electron，React + TypeScript | 原生窗口和文件体验；UI 与执行引擎隔离 |
| 构建与分发 | electron-vite + electron-builder 稳定版 | 分别构建 main/preload/renderer，Windows 安装包优先 |
| 画布 | React Flow / @xyflow/react | 使用其节点、边和交互基础；执行语义由本项目实现 |
| 前端状态 | Zustand 管编辑态，TanStack Query 管服务器查询 | 保存、任务、选择态有各自所有者，避免一个巨型 store |
| UI | 可维护的组件基础与统一设计 token | 中文优先、暗色工作台、可访问性；不照搬原站专有视觉资产 |
| 引擎 | TypeScript，桌面 utility process；远端 Node.js + Fastify | 共用应用服务，本机 IPC 与远程 API 分开适配 |
| 数据 | SQLite + 显式版本化 SQL 迁移，原生驱动 | 单引擎写入、启用外键与 WAL，短事务处理预算及状态 |
| 调度 | SQLite 持久任务表 + 引擎调度器 + 受控 Worker | 不要求用户装 Redis/PostgreSQL；租约和恢复属于本产品职责 |
| 媒体 | FFprobe + FFmpeg Worker | 探测、缩略图、代理、基础渲染；GPU 编码不是必需 |
| 事件 | 本机 IPC / 远端 REST + SSE，同事件契约 | 支持游标恢复；协作阶段再引入 WS |
| 部署 | 本机安装包；远端 Docker Compose 单引擎 + 持久卷 | 本机不依赖 Docker；远端默认单实例 |
| 验证 | 契约/数据库集成、Electron E2E、安装包测试、媒体样片 | 不把浏览器开发版跑通等同于桌面包可用 |

React Flow 官方建议组件记忆化、精细状态订阅及避免拖动导致大范围重渲染；本方案把大图性能作为独立验收项。[官方性能指南](https://reactflow.dev/learn/advanced-use/performance)

本机和远程个人版都由一个引擎串行处理短写事务，原子保存任务、预算预留和调度记录。Worker 不直接操作数据库；网络等待不占用事务。SQLite WAL 不适合网络文件系统，因此数据库必须位于运行引擎的本地磁盘，不把数据库文件放在 NAS 共享目录给多机共用。[SQLite WAL 约束](https://sqlite.org/wal.html)

electron-vite 明确区分 main、preload 和 renderer 构建；本方案采用这种隔离。打包使用稳定版工具，不能把预发布文档中的功能直接当成已可用。[electron-vite 官方说明](https://electron-vite.org/guide/)

### 7.2 代码与契约边界

新产品建立独立仓库，不混入当前 REA 仓库。建议结构为 `apps/desktop`（main/preload/renderer）、`apps/server`、`packages/engine`、`packages/contracts`、`packages/domain`、`packages/providers`、`packages/storage`、`packages/media`、`packages/ui`、`deploy` 和 `docs`。这是后续目录建议，本次不创建产品工程。

业务领域不直接依赖供应商 SDK。适配器把外部响应转换为统一事实；前端、Agent、画布都消费同一契约。生成状态只有任务模块能推进；素材版本只有资产模块能创建；画布变更都进入画布命令服务。避免三个入口各自保存一份不一致状态。

依赖版本在开工时核验并锁定，数据库/队列迁移版本和媒体镜像 digest 纳入发布清单。本文不把“最新版本”作为长期运行约束。

## 8. 模型配置中心与适配层

### 8.1 四层配置对象

| 对象 | 职责 | 典型字段 |
| --- | --- | --- |
| ProviderConnection | 连接一个服务 | adapterType、baseUrl、credentialRef、headers 的密钥引用、网络策略、超时、并发 |
| ModelDefinition | 描述该服务上的模型能力 | modelId、任务类型、输入/输出、参数、限制、流式/工具支持、定价版本 |
| ModelProfile | 为某类工作保存一套选择 | “剧本模型”“分镜图”“快速预览”“最终视频”，主模型、参数、可选候选 |
| RunConfigSnapshot | 冻结一次实际执行的配置 | 连接版本、模型/适配器版本、参数、能力快照、计价规则、输入版本 |

界面名称与供应商 model ID 分开。任务引用不可变配置版本，修改默认模型不改变已提交任务。API Key 不进入运行快照、提示词、浏览器状态或导出包；运行快照只记录凭据引用和版本标识。

### 8.2 真正可配置的内容

支持 API Base URL、认证方式、模型 ID、额外 Header、任务超时、并发/速率、默认参数、能力启停、成本规则、输入限制和输出保存策略。Header 名称与值受约束，敏感值独立存储；不能覆盖 Host 等传输管理字段。

| 接口族 | 接入方式 | 不能假设的事情 |
| --- | --- | --- |
| OpenAI 兼容文本/视觉 | 内置 Chat Completions 适配器；Responses 为独立适配器 | 宣称兼容不等于工具调用、图片输入、结构化输出全部兼容 |
| 其他原生文本 API | 独立原生适配器 | 消息格式、工具事件和 token 统计不一定一致 |
| 图像生成/编辑 | 图像适配器，声明生成、编辑、遮罩、参考图等能力 | 同一服务的图像接口不一定服从文本协议 |
| 视频/异步生成 | submit、query、结果收存；cancel/reconcile 按支持情况声明 | 返回超时不等于未接单，取消不一定成功 |
| TTS/ASR/音乐 | 按任务类型适配 | voice ID、时间戳、音频格式和计费单位不同 |
| Ollama | 兼容接口或原生适配器，逐项能力验证 | 官方仅承诺 OpenAI API 的子集。[兼容说明](https://docs.ollama.com/api/openai-compatibility) |
| ComfyUI | 工作流模板 + 输入节点映射 + 任务/产物适配 | 不能只填模型名；节点依赖、工作流版本和输出节点都需管理 |
| 自定义 HTTP 服务 | B 阶段提供受限声明式模板；特殊认证/流式协议写代码适配器 | 不提供任意 JavaScript、Shell 或无限 JSON 表达式执行 |

第一阶段以你能提供的 API 为准，验收至少 1 个文本、1 个图像、1 个异步视频连接。不能在没有文档、账户和测试结果时承诺所有中转服务可用。

### 8.3 能力描述与动态表单

每个模型声明 `taskTypes`、`inputKinds`、`outputKinds`、`supportsTools`、`supportsStructuredOutput`、`supportsStreaming`、`supportsCancel`、`supportsIdempotency`、`supportsLookupByRequestId` 以及尺寸、时长、批量、参考图数量等约束。能力同时保存来源与验证状态：适配器内置、管理员声明、实际测试。未知与不支持分开。

参数包含类型、默认值、范围、选项、条件依赖和成本影响；跨参数规则例如“该比例只支持这些分辨率”“首尾帧模式不能同时使用多参考视频”。前端用于提示，服务端执行前重新验证。未知字段拒绝或放入明确命名的 provider 参数区，不静默忽略。

示例是本产品契约草案，不是任何供应商可直接执行的配置：

```json
{
  "schemaVersion": 1,
  "connectionRef": "my-video-provider@3",
  "modelId": "YOUR_VIDEO_MODEL_ID",
  "taskTypes": ["image_to_video"],
  "inputs": {"image": {"min": 1, "max": 1}, "text": {"required": true}},
  "capabilities": {"cancel": "unknown", "idempotency": "unsupported"},
  "parameters": {
    "durationSeconds": {"type": "integer", "enum": [5, 10], "default": 5},
    "aspectRatio": {"type": "string", "enum": ["16:9", "9:16"]}
  },
  "pricing": {"status": "unconfigured", "currency": null},
  "verification": {"submit": "untested", "recovery": "untested"}
}
```

内置 API 契约采用固定 JSON Schema 方言和代码审查。可编辑模型参数使用受限数据描述语言，在边界校验深度、长度、正则和引用，不把任意用户 schema 交给框架代码生成器。Fastify 官方明确提醒其校验/序列化编译功能应把 schema 视为应用代码。[Fastify 校验说明](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/)

### 8.4 路由与适配器契约

路由先按任务与能力过滤，再按你选中的 Profile 执行。可选择“快”“质量优先”等配置，但这些名称对应你保存的模型和参数，不暗中换模型。跨供应商降级可能改变价格、质量和隐私接收方，默认给出建议，获得本次或预先限定的授权后才执行。

适配器对外提供：配置验证、连接探测、模型发现（可选）、能力、估价（可未知）、输入准备、submit、query（异步）、cancel（可选）、reconcile（可选）、产物解析与清理。LLM 另有流式输出标准化。每个结果是明确的成功、失败、未知或不支持；不得用 null 兼任所有含义。

幂等能力需要记录键位置、作用域、有效期、同键异参行为与测试依据，不能只有一个布尔值。文本适配器保存 message/tool-call 流、usage、stopReason 与可选恢复句柄；媒体适配器保存 providerTaskId 和产物描述。能聊天与能可靠调用工具是两项不同的测试结果。

自定义 HTTP 模板仅允许预定义字段映射、静态路径、JSON Pointer、枚举状态映射和有上限的轮询。秘密只能通过 credentialRef 注入。复杂签名、双向流、上传特殊格式需正式适配器及契约测试。

## 9. 生成任务与费用控制

### 9.1 任务与尝试分开

`GenerationTask` 表达“用这些输入生成这个结果”的业务意图；`TaskAttempt` 表达一次可能向供应商提交的尝试。用户重试、改变模型或输入会形成新的尝试/任务关联，历史不覆盖。每次尝试固定输入版本、图执行版本、连接配置、模型、参数、计价规则和适配器版本。

客户端提交携带幂等键。引擎在短事务内校验输入、冻结快照、预留预算、创建任务并入队。相同幂等键与相同请求返回原任务；相同键对应不同内容拒绝。队列可以重复唤醒，处理器必须检查任务和租约，不能每次唤醒都提交供应商。

### 9.2 任务状态及恢复

```text
DRAFT → VALIDATING → AWAITING_APPROVAL → QUEUED → SUBMITTING
                                                ├─ 接单明确 → RUNNING
                                                ├─ 明确拒绝 → FAILED
                                                └─ 提交结果未知 → SUBMISSION_UNKNOWN
RUNNING → COLLECTING → SUCCEEDED
   ├─ 供应商确认失败 → FAILED
   ├─ 超时无法确认远端状态 → RECONCILE_REQUIRED
   └─ 请求取消 → CANCEL_REQUESTED → CANCELLED / 继续完成 / RECONCILE_REQUIRED
```

无需审批的任务跳过 `AWAITING_APPROVAL`；取消排队任务可直接结束且释放尚未消费的预算。供应商执行状态、素材收存状态、画布挂接状态、费用核实状态分别记录。不能因为文件下载失败，就把已经生成的视频当成“尚未生成”重发。

| 故障位置 | 正确恢复行为 |
| --- | --- |
| 入队前失败 | 整个事务回滚，不留下已扣预算但无任务的状态 |
| 请求已发出，未拿到响应 | 标记提交未知；仅在有供应商幂等保证或查询依据时自动恢复提交 |
| 已拿到供应商 task ID | 持久化 ID，重启后继续查询原任务 |
| 供应商完成，下载 URL 暂时失败 | 保留完成事实，只重试下载/转存；临时 URL 过期则尝试刷新，不能盲目重新生成 |
| 文件已保存，数据库写入失败 | 根据收存记录和 hash 对账；孤立对象延迟回收，不重复生成 |
| 节点已删除或被修改 | 结果仍进入历史；不复活节点、不覆盖新内容，提供手动挂接 |
| Worker 崩溃或睡眠 | 租约过期后先对账，再恢复；旧 Worker 的迟到写入被 fencing token 拒绝 |
| 取消与成功同时到达 | 保存真实结果与取消请求记录；取消请求不等于远端已停或已退款 |

**无法跨网络保证供应商恰好执行一次。** 能保证的是本系统命令幂等、已知远端作业不重复提交、未知情况显式停下，并尽可能通过供应商机制对账。

租约和 fencing 只能限制本系统写回，不能阻止已发出的付费 HTTP。Worker 发送前申请一次 dispatch permit，引擎持久化 dispatch intent、请求摘要、稳定 clientRequestId 和幂等策略后授权。崩溃后发现 intent 或 SUBMITTING 一律先对账；不因租约过期重发。付费 submit 的 SDK/HTTP 隐式重试默认关闭，只有已证明未受理或供应商幂等仍有效时才允许重试。旧 Worker 迟到响应可以作为外部事实入对账 inbox，但不能恢复其旧租约写权限。

轮询按适配器和供应商限流设置退避、抖动、最大间隔与 deadline。等待远端作业时不占着长数据库事务。Webhook 只有在可达且签名校验成功时使用；本机模式默认轮询，远端可使用回调加轮询兜底。重复、乱序通知不得回退终态。

### 9.3 预算与计价

费用记录分成 `estimate`、`reservation`、`reportedActual`、`settlementStatus`。数量和金额使用整数最小单位或固定精度十进制；币种不同不直接相加。没有供应商 usage/账单时标记估算或未知，不能用 0 代表免费。

支持每次执行、每个项目、每日和连接级预算；Agent 自动生成另有本次运行总预算、最大任务数、最大工具步骤和墙钟期限。审批固定 `planHash + configRevision + inputVersions + quoteRevision + expiresAt`。输入、模型、数量或计价变化超出审批范围，就重新估价与审批。

预算预留必须原子执行，防止并发任务分别看见“还有余额”而总额超限。提交未知期间保留相应预留或转为待核实占用；取消不自动假定退款。供应商未暴露可强制的费用上限时，本地预算只是提交控制，不能保证远端最终账单不超过估价。严格模式拒绝无可信上限的自动执行，人工可设置明确的风险额度。

默认生成手动审批。可按会话启用有上限的自动模式，退出会话不把授权扩大为全局授权。

ApprovalGrant 同时绑定 libraryId、executionOwner、runId、action/plan hash、模型/输入/计价版本、允许连接与素材、费用币种及上限、任务数和期限。引擎在提交事务中消耗或计数，重复点击返回原结果；切库、改变执行所有者或扩展付费范围不能沿用旧授权。Skill 声称的工具权限只作为请求，与引擎策略及当前授权取交集。

## 10. 资产、实体与存储

### 10.1 分开四种身份

| 数据 | 含义 | 生命周期 |
| --- | --- | --- |
| BlobObject | 实际二进制对象，含 hash、大小、媒体信息、存储键 | 内容不可变，可以被多个版本引用 |
| Asset / AssetVersion | 用户理解的素材与某个固定版本 | 改名、标签可变；内容更新创建新版本 |
| Entity / EntityRevision | 角色、场景、道具、风格、声音的设定集合 | 引用指定素材版本，可有自己的描述与约束 |
| ProviderResourceBinding | 某供应商上传文件、主体或声音 ID | 绑定连接/账户/区域/版本，可过期或审核失败 |

文件夹只是组织方式；项目、画布、资产、任务均使用独立 ID。文件 URL 是临时访问手段，不能代替资产身份。普通生成历史不是全部自动加入收藏资产；两者复用相同 BlobObject。

实体示例“主角 A”可含正脸、侧脸、全身、服饰、声音以及文字禁忌项。运行时冻结其 revision，组装为当前模型支持的参考输入。某服务的“主体 ID”不会直接成为通用实体 ID。跨模型一致性通过参考素材、提示词、参数与人工挑选改善，不能承诺人物绝对一致。

### 10.2 导入与收存流程

```text
选择/拖入文件 → 建立导入记录 → 分块复制到临时区
→ 校验大小/类型/hash → 媒体探测 → 原子落入对象区
→ 创建不可变版本 → 异步缩略图/代理 → 可供画布与 Agent 引用
```

桌面默认复制进应用资料库，不依赖源文件继续存在。大文件可取消，显示已复制字节；导入失败清理受本次导入拥有的临时对象。外部文件就地引用仅作为高级模式：记录指纹、移动/缺失状态，迁移和远端执行前必须收存。

HTTP 导入先通过受限下载器，再进入相同收存管线。不会让 FFmpeg 或任意模型 URL直接访问本机文件。图像解码、视频时长/像素、压缩包展开、对象大小均设资源限制。

供应商结果优先立即保存原件，再生成预览。临时输出链接不能作为永久素材地址。所有派生对象记录来源版本和处理参数；缩略图可以重建，原始作品必须进入备份。

收存状态单独区分 pending、collecting、durable、retryable_failure、unrecoverable。只有原件完整落盘并校验后才显示“已保存”；不可重取的临时输出保留完成事实、诊断和费用，并明确显示损失状态。新生成、导入和渲染都按存储目标原子预留原件、临时文件和预览所需容量；空间紧张时优先收存已付费结果，暂停新任务。预估容量不能替代实际写入时的空间检查。

文件系统/对象存储与 SQLite 无法组成同一事务。采用持久收存记录、唯一 staging 身份、完整性校验、最终对象落盘、数据库发布引用的顺序；只在最终事务完成后对用户显示 ready。崩溃后对账原收存记录，已写完的对象不必重新生成。可选 S3 直传只给 staging key 写权限，最终对象不可由客户端覆盖；发布前绑定具体对象版本或重新校验最终字节。预签名 URL 可被重用、相同 key 可被覆盖，multipart ETag 也不一定是内容 MD5，因此应用自己保存强 hash。[S3 预签名说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)、[multipart 说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html)

### 10.3 版本、删除与迁移

画布和时间线默认引用固定版本；“跟随最新”只允许作为编辑辅助，执行前必须解析并固定。资产删除先进入回收站。存在项目引用、运行任务或未过保留期的对象不得物理回收；垃圾回收重新检查引用，具备失败重试和审计。

每种文档的领域所有者按版本化 schema 提取引用，内容版本与引用边在同一个 SQLite 事务中写入；引用计数仅作加速，不能是删除的唯一依据。长任务、导出和备份创建持久 pin。GC 在事务内检查引用和 pin 并认领 deleting，新引用与删除认领互斥，物理删除失败保留认领供重试；不重用删除中的对象键。未知 schema 的引用不能被解释成“没有引用”。

建议回收站默认 30 天，可配置；缓存单独按空间上限淘汰；未完成导入和无人引用对象设置独立宽限期。磁盘不足时暂停新收存和新渲染，不删除用户原件来腾空间。

项目交换包包含 manifest、项目/画布/剧本/时间线的版本数据、必需素材、hash 和格式版本。不包含密钥、会话令牌、绝对源路径或可自动执行的脚本。导入先预检容量/版本/路径，再事务提交；重映射节点、边、镜头、剪辑与资产引用。供应商绑定标记待重建，正在运行的任务只导入历史，不在新环境自动重发。

默认导出选定项目快照的可执行依赖闭包，包括固定实体、素材、字体及脱敏配置；完整历史归档另选。manifest 带 packageId、sourceLibraryId 和范围。目标持久保存 migrationId 与源/目标 ID 映射，中断后恢复同一次导入；重复导入完成包默认提示已存在，只有“导入为新副本”才创建新身份。二进制按 hash 复用，但不因名称或字节相同而合并逻辑资产。导入的任务/费用只作来源历史，不计入目标新预算，也不取得源作业的取消或重试控制权。

### 10.4 搜索

首版先做名称、标签、类型、项目和生成参数的结构化检索。中文名称采用规范化子串/关键词索引，不依赖英文分词假设。语义检索后置，可配置独立 embedding 模型并按模型版本重建索引；向量检索不是核心创作流程的前提。

## 11. 画布与可执行工作流

### 11.1 编辑图与执行图分离

画布允许自由摆放、分组、注释和参考关系；只有带有执行语义的边进入任务图。边声明源/目标端口、数据类型、基数和用途。注释线可以形成环，执行依赖必须通过 DAG 校验；循环创作以后作为显式受限循环节点设计，不靠无限循环连线实现。

每个节点有 manifest：`typeId`、`schemaVersion`、编辑字段、输入/输出端口、参数校验、执行器类别、迁移器和 UI 组件。节点业务内容使用结构化数据，不把所有领域关系塞进无类型 JSON 字符串。

端口使用稳定 portId，声明 Text、ImageAsset、VideoAsset、AudioAsset、MaskAsset、ShotSet 等类型，以及基数和是否有序；多参考图顺序由显式 orderKey 决定，不随节点位置或边的数组顺序变化。视频截帧、图片转遮罩等转换作为可见步骤。跨画布复用通过固定产物或版本化工作流接口，不直接读取另一张活画布内部状态。

| 节点族 | 首期处理 | 后续能力 |
| --- | --- | --- |
| 文本、图片、视频、音频 | 内容与素材引用，文本/媒体输入输出 | 富文本、局部编辑、多版本对比 |
| 生成节点 | 文本、图像、视频；绑定 ModelProfile | 音频、模型专有扩展、多候选 |
| 分组、备注、引用 | 布局、复用、显式输入映射 | 可发布工作流模板 |
| 剧本、分镜、镜头 | B 阶段结构化编辑，镜头输出映射 | 镜头拆解、批量一致性处理 |
| 时间线 | B 阶段聚合固定媒体版本并导出 | 高级合成与转场 |
| 全景、3D 导演、镜头切换、专业控制台 | C 阶段逐项验证用途 | 不以首版出现占位按钮冒充完成 |

### 11.2 运行语义

执行入口分“运行当前节点”“运行所需上游”“运行选定子图”。默认仅运行当前节点并读取明确选定的固定产物；输入缺失或上游已 dirty 时展示原因和建议范围，不自动扩大付费任务。明确选用的旧产物可以继续使用，显示版本。其余模式先预览上游闭包，检查缺失/类型/能力/预算，形成可审阅计划。未被请求的无关节点不执行；批次、扇出和候选数明确展开，受数量与费用上限控制。

计划的每个输入绑定固定 AssetVersion/Artifact，或本计划内明确的 StepOutput。上游完成后，把 StepOutput 解析成不可变产物再创建下游快照，不重新遍历活画布。审批覆盖这份依赖计划及产出上限；正常依赖完成不重复要求审批，改变模型、输入绑定或展开范围才重新校验。一个步骤失败时阻断依赖它的步骤，独立分支按已批准计划继续；未决状态先对账，不自动整图重跑。

运行保存 `graphRevision`、节点输入 hash、模型配置和输入素材版本。图像生成等非确定性任务不因参数相同就默认为缓存命中；只在用户选择复用已有产物或该执行器明确可缓存时复用。

内容、输入或模型改变会使下游标记“需重新生成”；移动位置、改颜色不使生成结果过期。旧结果始终可查看。迟到结果只在节点仍存在且执行绑定仍匹配时成为当前输出，否则保存在历史并提示。

节点区分 incarnation、semanticRevision、layoutRevision，每次运行建立唯一 RunBinding 与 activeRunBindingId，输出选择也有自己的版本。只有身份、当前绑定和语义前置条件匹配，才能在事务中自动选择结果；不能只比较输入 hash，避免 A→B→A 编辑或同参数连续生成时旧任务抢占。删除后撤销恢复为新 incarnation，旧结果可手动挂接；用户手选历史输出也阻止迟到回写。运行状态、dirty 与“已有旧输出”分别表示，不互相覆盖。

### 11.3 保存、冲突与撤销

编辑命令包含 `commandId`、`canvasId`、观察时的 `baseRevision`、操作列表、字段/实体前置条件和客户端身份。引擎在一个事务内校验关系及前置条件、应用操作、追加事件并增加版本，成功后返回 ACK。全画布版本用于排序；具体冲突按相关语义字段判断，不能因无关移动而拒绝全部修改。客户端可以立即显示乐观结果，但必须区分“已保存”和“待确认”。

未确认操作写入本地恢复队列；远程断线期间允许编辑草稿，不允许假装远端生成已提交。恢复时按 commandId 去重、获取最新快照、重放无冲突命令；同一字段冲突展示差异，由用户选择，不用整图覆盖。

命令先写入以 libraryId/canvasId/clientId 分区的 outbox，再发送。ACK 丢失使用原 commandId 和原 payload 重发或查询 receipt；同 ID 不同内容拒绝。只有匹配的持久 receipt 才能移除本地命令。未确认草稿不按普通缓存 TTL 静默清理；超过安全重放窗口则转为可恢复草稿，不作为新命令盲目应用。

Agent 提案带基础版本和前置条件；修改过的节点须重新检查，删除、覆盖内容或扩大执行范围需重新审批。拖动和内容编辑分字段处理，避免拖动画布就让整个生成计划失效。

提案声明 readSet 与 writeSet，既检查准备修改的字段，也检查决策所依赖的事实，例如“该镜头还没有视频”。一次接受提案作为原子文档事务。逆命令也带版本条件，只撤销自己写入且尚未被后续修改的字段；冲突时提示处理，不用通用逆 JSON 覆盖后来编辑，不留下悬空边。

撤销/重做记录语义命令与逆操作，建议默认 100 步、上限可配置。撤销布局不撤销已发生的供应商费用；撤销节点删除也不恢复已经取消的任务。重做付费生成需要明确产生新尝试。

### 11.4 性能与多窗口

重媒体节点只渲染缩略图，选中后加载播放器；默认同时播放一个视频。按节点/字段订阅状态，拖动过程合并布局变更，最终位置单独确认。对不可见内容懒加载，对资源预览使用代理文件。

Electron 多窗口、用户与 Agent 同时编辑都可能冲突，即使只有一个用户也保留版本机制。高级多人实时协作再加成员、光标、锁和权限；Agent 事件流不能被当成协作同步协议。

## 12. 创作 Agent

### 12.1 编排方式

首版采用一个可持久恢复的主 Agent，加确定性的任务执行器。剧本、导演、全能模式使用不同提示词版本、工具允许列表和产出 schema。先不引入多个 Agent 相互聊天，避免不必要的上下文与费用膨胀。

运行流程：读取相关项目摘要 → 明确约束 → 产出剧本/镜头/画布提案 → 校验 → 展示差异、数量、模型和预算 → 审批 → 执行工具 → 等待异步任务 → 整理结果。每次工具调用前后保存 checkpoint，不把一条长网络连接当成任务生命期。

工具参数必须完整闭合、严格解析并通过 schema/权限/预算检查后，才持久化执行意图并调用工具。部分 JSON、截断响应和中途断流都不执行。模型协议 toolCallId 与引擎业务 actionId 分开；checkpoint 重放取回已有 action 结果，不重复副作用。LLM 无续流能力时保存 interrupted 消息，新推理属于新的计费尝试；跨供应商切换重新构造规范化上下文，不重放另一适配器的私有 continuation/signature 数据。

### 12.2 工具边界

| 工具族 | 例子 | 执行规则 |
| --- | --- | --- |
| 读取 | search_assets、read_entity、inspect_canvas、get_task | 仅访问当前工作区授权范围 |
| 提案 | propose_script、propose_shots、propose_canvas_patch | 结构化草稿，不直接写入最终项目 |
| 修改 | apply_canvas_patch、save_script、create_entity_revision | 通过领域命令校验版本；可逆修改按会话授权 |
| 生成 | estimate_generation、submit_generation、query_generation | 必须经过模型能力、预算和审批模块 |
| 成片 | propose_timeline、render_timeline | 先校验素材齐备、渲染范围与磁盘预算 |
| 维护 | cancel_task、save_asset、summarize_project | 取消是请求；不能擅自物理删除素材或读取密钥 |

Agent 不获得任意 Shell、任意文件路径、数据库 SQL 或自由网络请求工具。Skill 内容和导入素材是输入数据，不能自行扩大工具权限。用户可编辑系统指令，但能力边界由引擎执行，不靠提示词约束。

### 12.3 审批与自动模式

审批卡应展示：将修改哪些内容、创建多少生成任务、使用哪些模型、输入会发送给哪些连接、估算费用/未知项以及可取消程度。批准只对这份提案有效。

自动模式是限定授权：允许哪些工具、模型和资产范围，本次任务数/预算/时限多少。默认不自动删资产、不发布分享、不切换供应商。耗尽预算、出现冲突、结果未知或连续失败即停下来等待处理。

界面“停止 Agent”应立刻停止新增工具和生成提交；已经接单的任务默认继续并列出，可另行请求取消。停止本地流式显示不等于停止服务器工作。退出桌面或关闭对话也不构成远程取消。

停止命令持久关闭该 run 的新增 dispatch gate；已在关闭前授权派发的请求如实显示已派发。继续运行是显式操作，重新检查审批期限、输入版本与预算，不能把重启当成无限恢复自动执行的授权。

### 12.4 上下文与 Skill

上下文按需读取选中节点、相关实体、镜头摘要和近期任务结果，不把全部视频字节和整个项目对话都塞给模型。图片用受控预览，视频只发送模型支持的输入或选定帧；截帧/转写作为独立可追踪步骤。

Skill 是本地可版本化的创作模板：名称、说明、输入/输出 schema、提示词、步骤、允许工具、默认 Profile 和预算建议。首批建议：短片分镜、产品广告、角色设定、图生视频、镜头续写、字幕配音。导入 Skill 默认不执行；模板升级不改变正在运行的会话。

保留用户可理解的计划、工具参数摘要、审批和输出，不要求模型暴露隐藏思维过程。对话长期历史保存在数据库，压缩摘要带来源消息范围，支持回看原文。

### 12.5 事件与恢复

事件统一包含 `eventId`、`scopeId`、`runId`、单调递增 `seq`、`type`、`schemaVersion`、`occurredAt`、`payload`。类型覆盖文本增量、工具开始/进度/结果、审批、任务更新、画布提交和运行终态。

远程传输使用可恢复 SSE；本机 IPC 使用同样事件结构。客户端以 seq 去重和续订，发现缺口获取快照；重放事件不再次执行工具。事件日志保留策略与长期消息分开，游标过期返回明确的重新同步响应。

seq 在明确的 libraryId/streamId 范围递增；领域状态与事件在同一事务提交，快照带 snapshotSeq，订阅只接收之后的事件。流式文字可批量落盘，但 durableSeq 与仅显示的片段分开。Webhook 验签后先写持久 inbox 再 ACK，统一处理重复与乱序。供应商 COMPLETED 可能只是处理结束，适配器必须检查错误字段，不能直接映射为成功。

## 13. 剧本、分镜与角色连续性

结构化层级为 Project → ScriptRevision → Scene → ShotRevision。镜头记录时长、景别、镜头运动、主体、场景、动作、台词、音效、画幅、提示词、实体版本、图像/视频产物和制作状态。

镜头表是内容事实源，画布是其一种视图。画布镜头节点存 shotId 与必要展示缓存；编辑镜头字段统一提交 Shot 命令，不在两处各存一份正文。时间线只引用已经选择的产物版本。

从剧本生成镜头先形成新 revision 草稿，支持接受部分镜头。重新生成单镜头不会覆盖其他镜头；改变角色设定会提示受影响镜头，由你选择重做范围。长篇项目可建立角色设定与已发生事实，但这是 C 阶段能力，不靠无限扩大提示词实现。

## 14. 时间线与媒体导出

### 14.1 B 阶段支持的范围

一条主视频轨、两条音频轨和一条字幕轨；支持顺序编排、剪切、分割、片段内裁切、画面适配/裁剪、基础音量、静音、固定文字字幕和封面。静态图片可以指定持续时间。变速、叠加画中画、复杂转场、关键帧与 HTML 特效进入后续阶段。

时间使用整数 tick 和明确 timebase；输出 fps 用有理数表达，不用浮点秒不断累加。片段引用 assetVersionId，记录素材入点、时间线起点、长度、变换和音量。缺帧、素材丢失、音频采样率和旋转信息在渲染前预检。

所有时间区间为左闭右开 `[start,end)`，帧/采样边界使用同一舍入规则。源视频保留时间基与 PTS；VFR 输入保存可靠的代理映射或生成规范化中间媒体，不以平均 fps 推算帧位置。首版验证固定帧率清单后启用，字体、字幕样式和色彩策略也随时间线版本固定。

### 14.2 预览与渲染一致性

编辑预览使用低分辨率代理文件与共享时间线模型；正式导出把 TimelineRevision 编译成固定的渲染描述，引用固定原始素材、字体、输出配置和渲染器版本。浏览器预览与 FFmpeg 不能天然逐像素一致，因此为支持的效果逐项制定样片和差异容限；复杂效果未通过前不进入“可导出”菜单。

提供快速编辑预览和导出校验预览：后者用相同 RenderPlan 与渲染引擎生成低分辨率样片，确认剪切、音画和字幕。已排队渲染固定 revision，不受随后编辑或镜头新产物影响。验收检查每个剪切边界及中文字体，而非只检查总时长；缺少字体或不支持效果应阻止导出。

B 阶段默认 MP4/H.264/AAC、1080p、项目固定帧率，另支持原始素材包、WAV、SRT 和镜头 CSV。编码器是否可用以随发行版验证的 FFmpeg 构建为准。导出水印默认无；自定义片头/标识作为用户内容。

### 14.3 渲染任务

渲染也是持久任务：预检容量与素材 → 建立独立临时目录 → 参数数组启动 FFmpeg → 记录进度 → 校验输出可解码与时长 → 原子收存 → 挂接导出版本。失败重试只重跑渲染，不重新调用图像/视频模型。

媒体 Worker 只读取获准暂存的本地文件，禁用不需要的网络协议，不拼接 Shell 命令，不接受任意滤镜字符串。FFmpeg 提供协议白名单配置，本方案据此收紧可访问输入。[FFmpeg 协议说明](https://ffmpeg.org/ffmpeg-protocols.html)

## 15. 数据模型与必须成立的约束

以下是逻辑表设计，字段和索引在实现计划中展开。SQLite 以版本化迁移维护，启用外键；媒体二进制不存进数据库。核心关系使用外键和唯一约束，扩展参数使用带 schemaVersion 的 JSON。

| 表组 | 关键表与字段 | 主要约束 |
| --- | --- | --- |
| 实例与身份 | library(id, schemaVersion)、owner、remote_session | 每个资料库独立 libraryId；远端会话可撤销 |
| 项目 | project、canvas(projectId, revision)、folder | 项目与画布身份独立；父关系不得成环 |
| 图 | canvas_node(incarnation, semanticRevision, layoutRevision)、canvas_edge(ports)、run_binding、output_selection、canvas_command、canvas_event | 同画布关联；命令去重；语义/布局/输出选择分开版本化 |
| 资产 | blob_object、asset、asset_version、version_reference、object_pin、storage_reservation、tag、asset_tag | 对象不可变；版本唯一；引用、pin 与回收认领互斥 |
| 实体 | entity、entity_revision、entity_reference、provider_resource_binding | 外部资源绑定包含 connectionRevision 和过期/审核状态 |
| 模型 | provider_connection、connection_revision、credential_ref、model_definition、model_profile | 密钥与业务配置隔离；历史配置不可覆盖 |
| 工作流 | execution_plan、workflow_run、step_run、input_snapshot | 运行固定图和输入版本；下游依赖显式 |
| 生成 | generation_task、task_attempt、scheduler_job、task_lease、artifact | attempt 与 providerTaskId 关联；队列不是唯一业务记录 |
| 费用 | price_revision、budget、reservation、usage_entry | 预算预留原子；币种/精度显式；未知金额非零值 |
| Agent | conversation、message、agent_run、run_checkpoint、tool_invocation、approval | toolCallId 幂等；审批绑定具体提案 hash 与期限 |
| 创作 | script_revision、scene、shot_revision、timeline_revision、render_job | 镜头、时间线引用固定素材版本 |
| 运维 | import_job、export_job、backup_manifest、migration_log、audit_event | 长任务有恢复状态；日志有容量与保留期 |

核心索引围绕项目更新时间、任务状态/下次查询时间、产物来源任务、资产标签、引用目标、会话消息序号和事件游标建立。索引必须根据实际查询验证，不先铺满所有字段。

SQLite 单引擎写入不等于只能同时进行一个生成任务：引擎用短事务管理状态，网络请求与媒体处理在事务外并发。调度领取用原子状态更新、租约到期和递增 fencing token；不复制 PostgreSQL 的 SKIP LOCKED 写法。每个资料库只允许一个活跃引擎进程，双启动被实例锁与数据库 ownership 检查拒绝。

## 16. 命令、API 与双模式连接协议

桌面 UI 只依赖 `WorkspaceConnection`：查询、提交命令、订阅事件、导入/读取媒体。LocalConnection 与 RemoteConnection 实现同一语义，不要求每个 IPC 调用恰好对应一个 HTTP 路由。

| 操作 | 远端 API 草案 | 本机等价命令 |
| --- | --- | --- |
| 能力协商 | GET /v1/instance | instance.describe |
| 项目列表/创建 | GET /v1/projects、POST /v1/projects | project.list / create |
| 画布快照/修改 | GET /v1/canvases/:id、POST /v1/canvases/:id/commands | canvas.read / command |
| 导入上传 | POST /v1/imports、分块上传、POST finalize | asset.importGrantedFiles |
| 资产/版本 | GET /v1/assets、GET /v1/assets/:id/versions | asset.search / versions |
| 模型连接 | /v1/connections、/v1/models、/v1/profiles | provider/model/profile 命令 |
| 生成估价/提交 | POST /v1/generation/estimate、POST /v1/tasks | generation.estimate / submit |
| 查询/取消 | GET /v1/tasks/:id、POST /v1/tasks/:id/cancel | task.read / requestCancel |
| Agent | /v1/conversations、POST /v1/agent-runs | agent.start / message |
| 审批 | POST /v1/approvals/:id/decision | approval.decide |
| 时间线导出 | POST /v1/render-jobs | timeline.render |
| 事件续订 | GET /v1/events?scope=…&after=… | events.subscribe |

每次连接握手返回 `instanceId/libraryId`、协议 major/minor、能力和格式版本范围。不兼容时阻止写入并说明需升级哪一端；兼容范围内忽略已定义的可选字段，未知命令拒绝。

命令通用信封示例：

```json
{
  "schemaVersion": 1,
  "libraryId": "LIBRARY_ID",
  "commandId": "UUID",
  "kind": "canvas.applyPatch",
  "targetId": "CANVAS_ID",
  "expectedRevision": 42,
  "payload": {"operations": []}
}
```

身份和权限来自已认证连接，不信任 payload 自报的 ownerId。错误采用稳定错误码、可行动信息和相关字段：`CAPABILITY_UNSUPPORTED`、`INPUT_MISSING`、`REVISION_CONFLICT`、`BUDGET_REQUIRED`、`SUBMISSION_UNKNOWN`、`SOURCE_EXPIRED`、`STORAGE_FULL`、`PROTOCOL_INCOMPATIBLE` 等；原始供应商错误保留为经过凭据脱敏的诊断。

切换连接增加客户端 connectionEpoch。旧连接响应不能写入当前视图或新资料库，但仍可由原 libraryId 的 outbox 处理器归档 ACK；不能一律丢弃导致旧命令永远未确认。缓存、草稿、事件游标与媒体播放都按 libraryId 分区。本机与远程不会自动合并同名项目，切换连接也不取消旧引擎任务。

## 17. Electron 桌面工程

### 17.1 进程职责

| 进程 | 拥有的职责 | 不应承担的职责 |
| --- | --- | --- |
| Renderer | 画布、表单、预览、交互、短期 UI 状态 | 直接读写数据库、保存 API Key、任意文件操作、执行 Shell |
| Preload | 暴露白名单命名 API，校验可序列化数据 | 暴露完整 ipcRenderer、fs、process 或动态频道 |
| Main | 窗口/托盘、系统文件对话框、授权句柄、凭据代理、连接生命周期、更新 | 高负载渲染、长时间同步 I/O、业务任务状态机 |
| Engine utility process | 数据库、领域服务、Agent、调度、模型连接 | 操作 UI；把原始远程 HTML 交给高权限页面执行 |
| Media/任务 Worker | 特定任务的计算/网络工作、受控临时文件 | 自行决定任务最终归属或绕过引擎修改数据库 |

Electron 官方 utilityProcess 提供 Node 子进程与 MessagePort，适合隔离引擎；应用仍需管理进程身份、握手、退出和恢复。[utilityProcess 文档](https://www.electronjs.org/docs/latest/api/utility-process)

### 17.2 资源访问

Renderer 加载随安装包发布的本地 UI，不直接加载远程网站作为高权限主界面。`contextIsolation` 和 sandbox 开启，`nodeIntegration` 关闭；IPC 校验发送窗口、frame、命令和参数。外部链接由主进程验证协议后交给系统浏览器。Markdown、字幕和模型输出不能执行 HTML/脚本。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

文件导入由系统对话框或受控拖放产生短期授权句柄。Renderer 传句柄而非任意绝对路径。引擎打开文件时重新检查允许根目录、真实路径/链接和类型；导出由系统保存对话框授予目的地。媒体预览走 `app-media://` 这类私有资源协议及受控资源 ID，支持 Range，不允许 URL 直接拼成本地路径。

文件 grant 绑定导入 ID、目标 libraryId 与期限；向服务器 A 上传时切换到 B，不会把剩余文件块发送给 B。远端只收到上传字节和受控元数据，不把本机绝对路径当作可访问资源。Renderer 重载需恢复原导入身份并重验授权。

本机 IPC 为默认，不启动一个对任意网页开放的 HTTP 服务。若某个库确实要求本机 HTTP，必须仅绑定 loopback、使用随机端口和会话认证，并纳入 origin/CSRF 验证。

### 17.3 关闭、退出、睡眠与恢复

- **关闭窗口**：有本机活动任务时提供“留在托盘继续 / 完全退出”，用户可记住偏好。托盘明确显示运行状态。
- **完全退出**：停止领取新任务、落盘 checkpoint 和租约信息、终止由应用拥有的本地子进程并等待有界清理；云端已接任务不假定被取消。
- **强制结束或崩溃**：下次启动扫描未终结任务、租约和已保存 providerTaskId，进入对账恢复；不按“上次未完成”直接重发。
- **系统睡眠**：本机计算暂停，租约时间/连接可能失效；唤醒重新握手和对账。只有主动启用“渲染期间保持唤醒”时才阻止睡眠。
- **远程模式**：桌面完全退出也不影响服务器任务；重连后继续显示进度。本机文件尚未上传完毕的任务不能启动远程生成。
- **取消**：单独的任务命令。关闭窗口、退出 UI、断开连接、停止 Agent 都不是通用取消信号。

首版不安装长期系统服务，不在用户完全退出后偷偷运行本机引擎。需要无人值守任务时使用托盘运行或远程服务器。

每个 run 固定 executionOwner（资料库与引擎实例），UI 切换连接不转移所有权。本机云任务在退出后可能由供应商继续，但本机 Agent 的后续规划、工具串联和收存会暂停；只有远端引擎拥有的 run 才能在桌面退出后继续整条流程。重新启动优先恢复原所有者上下文，不自动迁到当前选中的连接。

### 17.4 打包、升级与系统兼容

Windows x64 首发安装包，打包 Electron 运行时、前端、引擎、匹配 ABI 的 SQLite 驱动、媒体二进制、必要字体与许可证；用户不需单独安装 Node.js、Python 或数据库。FFmpeg 与 SQLite 原生组件在 CI 中对目标平台验证，不能只在开发机上运行。

Electron 的原生 Node 模块可能需要按 Electron ABI 重新编译；每次 Electron 升级都重跑原生模块与安装包启动测试。[原生模块文档](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)

初期支持手动安装更新；自动更新使用受信任 HTTPS 源、签名校验和版本通道，显示更新内容并等待安全时机重启。安装新版本前完成数据快照；数据库迁移失败保留原库与日志，恢复旧程序必须配套兼容数据备份，不宣称所有 schema 都能逆向迁移。打包与更新采用稳定版能力。[electron-builder 稳定版文档](https://www.electron.build/v26/)

Windows 正式分发需规划代码签名；macOS 后续包含签名、公证、Keychain 与架构测试。个人未签名测试包明确标识，不将系统“无警告安装”当作已满足。安装包名称、图标和产品名在视觉阶段确定。

## 18. 密钥、数据权限与网络边界

### 18.1 密钥归属

本机 API Key 使用操作系统保护的凭据存储，由主进程代理按连接获取，必要时短暂传给执行引擎；不通过 renderer、日志或项目文件流转。可采用 Electron safeStorage 对凭据封套加密，但它不能抵御已能读取同一登录账户数据的恶意程序。安全存储不可用时提示用户修复或选择仅本次会话保存，不能静默降级为明文。[safeStorage 平台语义](https://www.electronjs.org/docs/latest/api/safe-storage)

远端 API Key 保存在远端引擎，由独立的主密钥加密；主密钥从环境/secret 文件注入，不能和密文数据库一起当作普通项目导出。桌面只保存远端登录令牌。连接远端意味着使用那台服务器配置的模型连接，本机 Key 不自动上传。

修改或删除凭据对运行任务的影响要明确：默认保留被运行任务引用的旧凭据版本到任务终结；紧急撤销立即阻止继续使用，并把需要查询的任务标记待处理。备份恢复后的操作系统凭据可能不可解密，迁移向导要求重新配置，不承诺密文跨电脑可用。

### 18.2 远端访问与外发

远程实例默认单所有者、TLS、短期访问凭据和可撤销会话；初始化一次性口令通过部署终端获取，完成后失效。服务器 API 不因是“自用”而裸露无认证接口。

普通外链下载器禁止访问 loopback、链路本地、云 metadata 和未授权私网，逐次重定向重做校验。模型连接可明确批准某个本机/私网服务，但授权限定为精确主机、端口和适配器用途，不授予所有 URL 同等权限。连接校验和实际请求都检查解析结果，认证 Header 不带到跨域跳转。

远程引擎配置的 `localhost` 指服务器本身，不是你的电脑。远端要调用你电脑上的模型，需要你明确配置受控网络连接；默认不自动开端口或建立公网隧道。

### 18.3 内容、插件与隐私

项目导入、Skill、模型输出和网页文本都不能改变工具权限。将来支持 MCP 时，只通过单独的工具注册层暴露明确项目范围；默认无 Shell、任意文件或全局密钥能力。

默认无遥测上传。诊断包由你主动导出，去除密钥、认证头、会话令牌和临时签名 URL；提示词和素材信息可作为项目内容保存，但诊断分享前可预览并选择排除。日志保留供应商错误的必要字段，不把完整 HTTP 请求头落盘。

## 19. 部署、资料库与备份

### 19.1 本机模式

安装 → 选择资料库目录 → 添加模型 → 测试 → 创建项目。程序目录与用户数据目录分开，升级和卸载默认不删除资料库。建议支持将大素材目录放到空间充足的磁盘；更换目录通过暂停任务、复制校验、切换索引完成，不能直接更改字符串留下失效路径。

资料库包含数据库、objects、previews、temp、exports、backups 和受限日志目录。缓存可重建，原件与数据库必须保留。数据库必须在本地磁盘；可以向 NAS 备份导出包，不把运行中的 SQLite 文件放入同步盘供多端同时打开。

### 19.2 远端个人版

Docker Compose 运行一个引擎实例，挂载数据库与素材持久卷；按需加 HTTPS 反向代理或选择已有入口。媒体 Worker 与引擎同机，SQLite 不跨主机共享。连接对象存储时只迁移 BlobStore，数据库仍保存在本地持久盘。

桌面远程模式能浏览项目、上传素材、编辑画布、发起 Agent、查看任务和下载成片。服务器不需要显卡即可调云端模型和执行 CPU 媒体处理；自托管模型的硬件要求另按实际模型测算。Compose 用于管理远端服务、网络和卷，不是本机客户端前置条件。[Docker Compose 文档](https://docs.docker.com/compose/)

### 19.3 备份与恢复

默认建议每日备份数据库与新增原始对象、每周做恢复抽查；保留周期和磁盘上限可配置。备份建立一致的数据库快照和引用对象清单，备份期间延迟回收清单中的对象，再按 hash 校验。不能只复制一个正在写入的 `.db` 文件而漏掉 WAL 状态。

SQLite 提供在线备份 API；本产品使用受支持的快照方式生成数据库备份。[SQLite Backup API](https://sqlite.org/backup.html)

恢复先到新目录，校验 schema、引用、对象 hash 和凭据可用性，成功后再切换。恢复出来的运行任务全部先进入对账状态，禁止自动重发。备份、恢复、升级和 GC 共用维护锁，避免相互破坏。

完整恢复保留 libraryId，但产生新的引擎启动身份，默认禁止自动调度。恢复向导明确选择“旧实例停用后的接管”或“作为独立新资料库导入”；接管前原实例必须已停止，并更新执行所有者代次。本地文件锁不是跨机器唯一所有权证明。无法确认停用时只读/调度禁用，不能让两份库同时调度同一批供应商作业。项目迁移与完整恢复使用不同包类型和界面。

项目交换包用于跨资料库迁移，完整备份用于实例恢复。第一版不做离线多端自动同步：需要时导出/导入或迁移选定项目，并明确显示源、目标与占用空间。

## 20. 可观测性与资源控制

界面内提供“诊断与存储”页：应用/引擎/协议版本、资料库位置、磁盘余量、队列、失败原因、各模型耗时和费用状态、最近备份与恢复结果。错误可复制诊断 ID，详情能关联任务、attempt、工具调用和素材。

默认建议本机同时 2 个云生成任务、1 个媒体渲染任务；各连接另设上限，LLM/媒体队列互不堵塞。具体默认值根据首轮样机测量调整。队列数量、事件保留、文件下载、解码像素、压缩包展开与临时目录都设容量上限。

监测输入/输出 token、已报告费用、估价偏差、submit/query/collect 时延、失败/未知率、恢复成功率、磁盘与 CPU/内存。敏感信息不用于日志标签；使用任务 ID 关联。

## 21. 验收与测试矩阵

以下都是拟定验收标准，并非已经跑出的结果。开发时固定模型、素材、系统和网络条件，记录实际测试。

| 场景 | 通过标准 |
| --- | --- |
| 干净 Windows 安装 | 无 Node/Python/数据库环境也能启动、创建项目、导入和预览素材 |
| 模型配置 | 保存后重启可用；手工模型 ID 可用；不支持能力在提交前明确拒绝 |
| 图像闭环 | 提示词+参考图 → 实际 API → 持久素材 → 画布显示 → 资产复用 |
| 异步视频 | 已提交任务在刷新 UI/重启引擎后查询原 providerTaskId，不重复发起 |
| 未知提交 | 模拟供应商接单后断线，显示待对账；非幂等接口无自动重发 |
| 收存失败 | 保留供应商完成事实、元数据和费用；可重新取得时只重试收存，不重复生成；临时结果已失效且无重取能力时明确 OUTPUT_UNRECOVERABLE |
| 画布冲突 | 人和 Agent 同改节点，无静默覆盖；冲突可检查、重新应用 |
| 迟到结果 | 节点被删/变更或切换资料库后，旧结果只归原任务历史 |
| 重复生成选择 | A→B→A、同参数连续生成、人工选回旧结果后，迟到任务不抢占当前输出 |
| ACK 与切库 | 引擎已提交但切库前未收到 ACK，重发不产生第二次修改，旧 ACK 只结清旧库 outbox |
| 审批与预算 | 改模型/数量/输入导致授权失效；并发预留不越界；未知费用不算免费 |
| Agent 恢复 | checkpoint 后进程崩溃，已完成工具不再次执行，未决付费调用先对账 |
| 工具断流 | 工具参数任意位置断流不执行半条调用；重复 action 不重复提交模型 |
| 停止与退出 | 停 Agent 不再产生新任务；关闭/退出/取消语义与界面一致 |
| 文件与 IPC | 非授权路径、路径穿越、非法 sender、任意 IPC 频道和脚本输出被拒绝 |
| 远程模式 | 断连后恢复事件，上传完成前不执行；本机Key不自动送远端 |
| 迁移备份 | 全新目录恢复可打开项目，素材 hash 对齐；运行任务不自动重发 |
| 恢复所有权 | 同一备份在两台机器恢复时默认调度禁用，明确接管后才继续后续付费步骤 |
| 引用与导入 | GC 与新增引用不竞态误删；同包重试不重复建项目；导入后不控制源作业 |
| 基础成片 | 3–5 镜头含音轨字幕可导出；片段顺序、裁切、时长与字幕对齐 |
| 升级 | 旧库备份后迁移可用；中断迁移有恢复路径；原生模块加载成功 |

测试分层：纯领域状态机与契约 → 真实 SQLite/文件系统/进程故障注入 → Electron 安装包 E2E → 少量真实供应商冒烟。Mock 用于稳定复现重复通知、断网和时序，但不能证明某供应商真实可用。真实付费测试使用你明确配置的模型和预算，记录测试日期、输入和结果。

### 21.1 性能目标

先以 Windows x64、16 GB 内存、SSD、1440×900 窗口作为建议基线，记录实际 CPU/GPU 与 DPI；没有测量前不宣称达到以下数字。

- 应用暖启动进入可操作项目列表目标 5 秒内；冷启动、升级迁移单独统计。
- 500 节点、750 边、10% 图片缩略图的样例画布，拖动目标持续 45 FPS 以上；按操作记录卡顿和 p95 输入响应，目标 100 ms 内。
- 本机非媒体命令 ACK 目标 p95 200 ms 内；远程额外报告 RTT，不混作引擎耗时。
- 1,000 节点大图作为压力场景，至少能打开、保存、定位并保持可恢复；不承诺无限规模。
- 1080p、30 秒、5 镜头基准成片，检查输出时长误差不超过 1 帧、无累积音画漂移；字幕与音轨设置固定容限。
- 同一场景报告峰值进程族内存、CPU 时间、磁盘临时占用、总耗时；视频生成时长由供应商决定，单独统计。

## 22. 开发顺序与里程碑

每个里程碑交付可运行增量。下面是设计层工作分解；设计确认后再形成具体文件、接口实现和测试命令级实施计划。

| 里程碑 | 工作与交付 | 退出条件 | 粗估人日 |
| --- | --- | --- | --- |
| M0 风险验证 | 定模型契约；验证 SQLite/Electron 打包；试一个图像和一个异步视频 API；导出样片 | 原生组件、真实 API 和媒体链路无未解释阻断 | 3–5 |
| M1 桌面底座 | main/preload/renderer、内置引擎、资料库、凭据、安装包、连接抽象 | 干净机器安装可用，UI 重载不丢已保存数据 | 7–10 |
| M2 资产与画布 | 资产版本、文件导入、基本节点/连线、命令保存、撤销和恢复 | 上传/引用/保存/重开闭环，旧版本可追溯 | 8–12 |
| M3 模型与可靠生成 | 配置中心、文本/图像/视频适配器、持久调度、预算、产物、对账 | 手工创作 A 阶段可用；崩溃/未知提交不会盲重发 | 8–12 |
| M4 Agent 与分镜 | 会话、工具、审批、Skill、实体、剧本/镜头、差异应用 | Agent 生成可审阅计划，批准后完成多个镜头任务 | 9–14 |
| M5 音视频成片 | TTS/ASR 或音轨导入、基础时间线、字幕、渲染/导出 | 完成 B 阶段 3–5 镜头成片验收 | 8–12 |
| M6 远端与发行强化 | 远端部署、完整连接验证、迁移备份、升级、故障矩阵、性能修正 | 本机/远程两种模式均验收，恢复演练通过 | 7–10 |

远端协议和 connectionEpoch 从 M1 就建立；M6 完成实际部署和全链路验证，避免最后才发现本机路径和密钥写死。安全、诊断和必要测试随各模块完成，不全部拖到 M6。

总基线约 **50–75 人日**；为外部 API 差异、桌面打包、媒体兼容预留 20%–30%，约 **60–98 人日**。以一名熟悉该技术栈的开发者全职投入估算约 12–20 周，属于范围估算，不是交付承诺。AI 辅助可以加快部分实现，但不能替代真实 API、安装包和恢复验证。具体模型接入数量、视觉精度与高级节点会改变规模。

能并行的工作是模型适配器、资产模块、画布组件和媒体样片；身份、命令、版本、任务与审批契约先确定，否则并行会增加返工。原站完整高级功能分期追加，不塞进这一首版工期。

## 23. 成本、容量与范围控制

成本主要是模型调用、素材存储/备份、服务器（可选）、代码签名/发行（如需）和开发维护。没有具体模型及用量前不写固定月费，也不把模型价格锁死在程序里。

计算方式：文本输入/输出 token × 对应单价 + 图像任务数量 × 参数对应单价 + 视频计费时长/任务 × 单价 + 音频用量 + 重试实际发生费用 + 存储/流量。时间线渲染还消耗本机或服务器 CPU/GPU，但不应重复计成模型费用。

设置页显示本月已核实费用、估算费用、待核实占用三项。建立项目时可选择总预算；为试错保留预算而非一次耗尽。供应商费率变化创建新版本，历史结果仍显示当时规则。

本机不要求显卡即可使用云模型；本地大模型/ComfyUI 的显存、磁盘与模型下载由实际工作流决定，不包含在“安装即用”的基础包。基础包包含工作台和引擎，不捆绑数十 GB 模型权重或代替用户安装模型服务。

## 24. 主要风险与控制办法

| 风险 | 影响 | 设计控制 / 验证时点 |
| --- | --- | --- |
| 把“兼容 API”当成全功能兼容 | 工具、图像或视频执行失败 | 能力矩阵 + 每个实际连接的契约测试，M0/M3 |
| 提交结果未知后自动重试 | 重复生成、重复费用 | attempt、幂等/对账、未知状态，M3 |
| Agent 与用户同时改图 | 覆盖内容、错误结果挂接 | revision、patch 前置条件、显式冲突，M2/M4 |
| 供应商临时 URL 过期 | 生成成功但作品丢失 | 优先收存原件，持久化收存任务，M3 |
| Electron 权限过宽 | 素材/模型内容获得本机权限 | 隔离 renderer、窄 IPC、授权句柄，M1 持续验证 |
| 本机睡眠/崩溃 | 任务卡死或重复发起 | checkpoint、租约、恢复对账，M3/M6 |
| 桌面原生依赖 ABI | 开发环境可用但安装包失败 | 真实安装包、干净 Windows 环境，M0/M1 |
| 剪辑预览与导出不同 | 成片不可信 | 限定效果集、共享时间模型、固定样片，M5 |
| 参数/schema 升级 | 老项目打不开或行为变了 | schemaVersion、迁移器、不可变运行快照 |
| 本地与远端混淆 | 发错素材、读错项目或配置 | 可见连接标识、libraryId、connectionEpoch、显式迁移 |
| 一次追求全部高级功能 | 长期无法交付 | A/B/C 分期，每期闭环验收 |
