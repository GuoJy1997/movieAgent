# P3 创作 Agent、剧本分镜与项目实体

用户已明确要求开始执行 P3。依据既有完整产品设计第 12–13 节及交付路线图，不重复请求已经给出的范围批准。基线 ec0813b；沿用 Electron/React/TypeScript、本机 utility 引擎、SQLite 和 P2 执行器。

## 交付目标

在短剧项目内选择已有文本模型，通过对话提出创作需求，得到可编辑、可部分采用的剧本/角色/场景/镜头提案；批准后保存为不可变修订，再把所选镜头变成画布生成节点，经一次执行计划批准运行图像/视频任务。结果保留固定版本并关联镜头。停止、重开、重复点击和人工并发修改都不能导致重复副作用或静默覆盖。

同时支持完全手工维护剧本、场景、镜头与实体。所有功能有正式页面与实际后端，不使用样板假数据。

## 实现方式与范围

选择一个持久化主 Agent，复用 P2 文本生成任务作为每轮规划请求，以严格 JSON 提案作为受控工具参数协议。每次用户发送消息只产生一个经过预算批准的文本请求，不建立自动递归的模型思考循环。批准提案后的确定性操作、批量镜头生成由引擎与 P2 工作流执行。会话支持继续追问、查看原始历史、失败后明确发起新一轮。

这比另建供应商 SDK 工具循环更能复用当前 OpenAI/Anthropic 适配和未知提交保护；原生 tool_calls、多模型自主协商及流式输出不作为 P3 依赖，也不伪装这些能力。严格结构化提案无论来自模型、模板或导入内容都不能扩大允许的动作。

三种模式：全能创作、剧本创编、导演分镜。内置版本化模板：短片分镜、产品广告、角色设定、镜头续写。每个模板有 ID/revision、说明、输入/输出约束、提示词、允许提案类型及建议任务/预算范围。版本在每轮准备时冻结。P4 的配音/字幕/时间线模板不提前提供可执行入口。

不扩展音频/TTS/时间线/成片导出、远程服务器、任意网络/Shell/SQL工具、模型训练或无限自动 Agent。短剧项目资料的 JSON/Markdown 导出属于 P3，MP4 成片属于 P4。

## 内容模型与编辑

- 统一放在当前项目所属资料库内，按 projectId 隔离。SQLite 是可编辑事实源，导出文件是明确版本的快照，不能形成第二份会自动覆盖数据库的事实源。
- EntityRevision：角色/场景/道具/风格，ID、项目、修订、名称、描述、约束、固定素材引用。名称最多 200 字符，描述/约束分别最多 8000 字符，参考素材最多 4 个；引用必须是本资料库可用的固定版本。更改实体不自动改写已经引用旧实体修订的镜头。
- ScriptRevision：ID、项目、修订、标题、梗概、正文、场景清单。标题最多 200、梗概 4000、正文 64000 字符；最多 32 场景，场景具有稳定 ID、标题、地点、时间和描述。每个保存调用携带 expectedRevision；新对象为 0。
- ShotRevision：ID、项目、所属 scriptId、sceneId、修订、排序、标题、时长、景别、运镜、主体、动作、台词、音效描述、画幅、生成提示词、固定实体修订。最多 64 镜头/剧本；时长整数 1–120 秒，画幅 16:9/9:16/1:1/4:3；标题 200、提示词 8000，其余文本字段各 2000 字符；实体引用最多 8 个。整体命令/提案 JSON 另设 256 KiB 字节上限。
- 镜头选中的图像/视频输出单独有选择版本，与正文修订分开；自动完成不能覆盖之后的人工选择。输出/生成历史引用固定 MediaReference，原件沿用资产系统。
- 查询可读当前版本与历史；所有写入使用现有命令回执、事务及事件。不同项目/资料库、无效场景/实体、旧 expectedRevision 均拒绝。修改场景清单不能使现有镜头悬空；需要保留被引用场景或明确先调整镜头。
- 页面显示引用实体有新修订的提示，由用户决定是否更新镜头引用及重新生成；不把全部镜头无声换成最新设定。重做单镜头不会改写相邻镜头。

## Agent 会话、提案与审批

每轮持久化 session/run/user message/context manifest/template revision/PreparedGeneration/task reference/parsed proposal/stop gate/action receipts。保存的是可理解的上下文摘要、动作和结果，不保存或显示模型隐藏思考。

准备轮次时读取当前项目、指定剧本/镜头/实体、相关资产和画布摘要、最近对话；可显式选择最多 8 个固定资产引用。选中的 TXT/MD 文本原件经现有资产读取边界校验后按上下文预算提取文字，图片/视频仅提供元数据，不能假称模型已看过画面。仅发送文本摘要与固定引用标识，不发送密钥、任意文件、视频原件或整个资料库。请求仍受 P2 的 16000 字符 prompt 上限约束；按确定优先级限制上下文，保留输出 schema、用户需求和版本清单，并告知用户省略了哪些范围。禁止截断 JSON 结构。

规划请求展示文本模型、上下文范围、输出预算、费用未知提示。Agent 页面提供显式输出 token 预算（1–8192，建议 4096），可沿用所选 Profile 或由用户指定；指定值形成项目内不可变派生 Profile，不修改软件全局配置。批准卡显示实际冻结值，不自动扩容或重试，以免普通短文本默认预算不足导致分镜 JSON 截断。通过现有 generation.prepare/approve 费用语义准备和提交，新的 agent.prepareTurn/approveTurn 也必须进入软件模型配置 ensureCurrent 屏障。既有配置连接不自动成为新的付费授权。测试开发不得调用用户真实服务。

模型输出必须完整解析为一个 schemaVersion=1 的 JSON 提案；允许单个完整 json 代码块包裹，不允许从任意散文中猜取 JSON。提案包含 reply、可选剧本草稿、实体草稿数组、镜头草稿数组。草稿使用受限本地 key 相互引用；新对象 ID 由引擎稳定分配。已有目标由准备时用户选择和捕获的版本确定，不接受模型指定跨项目目标、任意 revision、命令名、路径、模型或预算。回复文本最多 8000 字符，提案最多 32 个镜头/32 个实体，总字节最多 256 KiB。无提案的正常文字回复是合法结束状态。

校验失败、响应截断、任务失败或未知提交明确显示原因、保留任务/会话记录，不自动重试模型。用户再次发送才是新的计费轮次。规划完成仅生成提案，不直接修改剧本、实体、镜头或画布。

采用提案前显示将新增/更新的剧本、实体和镜头以及版本差异；支持选择部分镜头，自动列出这些镜头必需的场景/实体依赖。批准绑定持久化 proposalHash、runId、项目和基准对象版本，10 分钟有效。修改提案/选择产生新的明确批准范围，不沿用过期计划。采用在单个命令事务内完成并记录稳定 actionId；重复调用返回原结果，不重复创建对象。只检查本次修改及引用所需的版本，其他无关对象变更不必使提案失败。发生人工冲突保留草稿并要求重读/新提案，不覆盖。

停止先持久化关闭 run 的修改与派发门，再停止其尚未提交任务/后续动作。已受理请求可能继续；其结果可以收存和查看，但不能因迟到而自动采用或生成新任务。重启只核对已存在的任务及持久化结果，不重新提交规划请求，不自动批准提案。需要重新推理时必须显式发起新轮次。

## 分镜到画布与生成

镜头表是内容事实源。画布生成节点携带 engine-owned shot binding（projectId/scriptId/shotId/shotRevision/role），并存用于本次执行的固定提示词/配置；画布检查器指向镜头编辑入口，不能独立编辑绑定镜头的正文后假称已同步。历史节点保留对应修订，当前镜头已变化时显示过期。

用户选择镜头和图像/视频 Profile，先预览节点数量、引用实体/素材、派发连接和参数，再通过受版本约束的确定性命令布置画布。每批最多 16 个镜头、32 个生成步骤，遵守 P2 100 操作/32步骤/128依赖上限。操作超过上限明确拒绝并提示分批，不能悄悄漏镜头。

图像→视频使用 first_frame 边；没有图像步骤时可以直接按受支持的参考图或纯文本视频生成。实体参考图必须固定版本且符合所选模型能力，不能静默丢弃。MiniMax 时长与首帧 adaptive 等必要参数通过明确展示的项目内不可变派生 Profile 固定；超出模型范围拒绝，不静默裁切时长。首帧视频输出画幅由输入及模型能力决定，预览说明与分镜意图画幅的关系。

布置画布后复用 workflow.prepare/approveAndEnqueue 展示实际执行计划并一次批准所有所选生成步骤。Agent 提案采用本身不授权付费媒体生成。停止关联执行通过 P2 workflow.stop，已接单任务继续查询/收存；不新建另一套调度器。

每个镜头保留生产批次、任务、画布节点和输出固定引用。重启/重复收存只增加一次历史；自动选择结果必须匹配当时镜头修订和选择版本，冲突结果留在历史中供手工选择。生成资产可按 P2 保存/加入画布；产物应能从镜头表直接预览。

## 正式桌面体验与导出

复用当前深色组件风格和布局，不重做品牌/背景/画布动效。新增创作 Agent、剧本分镜、角色场景入口，明确关联当前项目。支持：会话列表/历史、模式/模板/模型选择、上下文选择、规划预算审批、提案差异/部分采用、停止/恢复状态；剧本与场景编辑、镜头表编辑、实体管理/固定参考图、选定镜头生成、结果与历史预览。

字段编辑通过正常表单而非要求用户手写 JSON。状态/错误/冲突/空列表均有可见反馈；不允许成功提示早于真实命令确认。恢复只订阅已有持久状态，不由 React mount 发起付费动作。工具栏与表格需适配 1440×900 及 1100px 窗口，避免用模型生成图片撑视觉。

导出通过受限主进程动作写入当前目录项目的 exports/creation，命名只用已验证对象 ID 与修订；JSON 和 Markdown 两种快照，包含剧本、镜头和实体引用，不含凭据。禁止用户输入任意目标路径、路径穿越、覆盖已有文件或跟随目录符号链接逃出项目；旧版无目录项目明确说明需使用目录项目。导出失败可重试且不修改项目内容。

## 验证与交付边界

迁移依次 schema11 内容修订、schema12 Agent、schema13 镜头生产绑定、schema14 生产收存诊断。诊断使用独立增量迁移，保证早先 schema13 资料库也能升级。schema10 fixture 迁移保留原件 hash 和既有任务/画布/配置；使用当前自动备份及所有权保护，不接触用户正在运行的项目。

重点测试：结构/越界/跨项目/旧版本；模型提案注入与非法动作；截断/无效 JSON；未批准无修改；部分采用依赖；冲突无覆盖；重复回执/重启不重复模型 POST/内容/媒体生成；停止与迟到结果；镜头→图像→视频→固定结果回填；运行期间模型与实体变化；导出目录边界。

每步只运行相关测试与类型检查；最终一次完整核心测试、构建、独立目录 release-p3 打包和针对性 Electron 全链路检查。失败仅重跑受影响部分，不重演 P2 的画布调试循环。所有自动化测试使用显式 fixture/空 --model-config，不读取用户 Key，不发起真实计费请求。保留当前 PID9268 和现有发行目录；完成后提供新启动入口，未经用户关闭不重启其工作台。

P3 完成是本机可用、fixture 验证的创作闭环。真实 Kimi 长剧本结构化输出、实际图像与参考视频整链验收单独报告；已有 Kimi 连通成功不能替代这些证据。
