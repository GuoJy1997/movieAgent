## 本次代为作出的 15 项决策

按原始记录顺序列出；每项说明判断错误时的代价。

1. 在用户指定目录的专用本地分支实施，不另建 worktree。若并行编辑增加，需要重新隔离工作区。
2. 顺序执行各任务并分别审查，不并发修改实现；付费测试需明确配置与额度。代价是额外审查时间，不能据此授权真实调用。
3. 使用经当前 Node/Electron 验证的内置 SQLite。代价是实验 API 升级时需要回归验证。
4. 早期解包运行只作为阶段证据，安装包与干净环境分别验收。代价是阶段通过不能替代后续发行验收。
5. 凭据模块的实际传输与 UI 验证分别由后续任务完成，真实 API 留后。代价是不能提前宣称完整供应商验证。
6. 收存 journal 独立于导入批次，生成与导入共用收存能力。若抽象不合适，需要调整 schema/服务接口。
7. P1 允许最多 32 MiB 的完整媒体字节经受控 IPC 传输，再在 main 处理 Range。代价是内存与延迟开销，不宣称流式读取。
8. 先持久化供应商完成事实和私有输出描述，再收存原件。代价是适配器/收存接口复杂度，私有定位信息必须继续隔离。
9. 模型验证证据使用 SQLite 迁移 0006，画布迁移顺延 0007。代价是迁移版本及测试需要一致调整。
10. 每个项目先提供一个默认画布，canvasId 与 projectId 一致。未来多画布需要增加默认映射并保留已有引用。
11. 资产 DTO 增加可空的来源 artifact 引用，以持久显示是否已加入资产。代价是消费者与校验器需兼容该字段。
12. 产品显示名采用 MovieAgent，保留仓库/appId 和旧数据路径。若改名，需要调整标签与打包元数据，不迁移用户数据。
13. 真实验收入口须在取得资料库独占权后、启用调度前复核空闲任务与 outbox。代价是额外的窄启动策略及测试维护。
14. 草稿按资料库/画布/节点 incarnation 保留，网络响应仍按 epoch 隔离，并保留原字段 CAS。代价是恢复与冲突提示复杂度；禁止静默重基或跨库复制。
15. 对最终审查逐项列出的未验领域维持明确非承诺：真实 API、干净安装、签名/图标、物理故障、完整恢复/远端、后续创作功能、更广预算策略、任意供应商兼容、规模/DPI/吞吐性能、恶意同账户进程防护以及已知警告/诊断残留。代价是更广泛发行前仍需相应开发和验收。
