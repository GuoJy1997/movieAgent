# P3 Creation Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. No nested subagents.

**Goal:** Deliver persisted project entities, editable scripts/shots and an approval-gated creation Agent that connects to real P2 generation and canvas workflows.
**Architecture:** Existing command/query/event boundary, schema-versioned SQLite services, P2 text generation for one structured planning response per user turn, deterministic proposal application and P2 media workflows. No new arbitrary provider/network bridge.
**Tech Stack:** Existing TypeScript, Node24, Electron45, React19, SQLite, Vitest/Playwright.
**Spec:** docs/superpowers/specs/2026-10-26-p3-creation-agent-design.md

## Review Focus

- Model-supplied targets/IDs/versions escape selected project or overwrite manual edits: task2 tests malicious/mismatched targets and CAS rejection with unchanged DB.
- Crash between planning-task completion and proposal publication, or between approval and content write: task2 tests deterministic harvest/replay and atomic content receipts without extra HTTP POST.
- Entity revisions, mirror canvas nodes or late results silently change chosen shot content: task1/3 tests fixed refs, immutable revisions and selection CAS.
- Approvals accidentally authorize model retries or media work: task2/3 tests no writes/submissions before exact approval and stop gates after awaits.
- Draft forms overwrite delayed loaded data or duplicate operations on remount: task4 tests real controls, save/reopen, input changes and mounted UI not making requests.
