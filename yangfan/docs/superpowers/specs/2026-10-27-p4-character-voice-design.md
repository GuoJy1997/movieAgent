# P4 角色声音、对白制作与口型修正设计

日期：2026-10-27。状态：已完成[独立可实施性检查](../../verification/p4-character-voice-builder-check.md)，用户已认可四项组织原则并授权实施；MiniMax 单句 TTS/ASR 已实测通过，H3 声音参考与口型质量尚未实测。本文补充 [P4 音频与时间线设计](2026-10-27-p4-audio-timeline-design.md)，相关冲突以本文为准；运行时、字幕、导出和本机队列仍按原设计执行。

## 1. 用户确认的目标与本次技术选择

用户确认：每个角色保存声音档案；分镜自动带上对应参考声音；先试听不同情绪的镜头再批量生成；重要台词保留独立配音与口型修正。产品面向个人本机 Electron 使用，每部短剧独立目录，模型连接配置仍属于 MovieAgent 全局配置，API Key 不放进短剧资料。

本次建议：以 H3 参考声画生成作为首条视频适配路线，同时支持已确认音轨的配音修正路线；声音在项目实体上管理，镜头表负责对白与验收，现有画布展示固定产物，时间线消费已经采用的版本。继续使用当前视觉体系，不增加另一个应用或重做画布。

“音色一致”指用户听感认可同一人物；“口音一致”指地域发音与用词；“对白准确”指台词完整；“口型同步”指发声和可见嘴部动作匹配。四者分别验收，不把任务成功、音频长度相等、模型名称或 ASR 文本相同当作质量证明。

## 2. 路线选择与范围

| 路线 | 优点 | 代价与结论 |
| --- | --- | --- |
| 每镜头只写声音描述 | 接入简单 | 无固定声音依据，不作为有声对白生产默认 |
| 固定角色参考声音，声画同生 | 表演、声音、环境声可以一起形成；符合用户认可的组织方式 | 每镜头仍需试听；选为默认候选路线，不能承诺整剧零漂移 |
| 确认对白音轨，再做口型修正 | 台词和声音版本明确，可单独修一镜 | 增加处理步骤，侧脸/遮挡/多人存在质量限制；作为可选择的正式路线 |

本次纳入 P4：声音档案、参考裁切与试听、角色绑定、H3 音频参考、三种情绪试镜、批次门槛、逐镜头质量记录、独立配音、可配置口型服务、修正产物采用、原声与配音互斥、最终可追溯导出。

不纳入：训练或下载本机视频/声音权重、应用内声音克隆账户管理、声纹识别认证、自动判定方言正宗、自动无限重抽、多人重叠对白口型修复、自动人声与环境声分离。MiniMax Speech 的已有 voice_id 可以配置使用；创建克隆音色可在服务商完成后配置，不能把它当成 H3 的 voice_id 参数。

技术默认不是用户指定供应商：H3 官方 V2 适配和 MiniMax Speech HTTP 适配作为明确实现目标；口型候选采用 Sync 官方 API，保留用户导入外部修正视频的同一审核入口。使用其他网关仍须验证实际能力，不凭模型 ID 判断兼容。

## 3. 和原 P4 的合并规则

1. 保留基础 P4 的一条视频轨、配音/音乐两条附加音轨、字幕轨、600 秒限制与本机 FFmpeg。FFmpeg 做确定性裁切、混音和封装，不负责生成口型。
2. 原文“不包含智能口型”由本专项取代；“不包含声音克隆”仍指不实现克隆创建/训练，允许使用已有 TTS 音色。
3. 原“视频原声默认静音”改为：无对白制作元数据的旧镜头保持默认静音；已采用原生对白视频使用原声；已采用修正视频使用固定配音轨并静音其嵌入声音；用户在粗剪确认页看到实际声音来源。
4. 旧镜头的 dialogue 字符串继续可读；新增结构化对白不自动从字符串猜角色。用户明确拆句/指派或采用 Agent 提案后才产生新对白版本。
5. 基础迁移 0015–0019 保持分工，本专项追加 0020–0023。0023 只补充审核上下文和整批批准记录，不改写既有迁移。完整 P4 需基础八项及本专项六项都完成，不能只完成旧八项就宣布整批结束。
6. LibTV 的画布剪辑节点可作为后续交互参考；本次仍保留已规划的独立剪辑页，在镜头/画布提供跳转与固定结果卡，不声称复制了 LibTV 后端。

## 4. 用户流程与页面

**角色详情 → 声音页签。** 显示角色图片、声音名称、地域/口音、表演说明、标准参考音频、可选已有 TTS 预设。导入或选择资产→裁切一段清晰单人声音→试听→保存修订。建议样本覆盖完整语句、少混响；系统提示削波/静音/时长事实，不宣称能自动证明“只有一个人”。保存成功显示版本，修改不会覆盖历史。

**镜头详情 → 对白。** 每句包含角色、台词、情绪、镜头内起止时间和制作路线。角色有声音档案时自动选择其当前修订，保存时冻结；缺档案显示“未绑定声音”，不默认借用上一个角色。可临时选择另一档案，但必须仍归当前项目并明确显示角色归属。多人 H3 镜头首版最多三位说话人、顺序发言；重叠区间拒绝，提示拆成反打镜头。旁白独立配音，不要求口型。

**试镜面板。** 推荐平静、激动、低声三段；台词由用户填写或明确采用文本建议。每次点击先展示所用图片/声音/模型/台词/时长/条数和费用上限。生成后可对照播放标准声音与结果，四项逐一选择通过/需修正并写备注。没有自动付费补抽。

**批量制作。** 从镜头表勾选固定镜头（最多16个），显示每个角色的试镜状态、声音版本、对白路线和预估。默认只有已通过试镜的声音配置可进入正式批次；未通过者仍可逐条试镜。允许一次明确的“本批仍要生成”例外，必须填写原因并写入批次快照，不能永久关闭门槛。

**单镜头修正。** 选择失败原因→选择“重做原生对白”或“固定配音＋口型修正”。后者先录音/导入/TTS、试听确认，再选择可用的讲话视频作为源视频；独立提交口型任务。前后视频与固定对白可对照播放，用户采用后才更新镜头选择。修改一句台词只使相关镜头待复核，不重做整集。

**剪辑成片。** 同一镜头仅一个对白来源：原生视频声音或独立配音。后者没有可独立保留的环境声时必须提示“原声已静音，需另加环境声”，不能暗示自动保留背景。BGM 可单独混入；配音与图像分割/移动按关联组共同操作。取消关联是明确动作，界面提示可能失步。

所有新增面板复用现有 token、Dialog、空态、错误态和键盘习惯；保存竞态、项目切换、旧回执、离线行为沿用 P3/P4约束。查询和页面挂载不产生模型调用。

## 5. 数据、版本与目录

所有对象含 libraryId/projectId，版本引用为 `{id,revision}`，媒体沿用 `MediaReference`。模型预设引用仍为现有 `RevisionRef`；本文的声音档案不是模型 ModelProfile。

| 对象 | 固定字段与作用 |
| --- | --- |
| `CharacterVoiceRevision` | id/revision、entityRef（必须是character）、name、dialect、performanceNotes、reference（固定媒体、hash、probeId、sourceInTicks、durationTicks）、可选 ttsProfileRef。角色外观通过固定 entityRef 的媒体列表引用 |
| `ShotDialogueRevision` | id/revision、shotRef、turns：稳定turnId、characterRef、voiceRef、text、emotion、startTicks/durationTicks、mode（native/reference 或 dubbed；见下文），可选已确认对白音频引用（生成take或导入固定媒体）。一个镜头最多16句，每句≤4000字符，总≤16000字符；H3编译另受7000字符限制 |
| `DialogueProductionPlan` | planId/hash/expiresAt、route、固定shot/dialogue/voice/model/media快照、逐项provider输入、试镜或正式用途、试镜证据/例外、有限总费用、owner/runId；10分钟有效 |
| `DialogueTake` | 显式来源联合：供应商生成保存真实 taskRef，外部修正导入保存 manual 来源与本地导入回执，不伪造 TaskRef；共有镜头/对白/档案修订、route、固定视频/音频及hash、计划或导入快照身份、产物状态和质量记录；源产物永不覆盖 |
| `VoiceAudition` | voiceRef＋模型配置指纹＋route＋试镜prompt模板版本的组合，平静/激动/低声三个固定take及人工评价；无权修改声音档案 |
| `DialogueReview` | takeRef、四项分别 `pass|needs-fix|not-applicable`、原因、checkedAt；音色/口音/台词必填，画外音的口型可不适用；机器状态与人工质量分开 |

统一类型值：制作路线 `native-reference|dubbed-lipsync|voiceover`；对白 turn 的 `mode` 使用这三种值，同一镜头首版只选一种路线，不混合原生角色对白和补配角色对白。旁白可独立附加，不用它消除原生对白失败。旁白批次走原 P4 audio.prepareSpeech，不占视频生成步骤。

独立 TTS 旁白以真实 `VoiceLineRevision` 和 `AudioTake` 为来源，不伪造视频或 `DialogueTake`。台词可选 `dialogueSource={dialogueRef,turnId,voiceRef}`，同时保存固定 shotRef/entityRef；服务器验证当前画外音 turn、文字、角色、声音及其固定 ttsProfileRef，准备与批准时重验。普通独立配音文案保持原行为。视频制作入口在任何准备写入前拒绝包含画外音的选择。

旁白每个音频结果都要明确试听并确认音色、口音、台词，口型标为不适用。`audio.voiceoverContext` 提供真实 take、来源及当前上下文摘要；`audio.reviewVoiceover` 绑定所展示摘要和 `pass|needs-fix` 判断，以已提交命令回执及 `audio.voiceoverReviewed` 类型事件保存审核事实，不新增迁移。上下文包含固定输出 hash、任务、台词/对白/角色/声音及模型连接版本；查询与审核不调用模型。新增到时间线的关联旁白（包括同字节资产别名）必须具有当前上下文下最新的通过审核，新的需修正记录会撤销旧通过；历史未变片段继续可读，重新采用已移除的片段需要重验。

参考视频的三情绪和角色组合试镜用于验证画面、人物及声音的共同表现；独立 TTS 旁白使用固定 TTS 声音预设和逐结果音频审核，不复用视频试镜账本，不显示全局声音通过或方言保证。这是两条路线的明确审核规则，不能用旁白通过替代原生对白或口型修正的门槛。

0020存档案/对白修订及引用保护；0021存制作计划、逐项任务/收存回执和take；0022存试镜、质量审核、采用回执与声音选择；0023追加 `dialogue_review_context` 和 `dialogue_batch_approval`，分别固定人工复核所依据的当前声音/镜头/配置，以及一次整批批准的金额、逐项分配和原任务身份。新记录使用严格、受限结构，保持引用和不可变身份；不修改0020–0022。各表只追加修订，CAS保护当前指针；schema14/19/22升级到23均须保留真实旧数据并验收，已交付0011–0014不修改。

固定配音确认复用已提交的 `dialogue.confirmAudio` 命令回执和对应类型事件，必须验证库、项目、对白修订、来源引用、对象哈希及探测身份；仅有预检结果或相似JSON不能成为确认依据。成功的本地对齐作业、固定计划和持久化输出共同证明对齐来源及结果，付费修口型、手工导入和采用均校验这一证据。已消费的整批批准重放返回原批次，不重新分配额度或提交任务；新的人工复核必须明确绑定当前证据上下文，旧的通过标记不能自动刷新。

只读查询 `dialogue.reviewContext({projectId,takeId})` 返回库/项目/take身份、`contextHash`、`stale`、当前 `shotRef`、全部 `voiceRefs`，以及可空的 `profileRef`、`connectionRef`、`modelRef`；不返回凭据。内部摘要同时绑定当前对白及配置指纹。`dialogue.reviewTake` 允许携带 `reviewContextHash`，旧take的声音/镜头/配置上下文过期时必须提供；只要提供就须在提交事务中与当前值严格匹配。页面展示当前复核依据，用户明确作出四维判断后提交所展示的摘要；上下文变化会使未提交的旧判断失效。采用要求最新保存审核上下文仍匹配当前值。此机制不绕过已修改对白的拒绝、不可用输入检查或采用CAS。

活跃档案、未终态计划、已采用take与历史时间线对媒体/配置有引用保护。回收站对象不能新选；历史快照可以读取。新增保护必须进入维护/备份枚举，不能只在页面隐藏删除按钮。改变参考、裁切、口音、TTS预设或模型连接/凭据版本时产生新指纹并要求重新试镜；改角色显示名不使声音证据失效，改角色图片则使画面/口型试镜待复核。旧结果保留原证据，绝不重标成新版本已通过。

短剧资料库仍为事实源。显式导出时可发布到 `audio/voice/characters/<entityId>/<voiceId>-rN/`（reference.wav、voice.json）与 `audio/voice/takes/<shotId>/`；采用现有受限目录导出与无覆盖发布策略，JSON不含凭据、绝对路径或临时签名URL。这里是可读快照，不自动双向同步，不改变项目清单版本。完整迁移仍归P5。

## 6. H3 适配与请求冻结

新增内部适配器 `minimax-h3-v2`，保留现有 `MiniMaxVideoAdapter` / `minimax-video-v2` 及历史任务。现有适配器虽然已经使用V2，但仅构造text/image_url，不能据名称认为已有声音参考。模型设置中提供“MiniMax H3”服务类型，填BaseURL、Key和Model ID（可拉取则拉取）；用户不需要编辑请求JSON。支持能力由适配器声明与实际测试共同确定。

V2提交 `POST /v2/video_generation`；content中声音使用 `type:audio_url, role:reference_audio`，图像使用 `reference_image`。标准H3视频4–15秒整数；首版仅接768P，沿用≤64MiB模型输出限制，2K待独立有界下载验收后启用，不把旧全局限制放大。Prompt≤7000字符。最多9参考图、3段参考音频，所有音频合计≤15秒；每段2–15秒、WAV/MP3、≤15MB。P4本功能不新增参考视频输入，后续可按独立能力扩展。

人物与声音顺序由显式角色映射确定，使用稳定的“图1人物/音频1声音”关系和逐句发言顺序，不能依赖对象遍历顺序。首尾帧模式与参考模式互斥；用户原有首帧意图需明确改为参考图（不保证锁定首帧），确认前阻止提交，不能暗中丢掉音频或首帧约束。

参考裁切/归一化是本地媒体作业，产物成为固定内部输入对象并保留hash，输出48kHz/单声道/PCM s16 WAV。官方OpenAPI明确支持 `audio_url.url=data:audio/wav;base64,...`；采用这个输入方式，无需图床或公开本机端口。产品首版仍最多4张图片，每张≤10MiB，图片与音频原始输入合计≤32MiB；JSON完整编码后≤48,000,000字节，在网络POST前检查，不能只统计源文件。官方9图是服务上限，不是本产品首版承诺。内容hash覆盖原始字节和固定角色顺序，重试不能重新裁切出不同字节。

云端输入只发送批准计划选定的片段，不发送整集声音。renderer只提供媒体引用，Base64编码在特权transport执行；不接受renderer传入file/localhost/任意网络媒体URL。provider返回的下载URL经既有来源策略校验和有界收存。具体协议见技术附录。

能力测试分开记录“协议可用”和“声音质量验收”。若兼容服务未支持音频参考，阻止该路线并保留可用的普通视频能力，不静默降为纯文本。真实连通性测试同样可能生成付费视频，先显示明确片段和额度；fixture只能证明程序协议，不能给用户连接伪造验证徽标。

## 7. 试镜门槛、批次与恢复

参考视频路线默认每个 voiceRef＋modelFingerprint＋route 组合要求三个情绪样例均通过；三个是本产品建议门槛，不是模型保证。两人对话首次采用另检查至少一个该角色组合的轮流发言镜头，避免单人通过就推断不会串音。新的组合先单镜头试制，不扩大自动试镜费用。独立 TTS 旁白按第5节逐结果审核。

批次最多16镜头，每项一个实际付费视频请求；独立TTS与口型是两次不同准备/批准，不能按一个视频费用掩盖整条链。先确认全部对白音频，再批准口型批次；不得把未确定的上游输出放进“已冻结”下游计划。费用未知必须显示未知和有限风险额度。

prepare只做读、验证、预算计算与冻结，不提交云端。approve原子检查所有捕获版本/质量证据/预算并入队，重复同一hash返回原任务列表。修改、停止或切项目后的迟到响应不能切换当前选择。批次停下后不创建后续步骤；远端不能取消时显示事实，保存可核实的原任务结果，不自动采用。

非幂等POST超时保持SUBMISSION_UNKNOWN，不能自动重发；有providerTaskId只查询原任务，收存失败只重试收存。每个take独立收存，不能一条失败堵死其他镜头。恢复不自动补抽、补TTS或补口型。发布后用户显式采用，CAS检查shotRevision、selectionRevision、dialogueRevision；新台词与旧嘴形不能自动搭配。

重开后的批次发现使用只读 `dialogue.productions({projectId,shotId,beforePlanId?,limit?})`：默认每页10项，允许1–20项，按固定计划插入顺序倒序；游标必须属于同项目、同镜头，错误或跨范围游标返回 `INVALID_CURSOR`。响应为 `{libraryId,projectId,shotId,productions,nextBeforePlanId}`，其中每项只含计划身份、状态、用途、预设引用、原executionOwner/runId、expiresAt及最多16项原任务摘要；不复制整批文案/模型配置快照。完整详情继续由既有 `dialogue.production` 按planId读取。列表、翻页和页面挂载均不生成命令或POST；用户显式停止/核对时使用摘要中原任务与所有者身份。

## 8. 固定配音与口型修正

配音允许导入录音，或通过原P4 OpenAI兼容TTS/新增 `minimax-speech-v1` 生成。后者使用 `/v1/t2a_v2` 的 model/text/voice_setting.voice_id，输出本地固定音频；不把voice_id发送给H3。保持相同voice_id和模型可作为一致性手段，但口音和读音仍需试听确认。

口型输入为已选固定源视频＋已确认固定音频；首版一次只修一个可见讲话人物、≤15秒，拒绝重叠多人对白。先在本地形成完全等长的输入：对白过长时阻止并让用户改台词/重配或选更长视频；对白较短时由用户确定入点并明确补静音到视频长度，不能截断单词、自动变速或循环画面。末尾停顿由用户试听确认。

Sync作为首个建议适配器 `sync-lipsync-v2`，ModelCapabilities的taskTypes新增 `lip_sync`（当前代码没有单独的TaskType类型）；model、BaseURL、Key可配置，参数仅受限白名单。使用 `POST /v2/generate` 的multipart本地文件上传，video/audio/model及JSON字符串options，x-api-key鉴权；固定等长输入后显式 `sync_mode:cut_off`，不启用loop/remap。视频≤64MiB，上传WAV≤4MiB，原始总上传≤68MiB，使用流式multipart而非整包IPC。

首次提交前保存Idempotency-Key和固定文件hash；官方或已验证同契约服务允许用户点“核对原提交”时使用原键/原文件恢复，409/503不能换新键重抽。首版最多在首次提交后7天内使用此恢复能力，超期仍查已知任务或人工核对；不依赖无限保留，不在重启时自动POST。运行中服务不支持取消，UI明确“已停止本地后续处理，远端可能继续计费”。具体API以技术附录固定；没有可用服务时允许导入外部修正结果，再走同一审核/采用流程。

输出校验要求视频完整解码、时长与目标误差≤1目标帧、音频版本/源视频hash可追溯；这只验证技术完整性。嘴形自然、人物未变形必须人工审核。最终采用修正视频的画面和批准的独立音频，忽略服务返回的嵌入音轨以避免重采样/替声差异，形成一个固定组合。对口型后修改文字或配音会使组合过期，必须重新确认/处理，不能保留“已同步”标签。

## 9. 镜头选择、时间线与Agent

`DialogueSelection` 保存 shotId、expectedSelectionRevision、takeId、声音策略及来源hash；采用与现有镜头选视频使用同一个内部选择事务，更新同一selectionRevision。旧P3 `ShotProductionOutput` 不伪造新provider来源；新增查询聚合P3历史和DialogueTake，类型显式区分。

采用是硬门槛：所有适用检查必须pass，只有画外音的口型允许not-applicable；任一needs-fix或未评项均不能采用、由粗剪自动选入或作为正式对白导出。首版不提供带缺陷采用例外；“本批仍要生成”只允许产生候选，不绕过采用门槛。用户可继续本地对照预览失败结果，修订审核后再采用。已经采用的历史时间线保留原快照与当时的审核证据，之后改档案不追溯篡改历史。

粗剪时 `DialogueAssembly` 将 adopted take 转为固定 VideoClip 和可选 AudioClip，写入同一 `dialogueGroupId`。原生路线 video原声开启；修正路线 video原声关闭且配音clip开启；画外音为独立音轨。已有时间线不跟随镜头新选择；替换先预览差异并对整个关联组应用同一CAS操作。

关联组移动/裁切/分割/普通删除保持同一时间区间和源偏移；波纹删除仍按原P4全轨切除规则只执行一次，不双重移动。配音轨已有重叠内容、跨片段修正或超上限时整批拒绝并列出冲突，不自动覆盖。无声/纯画面镜头仍按原P4工作。

Agent只能建议对白文字、角色别名、情绪与路线；不能创建声音克隆、替用户勾选质量通过、覆盖声音指纹、决定服务商凭据或批准真实生成。采用提案只写本地修订，标出受影响镜头；不自动重新生成已通过镜头。

## 10. 验收与交付边界

| 项目 | 必须满足 |
| --- | --- |
| 声音档案 | 双角色独立绑定，改档案不改历史；跨项目引用拒绝；回收站与维护保护；裁切2秒/15秒边界 |
| H3请求 | 角色图/音频映射、请求体大小、最多3声音/合计15秒、首帧互斥；未支持时0个生成POST |
| 试镜 | 三种情绪、组合测试、指纹失效；例外有明确范围/原因；没有付费自动补抽 |
| 批次 | 最多16镜头，一次有限批准，重复批准/UNKNOWN/停止/重开不重复提交；失败项可独立处理 |
| 配音修正 | 固定音频，超长拒绝，补静音明确；新配音使旧口型待复核；先审核后采用 |
| 时间线 | 原声/配音不双播；编辑关联组不失步；原生声响与补配环境声限制可见；旧时间线不被追随更新 |
| 真实质量 | 两个角色各三种情绪＋一个轮流对话镜头，四维人工验收；山东话必须由能判断该口音的人确认；不承诺任何模型100%成功 |
| 本机交付 | 原P4完整导出闭环加入原生/修正两条路线；旧模型配置与P3产物可读；只开受控测试窗口，不反复启动用户应用 |

先完成fixture、真实本地媒体与受控桌面测试，再在用户指定连接/模型/有限额度后做真实质量验证。尚未进行的真实服务测试必须在交付报告标“未验”；开发可完成，不能提前宣称整剧音色已经实测稳定。
