# P4 音频、时间线与成片设计

日期：2026-10-27。状态：已完成[可实施性检查](../../verification/p4-design-builder-check.md)，用户已授权实施；逐项实现及验收状态以执行计划和验证记录为准。依据：P3 本机交付源码 `25513e9`、交付记录 `7f10c2c`、总体设计第14节及产品路线图。本文里的“新增”均为计划能力，不代表当前程序已有。

同日追加：[角色声音、对白制作与口型修正专项](2026-10-27-p4-character-voice-design.md)已纳入P4，配套[六项实施计划](../plans/2026-10-27-p4-character-voice.md)。本文是剪辑/媒体基础；角色声音、H3参考、口型、视频声音默认、迁移终点和P4完成条件以专项补充为准。基础八项＋专项六项共同构成当前P4。

## 1. 目标、既有约定和本次建议

在一部短剧的现有目录项目里，把 P3 已选定的镜头产物整理为可编辑时间线，配上导入或生成的声音、中文字幕，最后在本机输出可播放的 MP4。闭环样片为3–5个镜头、30秒、1080p，检查每个剪切点与音画同步。普通用户不需要安装 Node、Python、Docker 或 FFmpeg。

延续已明确的产品方向：个人使用、Electron 界面、本机引擎、全局模型配置、每部短剧独立目录、可手动接管、模型生成必须有明确批准。当前运行的旧应用、用户配置和用户资料库不作为开发测试对象。

以下是本次设计建议，并非声称用户逐项选过：支持可配置 OpenAI 兼容音频接口及 MiniMax 原生音频接口；本地音频导入与手工字幕始终可用；CPU FFmpeg 作为确定的导出路径；一条视频轨、两条音频轨、一条字幕轨；单条时间线最长10分钟。MiniMax 已完成用户授权的单句 TTS/ASR 实测，见[实测记录](../../verification/p4-minimax-audio-smoke.md)；开发仍使用本地模拟服务，不依赖额外真实调用。若用户指定离线模型，需另补模型分发、设备能力和安装方案，不暗中下载权重。

## 3. 路线比较与选择

1. **浏览器内编码合成**：预览复用方便，但大文件、编码能力、内存和平台差异更难控制，不适合作为本机首版唯一导出路径。
2. **交给外部剪辑软件**：专业编辑能力现成，但依赖另装程序、文件交接和外部工程格式，不能完成本应用内的安装即用闭环。
3. **Electron 编辑＋内置原生 FFmpeg**：沿用现有引擎、资产和持久任务，内置稳定编码路径；代价是发行包变大、需要固定媒体运行时及其分发资料。

推荐第三种。界面复用现有 React、组件 token 和任务状态；不引入整套外部视频编辑器，也不将远端媒体网址直接交给 FFmpeg。项目数据库仍是事实源，目录中的导出文件是固定快照。

## 5. 界面与用户路径

新增正式入口「剪辑成片」，替换两个 P4 占位入口；选择项目后才可进入。一个项目可有多条命名时间线，每条时间线归一个剧本，允许多个剪辑版本。

```text
项目 / 剪辑成片 / 第001集      时间线选择 · 撤销/重做 · 保存状态 · 导出
┌ 镜头/素材/音频 ┐┌        画面预览         ┐┌ 片段/字幕属性 ┐
│ 固定版本标签  ││ 播放、逐帧、时码、画幅  ││ 入出点/适配   │
│ 缺素材提示    ││ 编辑预览 / 校验预览标签  ││ 音量/原声     │
└───────────────┘└─────────────────────────┘└───────────────┘
时间尺 / 缩放 / 吸附开关 / 播放头
视频轨     [镜头1][镜头2] [镜头3]
配音轨     [配音1]   [配音2]
音乐轨     [背景音乐................]
字幕轨     [对白1] [对白2]
本机处理与导出状态：排队 / 处理中 / 校验 / 收存 / 完成或错误
```

首次进入提供「从当前镜头生成粗剪」「新建空时间线」。粗剪先显示固定镜头顺序、视频/图片来源、缺失项与实际长度：优先用户已选视频，只有明确允许时采用已选图片；缺失镜头阻止采用并指出对象，不能静默略过。视频比目标镜头短时默认采用实际可用长度并标出差异，不自动循环/补帧；图片采用镜头标注时长。

素材拖拽和属性输入用同一编辑命令；拖动过程中只更新本地草稿，松手提交一条操作。空白视频间隙显示黑场；音频间隙为静音；同轨片段不重叠。普通删除保留间隙；波纹删除明确列出会移动的片段并整体平移所有后续轨道，不隐式改变音画关系。拖错后可以撤销。键盘具备播放/暂停、逐帧、删除、分割和撤销，输入框聚焦时不抢快捷键。

波纹删除精确作用于选中视频片段占据的 `[s,e)`，长度d=e−s，对全部四轨应用同一时间切除：完全在前的不变，完全在后的起点减d，完全在区间内的删除；跨左边界的保留左段，跨右边界的保留右段并把源入点前移到e；横跨两边界的拆为左段和右段，右段放到s，源入点跳过被切除部分。字幕按同样区间裁切/拆分，保留文本，不猜测删掉哪些词；预览列出每条影响，用户可随后改字。新段ID由本次操作身份稳定派生；若拆分后超片段数上限，整条操作拒绝。例：删除10–15秒，0–30秒BGM成为0–10秒和10–25秒两段，后段从源15秒播放；9–11秒字幕只留下9–10秒。

时间线持续显示「未保存 / 保存中 / 已保存 / 冲突」。沿用 P3 的异步回执防护：新输入不被旧响应覆盖、切换时间线后旧回执不导航、离线停用新提交并保留当前草稿。切换项目/关闭有未保存内容时提供保存或明确放弃；崩溃恢复保存到数据库的修订，不声称恢复未提交内存草稿。正常查询刷新和媒体完成事件不能改当前剪辑。

音频模型设置继续在受保护的模型窗口中完成。选择「配音」或「语音识别」，填 Base URL、API Key、模型ID（或拉取后选取）；只有该类型实际测试通过后才可保存启用。voice、语言、返回时间戳格式是业务参数，不要求用户理解内部 adapter 名称。拉取列表失败时允许手填；列表里有某个ID不代表支持音频。测试可能计费，按钮先展示一次测试的输入范围和额度，不在打开设置时调用。

## 6. 时间模型、轨道与编辑约束

统一 `timebase=48000` ticks/秒，音频混音48kHz；全部区间为 `[start,end)`。帧率属于每条时间线，首版只允许 `{num:24|25|30,den:1}`，默认30；一帧对应2000/1920/1600 ticks。数据保留有理数形状以便后续扩展，但首版拒绝未验收的分数帧率。时间线完全为空时可通过setSettings改帧率；已有任一视频/音频/字幕则锁定fps，改变需要新建另一条时间线，不隐式重吸附现有边界。时长、入出点用安全整数，视频/图片边界按帧吸附，音频可按采样点定位，字幕按帧定位；UI秒数只是显示格式。

画幅可选1920×1080、1080×1920、1080×1080，SDR BT.709、方形像素。含HDR/PQ/HLG的输入首次使用时明确拒绝并提示需要预转换，不静默套一个色调映射。非零PTS、编辑列表、旋转和SAR由探测/归一化处理；VFR按实际PTS生成目标CFR代理/中间件，不用平均fps猜第几帧。音视频归一化共享起始基准并保持原始相对偏移；缺失音轨生成明确的静音，不从别的片段延续声音。

`TimelineRevision` 包含 `libraryId,projectId,id,revision,scriptRef,title,fps,timebase,canvas,videoClips,audioClips,subtitleCues,subtitleStyle,createdAt`。`scriptRef={id,revision}` 只标明创建依据，之后剪辑不改剧本。

- `VideoClip`：稳定id、`kind:'video'|'image'`、固定 `MediaReference`、`sourceHash`、`sourceProbeId`、`sourceInTicks`、`startTicks`、`durationTicks`、`fit:'contain'|'cover'`、原声 `gainMilli`/mute；可带 `ShotProvenance`，记录 shotId/shotRevision/selectionRevision/productionId或未知来源，不猜造来源。
- `AudioClip`：稳定id、`kind:'audio'`、固定媒体/探测身份、`track:'voice'|'music'`、入点/起点/长度、gainMilli/mute、可选固定配音文案/转写来源。显式剪辑，不自动循环BGM。

静态图片沿用导入时完整解码校验的 MIME、hash 和尺寸，`kind=image`、`sourceProbeId=null`、`sourceInTicks=0`，展示时长由镜头或用户指定；不伪造音视频探测时长。视频必须有真实 `probeId` 与 `video/mp4` 类型，音频亦必须有真实 `probeId`。媒体身份与引用不符时整批拒绝。
- `SubtitleCue`：稳定id、起止ticks、纯文本、可选 transcriptId/revision/segmentId。样式为已打包fontId/字号/颜色/底边距/描边的受限字段，不接受ASS标签、HTML、任意字体路径。
- `TimelineOp`：`insert|move|trim|split|delete|rippleDelete|setGain|setFit|replaceMedia|setCue|setSettings` 的精确判别联合；`replaceMedia` 必须重验入出点并明确预览，不让新视频偷偷换入。

上限：每时间线600秒、64视频片段、每音频轨128片段、1000字幕条、每条200字符、一次最多100操作/1MiB JSON；gainMilli取0–2000（1000=原始音量），最终混音明确启用固定limiter防削波。超界整批拒绝，不能只应用前一半。

时间线终点等于所有片段/字幕末端的最大值，再向上对齐一个目标帧边界；不另存可漂移的总时长。视频30秒、音乐60秒时输出60秒，后30秒黑场，界面及导出预检明确提示。普通删除只留下中间间隙，删除最后内容后总长按剩余内容缩短。空时间线可保存但不能渲染；MP4至少含一个视频/图片片段，只有音频时仅允许WAV；WAV要求至少一个启用的音频来源。MP4可以无声，但固定输出AAC静音轨。字幕/音频延长的尾部同样受600秒上限约束。

两条音频轨指配音和音乐这两条附加轨。无对白元数据的旧视频原声默认静音；专项已采用的原生对白使用视频原声，补配修正版使用独立音频并静音视频，两者互斥。粗剪确认页显示具体来源，视频轨显示原声标记和音量，不作为隐藏混音来源。所有启用声音共同混音，`amix normalize=0`，最终limiter上限0.95且不自动补偿增益，防止某一轨结束后其他轨突然变响。

保存采用 `expectedRevision` CAS，所有操作先验证最终状态再在命令事务中落一个新修订/回执/事件。历史不可变。撤销/重做是针对已捕获内容的新修订，仍检查当前CAS，不删除历史；初版提供最近50个当前会话操作的撤销/重做，重开可从持久历史显式“恢复此修订”。

编辑器保留语义操作及其固定持久修订依据，不能把一次合法波纹删除展开为上千条操作后拒绝。`timeline.restore` 可携带可选 `operations`：从同一时间线的确切 `sourceRevision` 读取历史内容，再执行最多100个严格TimelineOp，合计仍受1MiB限制；以当前expectedRevision做CAS，全部检查成功后原子产生一个新修订和回执。保留的历史来源沿用历史读取权限，新插入/替换的来源仍走新选择检查；不接收任意完整快照或provenance设置器。当前时间线非空时，最终候选修订必须保持当前fps。保存与历史恢复的迟到回执都不能覆盖后续输入。

## 7. 固定素材、媒体服务和原件保护

导入音频首版支持 WAV PCM s16/s24、MP3、M4A AAC-LC，最长600秒、每文件128MiB；不支持多音轨音频、DRM、网络播放列表或不明时长。普通图像/视频输入保留已支持格式与旧64MiB视频限制。音频字段width/height为0，新增独立媒体类型校验；旧P1–P3快照继续可读。

新增 `MediaProbe` 按 objectHash＋运行时版本保存：容器、流索引、编解码、durationTicks、timebase/PTS范围、sampleRate/channels、rotation/SAR/color、音轨存在性和验证状态。只公开有界元数据；不把输入绝对路径和完整ffprobe错误输出送到renderer。旧对象第一次进入时间线时显式排入本地探测，完成前显示“媒体分析中”，不在迁移中扫用户全部原件。

大媒体读写采用有界流和背压：先在特权层解析固定引用并验证hash，再通过只读句柄分块暂存/读取；内部每块最多1MiB、每会话最多2块并行，不允许renderer提交文件路径。主进程媒体协议实现标准Range/206/416并能续期；播放越过当前120秒授权期仍能续播。对象被修改、库切换、授权过期且续期失败时终止读取并提示，不退回任意路径。

派生媒体（波形、缩略图、预览代理、CFR中间件）的key包含原件hash、变换参数、运行时/字体版本；原件不覆盖。缓存只在库所属 `.movieagent/library/cache/media`，默认上限5GiB，已被活动计划占用的缓存不回收。活跃作业有独立lease；清理失败可报告，不能删除原件来腾空间。维护快照收录持久原件/输出与引用，缓存可重建。

派生处理由 `media.prepareDerived/enqueueDerived` 显式准备和入队，使用同一本地媒体队列，返回LocalJobRef；用户新增镜头后可点击「准备编辑预览」，先看到占用估算。它不是模型任务。缓存状态通过 `media.derived` 查询，页面挂载只读取，不偷偷重做整条时间线。`DerivedMediaRef={libraryId,cacheId,sourceHash,recipeHash}` 只能经受限媒体URL能力读取，不能作为可导出的原件引用；缓存缺失时用户明确重建。波形使用有界峰值桶，最多每秒60桶，不把全音频PCM传到renderer。

界面通过明确点击的 `media.inspect({projectId,reference})` 取得固定素材的 `ResolvedMedia`（hash、MIME、大小、尺寸和真实探测）；视频/音频首次使用调用本地探测，静态图片的probe为null。该能力不提供路径、原件字节、任意命令或生成批准。`media.derived` 另返回每个派生产物的kind/MIME，区分可播放代理、缩略图与波形，不能按缓存顺序猜类型。缺失的缓存需明确重新准备。

视频代理采用明确的画面适配变体：`media.prepareDerived` 和固定DerivedMediaPlan允许可选 `videoFit:contain|cover`，旧计划省略时为contain，新显式选择参与recipeHash。派生查询从固定计划返回fps、canvas和有效videoFit；预览仅采用与片段来源、当前fps、canvas及fit均匹配的代理。混合适配的时间线可分别明确准备两种变体，界面显示具体选择，不把已烘焙黑边的contain代理冒充cover，也不在客户端猜测recipeHash。四字段DerivedMediaRef保持不变。波形只读取授权的有界峰值JSON，按sourceInTicks和时间线位置显示，缺失或损坏时给出可操作状态，不自动重新入队。

SRT导入通过主进程 `selectSubtitleFile()` 的单文件OS选择框，返回文件名和严格UTF-8文本，最多4MiB；渲染进程不能传入或取得路径。导入后仍需校验条数、文字、帧对齐、时间范围和重叠，再由用户采用。

## 8. TTS、ASR与模型配置

新增内部 adapter `openai-speech-v1`、`openai-transcription-v1`、`minimax-speech-v1`、`minimax-transcription-v1`，任务类型 `text_to_speech`、`speech_to_text`，输出分别为audio与受限转写JSON。继续使用既有 connection/model/profile修订、credential vault、受限transport、PreparedGeneration批准、reservation、TaskRef及SUBMISSION_UNKNOWN规则。MiniMax 原生 TTS 提前至基础任务3实现，角色声音专项任务V4复用；请求在受限 transport 中执行。

默认以可配置模型ID与能力测试为准，不硬编码某家当前模型。TTS参数首版只包含voice、response_format(wav/mp3)、speedMilli(500–2000，默认1000，接口发送时除1000)；速度字段仅在能力声明且测试支持时发送，默认速度可省略。ASR默认只发送文件和model，接受最小JSON文本响应；可选语言参数按被测试的能力映射为language或languages，省略是安全默认，不混发。segment-json/verbose_json等输出模式只有在该模型实测支持时发送；不默认有逐词时间戳或说话人分离。不加入声音克隆、实时双工或供应商任意JSON。一个连接可分别保存TTS/ASR预设，其测试证据绑定实际配置指纹，修改baseURL/key/model/voice/能力参数后失效。

单次TTS输入最多4000字符；一次批量最多16条、总计16000字符，逐条TaskRef且批准前列出全文、模型、voice、数量和风险额度。ASR首版只处理用户明确选取的≤24,000,000字节、≤600秒音频（按十进制字节，非24MiB）；MiniMax 原生 ASR 供应商上限为500秒，取更严格限制。必要的单声道16kHz WAV预处理在本机完成，编码后的字节数仍需预检。超过上限拒绝并建议用户拆分，首版不自动分段发出多次付费请求。TTS音频超过镜头长度时显示差值，由用户剪切或调整时间线，不能偷偷变速或截断台词。

为音频扩展价格类型：unknown，或带版本/币种的每千字符/每音频秒单价；精确计费单位冻结在Profile快照。MiniMax 原生配音按[官方计量规则](https://platform.minimax.cn/docs/pricing/overview)区分汉字（2单位）与字母、标点、空白等（1单位），保留供应商返回的实际用量字段；不由此推断订阅套餐扣减。未配置单价时展示“价格未知”，复用有限风险额度确认，不显示0元。接口实际账单未知时不得以本地估算作实际扣款。非幂等音频POST超时视为提交未知，不自动重发；用户明确另发新任务才可能再次计费。

`VoiceLineRevision` 保存文字、可选shot/entity固定引用；voice/profile由用户选择。`AudioTake` 关联原TaskRef、输入文案修订和固定audio输出。`TranscriptRevision` 关联原audio/hash/TaskRef，保存原文、可选segments及 `timing:'none'|'segments'`。没有可靠起止时间的返回只产生可编辑文本；通过人工校时后才能导入字幕轨。保留原返回制品供诊断，schema不合法的内容不写成成功字幕。收存/转写发布可恢复且幂等，不触发第二个POST。

## 9. 原生运行时与进程边界

在 `resources/media-runtime/win32-x64/` 携带固定ffmpeg.exe、ffprobe.exe、CJK字体、LICENSE/NOTICE及来源清单，通过electron-builder `extraResources` 打包，不放在asar里。运行时路径由main根据 `process.resourcesPath` 解析并传给engine，开发时指向仓库的专用受控资源目录；不搜索系统PATH、不接受模型/renderer提供的可执行路径、运行时不下载工具。

实施第一项固定发行物的版本、来源URL、完整SHA256、构建配置、编解码/filter清单、字体许可与版本，形成 `runtime-manifest.json`。候选为Gyan FFmpeg9.0.2 essentials x64静态构建、Noto Sans CJK SC Regular Sans2.004静态OTF；发布者摘要及版本依据见[技术核对](../../research/2026-10-27-p4-media-runtime.md)。本次没有下载验算，实施时须验证，失败不自动换成latest。推荐CPU `libx264`＋AAC＋libass路径；GPU只是后续优化，不作为首版依赖。包含GPL组件的二进制必须配套对应许可证、源码/构建材料取得方式和分发记录；不能因为用子进程就宣称应用自动免除所有许可义务。公开分发前单独核查，个人本机beta也不抹去这些资料。

特权MediaWorker以参数数组spawn，`shell:false,windowsHide:true`，只接收引擎生成的本地暂存路径和编译后的受限操作。每个输入显式协议白名单file/pipe，并限制demuxer/stream数量；禁止网络/播放列表，字幕文字写入正确转义的受控文件；绝不接收任意滤镜串。白名单不是文件系统或解码漏洞沙箱，不能据此承诺隔离恶意本地媒体的一切风险。stdout使用 `-progress pipe:1` 的有限键值进度、`-nostdin`，stderr环形缓冲最多256KiB，日志不含凭据/用户绝对源路径。一个库只并行一个重型媒体作业，最多4编码线程；探测超时30秒，渲染超时30分钟，取消先请求进程结束、5秒后仅终止本作业所持有的子进程，禁止按名称全局杀进程。

字幕渲染需锁定实际font family和字体hash，并核验字符覆盖及实际选中字体。`fontsdir`只是补充目录，不能靠它保证没有回退到系统字体；缺字阻止导出并指出字符。cue端点先得到整数帧索引f，ASS厘秒端点统一为 `floor(100*f/fps)`；对首版24/25/30fps，该值位于前一帧之后、目标帧时刻之前或相等，使左闭右开的激活帧集合保持一致。测试逐帧确认起止，不以容器总时长替代字幕边界验收。

## 10. RenderPlan、本地队列与恢复

`render.prepare` 读取某一 `TimelineRef={libraryId,projectId,id,revision}`，冻结全部媒体hash/probe、字体hash、编码参数、runtimeVersion和输出规格；返回 `RenderPlan{planId,planHash,compositionHash,expiresAt,timelineRef,purpose,manifest,estimatedBytes,requiredFreeBytes,notices}`。用途为 `preview|mp4|wav`，每计划只生成一种结果，准备有效期10分钟。compositionHash标识共同的固定合成快照，planHash额外覆盖用途/输出规格。导出前检查所有素材、中文字符覆盖、输入能力及磁盘空间。空间估算包含暂存/归一化/结果，采用保守上界＋至少1GiB余量，显示给用户，运行时继续检查和限额；估算不能保证磁盘一定够。

`render.enqueue` 只接受对应hash、执行owner和runId以及磁盘预算确认，生成独立 `LocalJobRef`；不复用模型TaskRef，也不占模型费用预算。重复同一批准返回同一job；重试明确引用旧job并生成新attempt，从头渲染同一计划，不重生镜头、配音或转写。计划排队后时间线继续编辑不会改变它。

状态：PREPARED→QUEUED→RUNNING→VERIFYING→PUBLISHING→SUCCEEDED，另有FAILED/CANCELLED/INTERRUPTED。`cancelRequested`先持久化，检查每个await之后，验证/发布前再次检查；迟到结果不能以成功覆盖取消。进度来自ffmpeg实际时间戳，校验/收存单列阶段，不伪造匀速百分比。

重启只恢复原job和已有暂存/结果：未完成的RUNNING变INTERRUPTED；可验证的完整输出继续本地校验/收存，其余由用户点击重试。QUEUED在重启后显示“待继续”，须显式继续，不能恢复库就自动执行。pause/drain要协调模型scheduler、Agent/shot协调器和媒体队列；备份不抓取正在写的输出。正常退出终止本应用子进程并持久化中断状态；恢复时不根据可重用PID杀其他程序。

输出先在库内作业专属目录写临时文件，再检查完整解码、视频/音轨、尺寸、帧率、总时长、字体/字幕与音画样片，然后计算hash并原子收存。MP4上限1GiB、WAV上限128MiB、预览上限256MiB；媒体资料库接收大渲染产物走独立可信本地产物通道，旧网络模型上限不变。发布使用journal，崩溃后只有一份输出身份，不显示半个成功文件。

视频导出的 `burnSubtitles` 选择冻结在RenderPlan并影响planHash；默认烧录，旧计划省略该字段时保留原来的烧录语义。关闭烧录仅跳过画面字幕及相应缺字/字体选择检查，不删除时间线字幕，也不改变单独导出的SRT。WAV没有视频烧录选项。重试使用原计划中的选择，不读取当前界面复选框；共同固定时间线的compositionHash仍可供不同输出用途关联。

## 11. 导出文件与短剧目录

沿用已有目录，不把项目清单版本升高来表示几个新增文件夹。按需在明确导出时创建目录：

```text
短剧目录/
  audio/voice/ music/ sfx/       # 用户自己整理的源文件区，应用不自动覆写
  exports/creation/              # P3资料快照
  exports/video/<timeline>-rN-<exportId>.mp4
  exports/audio/<timeline>-rN-<exportId>.wav
  exports/subtitles/<timeline>-rN-<exportId>.srt
  exports/storyboards/<timeline>-rN-<exportId>.csv
  exports/packages/<timeline>-rN-<exportId>.zip
  .movieagent/library/           # 原件、数据库、派生缓存、本地作业
```

渲染成功表示库内制品已完整收存；复制到短剧目录是独立可重试的导出发布，目录断开时显示“成片已保存，复制未完成”，重试只复制。用主进程窄 `exportTimeline({projectId,timelineId,revision,kind,renderJobId?})` 能力，renderer不得传路径/文件内容。逐级验证目录真实归属和无链接，独占临时文件后无覆盖发布；有同名/符号链接/junction时拒绝。

MP4与WAV可从同一固定合成快照派生，但分别准备/批准/执行自己的RenderPlan和job：compositionHash相同，planHash与输出身份不同，取消和失败互不连带，导出MP4不会暗中再生成WAV。SRT从同一时间线修订输出UTF-8，字幕毫秒转换使用统一四舍五入、端点保持有序，不逐段累加。CSV按时间线顺序含shot修订/素材hash/入出点/时长/对白；对表格公式前缀做转义。ZIP只含本次使用的固定原件（去重，生成安全文件名）和JSON清单，最多2GiB；无Key、原始绝对路径或运行任务，不导出任意文件。大文件复制/打包必须流式且可取消。

CSV 将「分镜对白（固定修订）」与「时间线字幕」分列：前者按片段 provenance 的 shotId/shotRevision 读取精确历史对白，在准备导出时一并冻结；后者来自同一时间线修订中与片段重叠的字幕。没有字幕不代表没有分镜对白；缺少来源或历史修订时留空并保留未知来源，不回退当前镜头，也不把 productionShotRevision 偷换成所选分镜修订。角色声音专项后续另加实际采用的 DialogueRef、voice/take 与审核来源。

## 12. P4 成片助手

保留P3 schemaVersion1解析；新增独立版本的 `FinishProposal` 和三个模板：配音文案、字幕修订、镜头粗剪。复用原单次文本规划/有限上下文/审阅/停止，不做无限工具循环。捕获所选时间线修订、镜头与产物、字幕/文案修订，模型只能使用引擎给出的别名。

提案可含最多16条文案、100条字幕修改或32个粗剪片段；一次选择一种模板目标，避免跨对象大事务。文案只建议文字和角色/镜头别名；字幕只编辑已选条目文字，时间移动必须有明确受限op；粗剪只从所选固定媒体中安排顺序/合法入出点。模型不能决定BaseURL、voice/model配置、付费任务、文件路径或FFmpeg参数。

`finish.prepareTurn/approveTurn` 复用P3文本规划机制；`finish.acceptProposal` 检查hash、owner、版本、10分钟有效期，采用一个明确子集并保存回执。时间线草稿与文字保存只改本地数据；采用文案不自动TTS，采用字幕不自动ASR，采用粗剪不自动渲染。界面展示实际修改前后与略过项；人工修改后冲突不能覆盖。重开只收取已有文本结果。

## 13. 验收矩阵与交付条件

| 层级 | 必须证明 |
| --- | --- |
| 数据 | 14→19升级保留既有数据/备份；每步迁移可独立重开；事务、CAS、重复回执、历史引用固定 |
| 时间 | 24/25/30fps剪切边界；30秒和600秒无累积漂移；重排/分割/波纹删除保持跨轨关系 |
| 媒体 | 无音轨、非零起点、旋转、VFR、44.1k音频、截断/伪扩展名、HDR拒绝、损坏PTS有明确错误 |

| 渲染 | 3–5镜头/30秒样片完整解码，时长误差≤1帧；每个cut边界、中文字符、字幕定位，音画偏移≤1帧；600秒测试无累计漂移 |
| 恢复 | 磁盘不足、导出目录失联、取消、kill worker/重启、收存窗口崩溃，无半成品成功、无重复媒体POST |
| 桌面 | 真实控件完成镜头→粗剪→音频→字幕→预览→MP4→播放→重开；异步保存后继续输入和切对象不会丢草稿 |
| 包 | release-p4中CLI/字体/manifest hash/许可证齐全；无系统ffmpeg依赖；旧P2/P3包和用户实例不被测试替换 |

性能基准先记录同机数据，不承诺未知硬件的固定渲染倍速：样片导出时UI可操作，时间线64片段/1000字幕滚动与拖动不逐帧写数据库；大文件IO单块≤1MiB并有内存增长观测，不把1GiB成片一次读进renderer。CPU进度与磁盘写入真实可诊断。

开发使用临时库、显式fixture配置和本地HTTP。真实TTS/ASR接入由用户后续指定模型/连接及有限额度另行验收；现有Kimi连通成功不能代替P4语音或成片提案验收。每任务只运行受影响检查，最后集成后运行一次核心全套、必要的打包UI流程；后续修复只补相关证据和新包身份，避免反复开启用户桌面。

## 14. 风险、阶段划分与来源

优先验证媒体运行时、中文字体、固定时间模型和大文件路径，再写复杂UI；这几项失败会改变可交付范围。音频供应商格式不一致由能力测试和明确受限adapter处理，不宣称“任何OpenAI兼容都能用”。可独立先验收导入声音＋手动字幕的成片链，但P4整体完成还包括音频模型接入与成片助手，不能把阶段验收当作全部完成。

基础实施拆为8项：媒体基础；时间线数据；语音模型；本地渲染；导出发布；完整剪辑界面；成片助手；打包交付。角色对白专项追加6项。顺序为基础1–7→专项V1–V6→基础8统一发行，迁移最终14→22；基础表格14→19只是基础阶段断言。逐项接口与测试见两份同日实施计划。技术默认可在文档中修订，当前请求只授权写方案，不运行实现或真实生成。

官方资料的具体版本、音频协议变化与发行物建议见[技术核对](../../research/2026-10-27-p4-media-runtime.md)。对源码、兼容服务与实际发行能力分别标注，不能用一份在线API文档证明所有代理服务支持。
