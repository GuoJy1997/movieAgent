# P4 角色声音与对白验收

本清单区分工程 fixture、真实供应商质量和发行安装。任何任务成功、HTTP 成功或协议解析成功，都不能替代人工音色、口音、台词和口型判断。

## 工程验收入口

- 角色场景 → 编辑角色 → 声音档案：选择固定音频，试听裁切范围，保存本地档案；“准备标准声音参考”执行本地派生作业，完成后明确“将标准参考保存为新修订”。目标为48kHz、单声道、PCM s16 WAV，记录固定版本、hash和probe。
- 剧本分镜 → 编辑镜头 → 对白制作：逐句选择角色声音的确切修订、情绪、路线、起点和时长。保存不会调用模型；保存A后编辑B，A的迟到回执只推进保存基准，B保留。查询刷新、另一个声音新增和项目切换不得覆盖草稿。
- 试镜与审核：平静、激动、低声及新角色组合轮流对白；正式制作从已保存对白选择最多16镜头。能力不支持或所选配置已失效时停用，不自动换预设。例外原因只进入当前正式批次。
- 批次确认：显示每个镜头/对白/角色/声音/模型/预设的固定修订、全文、媒体引用及hash、条数、估价、总风险额度和项目上限。未知费用/云端不能取消风险需明确勾选。过期计划或配置变化需要重新准备。
- 配音与口型：录音走`imported-audio`，已有真实TTS结果走`audio-take`及原takeId，禁止伪造生成任务。确认后本地补静音；实际选择的Sync预设和对齐时冻结的视频进入修正计划。手工导入必须使用身份匹配且成功的对齐作业音频版本和捕获的源视频，不能传原始录音；改变来源、台词或入点后旧输出失效。可播放原视频与修正结果。
- 逐镜头审核：通过`dialogue.reviewContext`展示原take与当前镜头、所有声音和配置修订。音色、口音、台词、口型需明确判断，并提交所展示的依据hash；依据变化或读取失败使旧选择和迟到审核回执失效。只有明确保存当前审核后才能采用。采用使用当前镜头选择修订进行CAS；冲突不覆盖当前选择。旧对白结果保留历史。
- 原批次历史与恢复：按项目/镜头分页读取原批次，打开详情不执行任务。停止和核对使用保存的原owner/task身份；未知提交禁止重发，已验证的Sync原提交核对仍受7天窗口约束。
- 画布产物卡：声音来源对应确切当前媒体；“打开对白/剪辑”只跳转到该镜头。粗剪复用`timeline.prepareAssembly`/`timeline.applyAssembly`；原生声音和独立配音互斥，相关编辑保留声音快照。
