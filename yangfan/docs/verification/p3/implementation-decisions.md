# P3 实现约定与边界

以下按实施过程中作出决定的顺序记录。它们不代表尚未完成的真实服务验收。

| 决定 | 原因 | 使用上的代价或限制 |
| --- | --- | --- |
| 保留 D:/movieAgent/libtv-studio 和现有开发分支 | 沿用用户指定目录，继续本机项目 | 没有另建可随意丢弃的隔离副本；未合并或推送远端 |
| 已批准范围内持续实施，不重复请求设计或执行许可 | 用户已明确要求完成 P3 | 普通实现选择由此记录说明，可在后续调整 |
| Agent 每轮复用一次 P2 文本生成，以严格 JSON 提案表达受控操作 | 兼容已有 OpenAI/Anthropic 接入、预算与恢复逻辑 | 不是原生 tool_calls、流式输出或无限自主循环；模型必须遵守提案格式 |
| 开发只使用本地模拟接口 | 避免未经本轮批准的真实计费 | Kimi 长篇结构化提案和真实媒体全链路仍需后续有限验收 |
| 保留正在运行的旧桌面、全局配置和用户项目 | 不打断现有工作 | 新版本放在 release-p3；退出旧程序后再使用新入口升级资料库 |
| JSON/Markdown 导出是固定版本快照，SQLite 继续作为编辑事实源 | 避免两份数据自动互相覆盖 | 导出文件不自动同步或重新导入，也不是 MP4 成片 |
| 规划输出预算可显式覆盖，形成项目内不可变预设 | 普通短文本预算可能截断分镜 JSON | 批准前需要确认 token 上限；不自动扩容、重试或改全局配置 |
| 每轮提案只采用一个明确子集，并保存稳定回执 | 防止重复批准产生重复内容，避免变更选择复用旧批准 | 未采用的想法需要新轮次；界面显示已采用和跳过项目 |
| 无提案的普通回复也使用版本化 JSON 外壳 | 保持完整文档解析和明确协议 | 模型返回裸散文会显示格式错误，不猜测或从正文中截取 JSON |
| 导出文件名包含主进程生成的快照标识及对象修订 | 镜头可能变化而剧本修订不变 | 多次导出生成独立文件，不覆盖旧快照 |
| 收存诊断使用新增 schema14 迁移 | 让先前 schema13 形状也能获得诊断表 | 增加一次增量迁移；沿用升级备份，未在开发中打开用户资料库 |
| 保留未修改的 ShotProductionPanel 长 JSX，作为非阻断维护项 | 最终修复已格式化涉及的表单，未发现该长行造成运行故障 | 后续修改制作面板时仍需整理，当前代码阅读成本较高 |

内容、预算批准、媒体生成分别记录。采用提案不会批准媒体费用。历史镜头本身不推断保存时的完整父剧本正文；生成批次冻结实际使用的父剧本、场景与实体版本。
